# 02-信息补全机制设计规格-Copilot-2026-03-14

> Copilot 说明（2026-03-14）：
> 本文回答一个问题：
> **信息补全在需求分析五步流程中，什么时候触发、补什么、不补什么、怎么多轮而不失控。**
>
> 综合主架构（5 大节点 + 5 步二级步骤）与四份外部参考意见（A/B/C/D），经交叉验证、冲突排查后，给出统一执行规格。

---

## 一、核心结论

### 1.1 信息补全的本质

信息补全不是填表（Form Filling），不是问卷采集，而是：

**在需求分析推进过程中，围绕"当前判断能否继续冻结"做按需、递进、最小化的语义对齐。**

一句话门槛：

> **不是"字段是否为空"，而是"这个缺口是否影响当前步骤的退出条件"。**

### 1.2 定位

信息补全是嵌入 S1–S4 的阶段性机制，不是独立步骤。

- S1 负责识别缺口、轻量分诊
- S2 负责目标级 / 战略级关键补全（主战场）
- S3 原则不补，发现缺口则回退 S2
- S4 按专题补全战术级信息
- S5 编译补录，G3 自动兜底

### 1.3 与现有武器的关系

| 武器 | 原定位 | 本文扩展 |
|---|---|---|
| A2 信息充足度评估器 | S1 后台·必执行，输出充足/边际/不足 + gap_list | 增加 `gap_level` 字段：框架级 / 战略级 / 战术级 |
| E1 关键缺口补全器 | S2 内部按需，≤2 轮 | 扩展为三个激活上下文，每上下文独立预算 |
| G3 空字段自动兜底 | 全阶段质量门控 | 明确每个步骤退出时即时兜底，不等到 S5 |

## 二、参考意见交叉验证

### 2.1 四份意见的共识

以下判断四份参考全部同意，且与主架构一致：

1. **信息补全是递进过程**，不能一次问完
2. **应由信号触发**，不是机械扫描所有空字段
3. **嵌入现有流程**，不另设独立步骤
4. **用户跳过时用推断兜底**，标注 `[推断]`
5. **每轮追问数量严格限制**（1–3 题）
6. **S3/S4 阶段后不再做方向性补全**

### 2.2 冲突与裁决

| 冲突点 | 各方立场 | 裁决 | 理由 |
|---|---|---|---|
| **步骤编号** | B/D 使用旧四步（S1–S4）；C 使用新五步 | 统一为新五步（S1 拆→S2 目标锁定→S3 战略框架→S4 战术分解→S5 形成成果） | 旧四步已被新五步取代，文档必须对齐 |
| **主补全区在哪** | B/D 认为旧 S2"看清重点"是主战场；C 认为三个激活点平权 | 新 S2"目标锁定"仍是主战场，但 S4 按专题独立补全是第二战场 | S2 承担目标/动机的深层追问，信息自然在此获取最多；S4 按专题展开时会暴露新的战术级缺口 |
| **S3 能否补全** | B 说原则不补；C 说 S3 无独立激活点；D 说只允许"最后一跳" | **S3 不主动补全**。若激发盲区时发现战略级缺口，评估后回退 S2，不在 S3 内硬补 | S3 的职责是冻结战略，不是继续收集信息。在此补全会模糊 S2/S3 的职责边界 |
| **E1 是否拆分** | C 提议拆成 E1-框架/E1-战略/E1-战术 三个武器；B/D 保持统一 | **保持 E1 为单一武器**，定义三个激活上下文（@S1 / @S2 / @S4） | 拆成三个武器会膨胀武器库。一个武器 + 上下文参数更简洁 |
| **轮次上限** | B 说 3 轮总计；C 说 3–5 轮分散；D 说每冻结周期 ≤2 轮 | 采纳 D 的核心原则：**每步独立预算，单步 ≤2 轮**。超过说明不是缺字段，而是命题未压清，应回退 | 全局固定轮次无法适应不同项目复杂度；按步骤独立计量更灵活也更可控 |
| **G3 触发时机** | 现有定义：G2 发现空字段时触发；C 提议每个激活点结束后立即兜底 | 采纳 C：**每步退出时 G3 即时兜底该步骤产生的跳过项** | 等到 S5 统一兜底太晚，中间步骤已经在消费这些字段 |
| **追问方式** | A 强调"提议并确认"而非"问答填空"；B 强调"主题簇追问"；C/D 无特别要求 | **两者都采纳**：优先"提议+确认"，组织为"主题簇" | A 的洞察对 UX 至关重要——好的补全不是让用户填空，而是提出合理推断让用户确认或修正 |

### 2.3 被否决的建议

| 建议 | 来源 | 否决理由 |
|---|---|---|
| 在 S2→S3 过渡设置独立激活点做集中补全 | C | 与主架构矛盾。S2 的退出条件本身就包含"不再存在影响冻结的关键缺口"，不需要额外的过渡激活点 |
| E1 拆分为三个独立武器 | C | 武器库膨胀。用激活上下文参数解决 |
| L1/L2/L3 层次模型（物理骨架/意向对齐/决策深化） | A | 概念有价值但不直接映射到五步流程。其核心思想已被"框架级/战略级/战术级"三层分类吸收 |
| 为每个激活点设计不同的 `[推断-层级]` 标注 | C | 过度工程。统一 `[推断]` 标注，推断依据写在备注中即可 |

## 三、缺口三级分类

这是整个机制的判断基础。

| 级别 | 名称 | 定义 | 不补的后果 | 处理时机 | 处理原则 |
|---|---|---|---|---|---|
| **L1** | 框架级缺口 | 不补则不知道分析什么 | 无法路由、无法进入分析框架 | S1 退出前 | 优先补，不超过 3 题 |
| **L2** | 战略级缺口 | 不补则战略冻结会虚、取舍会错 | 命题方向不稳、冻结后高概率推翻 | S2 内部 | 在追问目标/动机过程中自然获取 + 退出前显式补缺 |
| **L3** | 战术级缺口 | 不补则专题展开会虚 | 具体策略无依据、只能给原则性判断 | S4 按专题 | 讨论到哪个专题才补该专题，不提前问 |

另有一类不属于补全范畴：

| 类型 | 说明 | 处理 |
|---|---|---|
| 表达缺口 | 不影响方向，只影响任务书完整性（字段命名、来源标注、格式偏好） | S5 编译时 G3 自动补，不追问 |
| 执行阶段缺口 | 属于后续概念/方案/施工阶段才需要的信息（家具型号、材料节点、施工做法） | 不在需求分析阶段追问 |

## 四、触发信号

信息补全不常驻全开，而由四类信号触发：

### 4.1 路由信号

**当前输入不足以判断项目对象或输出层级时触发。**

典型场景：
- "做个 HAY 气质的民宿概念" —— 不清楚是整盘民宿还是只做大堂
- "帮我分析一下这个空间" —— 不清楚是需要概念框架还是平面布局

对应缺口级别：L1 框架级
处理步骤：S1

### 4.2 推理断裂信号

**系统准备往下推进，但发现缺少关键变量，推理会虚时触发。**

典型场景：
- 用户要"空间尺度控制"，但没有面积、层高、客房数量
- 用户要"完整设计框架"，但没有功能配置和运营模式
- 用户说"以 HAY 为参考"，但 HAY 的多维属性（色彩、材质、模块化、平价精品定位）中不清楚参考哪层

对应缺口级别：L2 战略级 或 L3 战术级
处理步骤：L2 在 S2，L3 在 S4

### 4.3 冻结风险信号

**即将冻结，但某个变量一旦变动会推翻当前排序时触发。**

典型场景：
- 当前按"轻度度假高复购"定公共区社交梯度，但如果实际是"高端长住疗愈型"，整个公共区策略会改写
- 用户同时要求"克制功能主义（HAY）"和"山地自然景观的在地性（粗犷石材、原木）"，存在审美冲突，优先级不明

对应缺口级别：L2 战略级
处理步骤：S2 退出前必须解决；若在 S3 才发现，回退 S2

### 4.4 概念歧义信号

**用户引用品牌/风格/案例，但引用层级不明确时触发。**

典型场景：
- "参考 HAY" —— 参考品牌气质、家具语言、色彩系统、功能主义逻辑，还是年轻生活方式？
- "北欧风格" —— 是斯堪的纳维亚极简还是丹麦 hygge 还是芬兰功能主义？

对应缺口级别：取决于影响范围。若影响命题方向则为 L2，仅影响具体选材则为 L3
处理步骤：L2 在 S2，L3 在 S4

## 五、各步骤的补全规则

### 5.1 S1 拆：静默识别 + 轻量分诊

| 维度 | 规则 |
|---|---|
| **职责** | 识别缺口、建立 `initial_gap_map`；仅对框架级缺口做轻量追问 |
| **触发信号** | 路由信号 |
| **补全预算** | ≤1 轮，≤3 题 |
| **追问方式** | 分诊式，目标是"路由正确"，不是"问透项目" |
| **禁止** | ❌ 大规模追问 ❌ 展示分析结论 ❌ 对 L2/L3 缺口发起追问 |
| **G3 兜底** | S1 退出时，用户跳过的框架级问题由 G3 推断填充 |
| **与武器库** | A1 解析 → A2 评估充足度 → 若有 L1 缺口 → E1@S1 激活 |

**典型补全示例：**

```
在进入分析之前，需要确认：
1. 这次是做整盘民宿，还是只聚焦公共区/客房？
2. 期望的输出是概念框架，还是需要到平面布局层面？

如果暂时不确定，可以跳过——我会基于已有信息先推进。
```

### 5.2 S2 目标锁定：主补全区

| 维度 | 规则 |
|---|---|
| **职责** | 在追问目标/动机/根本需求过程中，**自然获取**战略级信息；退出前显式检查战略级缺口 |
| **触发信号** | 推理断裂信号、冻结风险信号、概念歧义信号 |
| **补全预算** | ≤2 轮，每轮≤3 题 |
| **追问方式** | 启发式 —— 在追问"为什么"的过程中顺带补"什么" |
| **核心原则** | 优先"提议并确认"，而非"问答填空" |
| **禁止** | ❌ 追问战术级细节（大堂尺寸、材料型号） ❌ 进入解法设计 |
| **G3 兜底** | S2 退出时，用户跳过的战略级问题由 G3 推断填充 |
| **退出条件** | 核心目标已锁定 + 不再存在影响战略冻结的关键缺口 |
| **与武器库** | B1/B2/B3/B4 必说武器推进中自然获取 → E1@S2 在退出前补剩余战略级缺口 |

**"提议并确认"示例（采纳参考 A 的核心洞察）：**

```
反例（低效问答）：
  "请问目标客群是什么？运营模式是什么？公共区要哪些功能？"

正例（提议并确认）：
  "基于七里坪的山地地形和 HAY 的社交属性，初步判断目标客群偏向
   城市年轻群体的周末轻度度假。如果是这样，公共区应以社交聚集
   为主而非安静疗愈。这个方向对吗？如果客群或运营有不同，请纠正。"
```

**主题簇组织示例（采纳参考 B 的建议）：**

每轮补全按主题簇组织，不散问：

```
主题簇：项目规模与空间对象
1. 本次是整盘民宿，还是只做公共区/客房样板？
2. 总建筑面积大约多少？客房数量大约多少？
```

```
主题簇：品牌参考深度
1. HAY 更希望参考其家具语言，还是整体品牌气质？
2. 品牌辨识度希望"隐性渗透"还是"可被一眼识别"？
```

每轮只开一个主题簇。

### 5.3 S3 战略框架：原则不补

| 维度 | 规则 |
|---|---|
| **职责** | 消费 S2 已冻结的目标与已补全的信息，进行战略级讨论 |
| **补全行为** | ❌ 不主动发起信息补全 |
| **若发现新缺口** | 评估缺口级别：若为 L2（会推翻战略排序）→ 正式回退 S2；若为 L3（仅影响后续专题）→ 记录，留给 S4 |
| **禁止** | ❌ 在 S3 内硬补战略级信息 ❌ 临时追问大范围背景信息 |
| **回退条件** | S3 激发盲区时发现某个变量一旦变动会推翻当前战略排序 |

**为什么 S3 不补：** S3 的职责是冻结战略方向。如果在冻结过程中还在补信息，说明 S2 的退出条件没真正满足。此时正确做法不是在 S3 凑合补，而是回退 S2 重新压清。

### 5.4 S4 战术分解：按专题补全

| 维度 | 规则 |
|---|---|
| **职责** | 按专题展开时，补全该专题所需的战术级信息 |
| **触发信号** | 推理断裂信号（专题级） |
| **补全预算** | 每个专题独立 ≤1 轮，≤3 题 |
| **追问方式** | 专题簇式 —— 讨论到哪个专题才问该专题的信息 |
| **核心原则** | 不提前问后续专题的信息；不重新问战略级问题 |
| **禁止** | ❌ 重开战略讨论 ❌ 一次性问完所有专题的信息 ❌ 追问执行阶段细节（施工做法、采购清单） |
| **G3 兜底** | 每个专题补全结束后，用户跳过的项由 G3 推断填充 |
| **回退条件** | 若补全的新信息导致战略方向不可行 → 正式回退 S3 |
| **与武器库** | E1@S4 按专题激活，每个专题一次 |

**按专题追问示例：**

```
[讨论进入"大堂空间组织"专题]

在继续讨论大堂布局策略之前，需要确认：
1. 大堂面积大概多少？（大致范围即可）
2. 层高多高？
3. 有平面图或现场照片吗？

如果暂时没有准确数据，我会按中型山地民宿标准（80–120㎡、层高 4–5m）
先给出原则性布局逻辑，后续有准确数据再校准。
```

### 5.5 S5 形成成果：编译补录

| 维度 | 规则 |
|---|---|
| **职责** | 编译任务书，G3 自动兜底，标注推断来源，用户审阅 |
| **追问** | ❌ 不做任何分析性追问 |
| **G3 动作** | 扫描所有未填字段 → 推断填充 → 标注 `[推断]` + 推断依据 |
| **用户审阅** | 汇总所有 `[推断]` 字段，提示用户确认或修正 |

## 六、E1 三上下文激活规格

E1"关键缺口补全器"保持为单一武器，但定义三个激活上下文：

### 6.1 激活上下文总览

| 上下文 | 激活时机 | 缺口级别 | 预算 | 补全内容 |
|---|---|---|---|---|
| **E1@S1** | S1 退出前，A2 识别出 L1 框架级缺口 | L1 框架级 | ≤1 轮，≤3 题 | 项目类型、空间对象、输出层级、基本使用场景 |
| **E1@S2** | S2 退出前，仍有影响战略冻结的 L2 缺口 | L2 战略级 | ≤2 轮，≤3 题/轮 | 品牌参考维度、核心定位、决定性约束、红线边界、驱动力排序 |
| **E1@S4** | S4 内部按专题展开时，当前专题有 L3 缺口 | L3 战术级 | 每专题 ≤1 轮，≤3 题 | 具体尺寸、数量、技术资料、配套功能等 |

### 6.2 去重规则

- E1@S2 激活前，检查 S2 讨论过程中已间接回答的信息，**不重复追问**
- E1@S4 激活前，检查 S2/S3 过程中已获取的信息，**不重复追问**
- 同一信息如果在讨论中被间接提到（如用户说"做 20 间客房的精品民宿"），直接更新字段，不再单独追问

### 6.3 超限处理

- 若 E1@S2 第 2 轮后仍有未消除的 L2 缺口：
  - 评估该缺口是否真的影响冻结
  - 若影响：说明不是缺字段问题，而是命题未压清 → 回到 S2 主流程重新分析
  - 若不影响：降级为 L3，延后到 S4 或交给 G3

## 七、G3 即时兜底规格

### 7.1 触发时机

G3 不等到 S5 统一兜底，而在每个步骤退出时即时运行：

| 步骤 | G3 触发条件 | 兜底范围 |
|---|---|---|
| S1 退出 | 用户跳过框架级问题 | 项目类型、空间对象、使用场景、规模范围 |
| S2 退出 | 用户跳过战略级问题 | 品牌参考维度、核心定位、决定性约束 |
| S4 每专题结束 | 用户跳过战术级问题 | 当前专题的尺寸、数量、技术参数 |
| S5 编译 | G2 发现剩余空字段 | 所有遗留空字段 |

### 7.2 兜底原则

1. **推断值必须保守**：宁可保守不可激进
2. **推断依据必须可追溯**：每个 `[推断]` 标注旁注明推断来源
3. **推断结果可被用户修正**：S5 审阅时集中展示所有推断项

### 7.3 标注格式

```
客房数量：18 间 [推断：基于七里坪山地民宿中型体量，参考同区域项目]
大堂面积：100㎡ [推断：基于 18 间客房中型民宿标准配置]
```

## 八、A2 扩展：gap_level 字段

A2"信息充足度评估器"的 `gap_list` 增加 `gap_level` 字段：

| 字段 | 值域 | 说明 |
|---|---|---|
| `field_name` | 字符串 | 缺口字段名 |
| `importance` | 关键 / 补充 | 原有字段，保持 |
| `gap_level` | L1 框架级 / L2 战略级 / L3 战术级 | **新增**，标识缺口应在哪个步骤处理 |
| `affects_freezing` | 布尔 | 标识该缺口是否影响对应层级的冻结判断 |

分级规则：

- **L1 框架级**：项目类型、空间对象、输出层级、基本使用场景
- **L2 战略级**：核心定位、品牌参考维度、目标客群、运营模式、决定性约束（预算/工期/法规红线）、驱动力排序
- **L3 战术级**：具体尺寸、客房数量、配套功能清单、平面图/技术资料、材料偏好、预算细分

## 九、追问交互规则

### 9.1 追问方式优先级

1. **提议并确认**（最优）：基于已有信息做合理推断，提出判断，让用户确认或修正
2. **主题簇追问**（次优）：按主题组织 2–3 个相关问题，一轮一个主题
3. **单选/区间**（辅助）：提供选项或范围让用户快速选择
4. **开放填空**（最后）：只在确实无法结构化时使用

### 9.2 追问必须说明的内容

每个问题必须让用户理解：
- **为什么现在问**（当前讨论到了什么节点）
- **不补会影响什么**（简要一句）
- **可以跳过**（告知用户跳过后系统会推断）

### 9.3 禁止的追问行为

| 禁止项 | 说明 |
|---|---|
| 散问 | 不按主题，零碎追问一堆不相关问题 |
| 问卷化 | 一次抛出 5 题以上，退化为表单采集 |
| 层级错位 | S2 追问战术细节（大堂尺寸），或 S4 追问战略方向（核心定位） |
| 重复追问 | 讨论中已间接回答的信息再单独追问 |
| 越阶追问 | 在需求分析阶段追问执行阶段信息（施工做法、采购清单） |

## 十、回退机制

### 10.1 回退触发条件

| 发现位置 | 缺口性质 | 处理 |
|---|---|---|
| S3 激发盲区时 | 发现 L2 缺口，会推翻战略排序 | 正式回退 S2 |
| S4 专题展开时 | 发现战略方向因边界不可行 | 正式回退 S3 |
| E1@S2 超限后 | 2 轮仍有未消除的关键缺口 | 不是缺字段，是命题未压清 → 回到 S2 主流程 |
| 补全新信息后 | 新信息推翻已冻结判断 | 不继续填字段，回退到相应上游步骤重新分析 |

### 10.2 回退协议

回退时必须说明：

1. **哪条信息触发了回退**
2. **它推翻了哪个已冻结结论**
3. **建议修订哪部分**（而不是从头重来）

## 十二、HAY 七里坪验证走查

用此案例验证机制的自然性：

**用户输入：** *"以 HAY 的年轻、克制、功能主义气质为核心，为四川峨眉山七里坪山地民宿提供室内设计概念。需要完整设计框架、空间尺度控制、公共社交空间组织。"*

### S1 拆

- A2 评估：项目类型（民宿）✓、使用场景（度假人群）✓、规模范围 ✗
- gap_list：`{field: "scale_range", importance: "补充", gap_level: "L1", affects_freezing: false}`
- 评估：规模范围虽缺，但"山地民宿"已暗示中小型体量，不是路由级阻断
- E1@S1：不激活（L1 关键缺口不存在）
- 进入 S2

### S2 目标锁定

- B1 任务目标提炼过程中，追问"为什么选择 HAY"——自然获取品牌参考维度
- B2 冲突诊断："HAY 的克制功能主义" vs "山地自然景观在地性"——自然暴露冲突优先级缺口
- 退出前检查：
  - 品牌参考维度 → 已在讨论中明确 ✓
  - 冲突优先级 → 已在 B2 讨论中解决 ✓
  - 客群与运营模式 → 缺失，影响战略冻结
  - 规模 → 缺失，影响后续专题

E1@S2 激活，第 1 轮（提议并确认式）：

```
基于七里坪的山地位置和 HAY 的社交属性，初步判断：
- 目标客群偏向城市年轻群体的周末轻度度假
- 规模在 15–25 间客房（中型精品体量）
- 运营以散客为主、偶有品牌活动

这个方向对吗？如果有不同，请纠正。
```

用户确认或修正 → 战略级缺口消除 → 进入 S3

### S3 战略框架

- 激发 2–3 个战略方向：
  - 方向 A："HAY 社交客厅"——公共区主导，品牌高辨识度
  - 方向 B："山地功能主义"——HAY 方法论 + 在地材料，品牌隐性渗透
  - 方向 C："双核策略"——公共区显性 HAY + 客房隐性山地
- 识别决定性矛盾 → 用户选定 → 冻结战略取舍
- **无缺口暴露，不回退**

### S4 战术分解

按专题推进：

**专题 1：大堂空间组织**

E1@S4 激活：

```
在讨论大堂布局策略之前，需要确认：
1. 大堂面积大概多少？（大致范围即可）
2. 层高多高？
3. 有平面图或现场照片吗？

如果暂时没有准确数据，我会按中型山地民宿标准
（80–120㎡、4–5m 层高）先给出原则性策略。
```

用户回答或跳过 → G3 推断 → 继续该专题

**专题 2：客房配置策略**

E1@S4 激活：

```
关于客房配置：
1. 20 间客房大概分几种房型？
2. 每种房型的面积范围？
```

用户回答或跳过 → G3 推断"标准配置：大床房 60%、双床房 30%、套房 10%"→ 继续

**专题 3–N**：按此模式逐专题推进

- G3 扫描空字段：标注所有推断值
- 汇总展示：

以下字段为系统推断，请确认或修正：
