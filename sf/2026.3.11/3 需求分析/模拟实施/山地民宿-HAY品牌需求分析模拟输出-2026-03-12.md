## 专业知识底盘参与总览

依据 `D:\11-20\2026.2.25\langgraph-design\sf\2026.3.11\专业知识底盘\README.md` 及其配套文档，需求分析系统不只是“有流程、有武器”，还必须回答：

> **系统到底用什么知识做判断？**

专业知识底盘在系统中的定位是：

- 流程层决定**做什么**
- 武器层决定**怎么做**
- 专业知识底盘决定**用什么知识做**

若按底盘架构文档还原，本案例背后应存在一个统一接入层：

- `KnowledgeRegistry`

它并不是让每个节点自己去翻不同 loader，而是按场景向节点配送四层知识：

| 层级 | 定位 | 本案例中的主要作用 |
|---|---|---|
| `L1 规则层` | 强约束、硬边界、规则卡 | 支撑山地静谧、维护可行性、边界压缩、门禁判断 |
| `L2 矩阵层` | 类型 × 模式 × 维度 × 任务 的单一事实源 | 支撑项目类型识别、空间分类、品牌/度假/民宿的上下文匹配 |
| `L3 经验层` | 案例、成功/失败片段、向量经验库 | 为“品牌不等于强陈列”“山地社交应低压”提供经验类参照 |
| `L4 项目记忆层` | 当前项目的已确认项、否决历史、冻结结果 | 记录本轮用户确认、取舍基线与回流原因 |

这意味着：本案例里“山地民宿 × HAY 品牌气质”并不是系统现场拍脑袋推出来的，而应理解为：

- **L2** 先告诉系统它面对的是哪类空间对象、哪类项目语境
- **L1** 告诉系统哪些边界不能被浪漫化表达覆盖
- **L3** 告诉系统类似命题里常见的成功/失败判断方式
- **L4** 记录这次会话里哪些判断已经被冻结、哪些仍只是 `[推断]`

## 空间分类系统参与还原

依据 `04-空间分类系统与类型清单-2026-03-11.md` 与 `SPACE_CLASSIFICATION_SYSTEM_INVENTORY-空间分类系统清单.md`，空间分类不是一个单点模块，而是一条链：

> **分类定义 → 类型检测 → 状态写入 → 本体注入 → 问卷消费 → 交付消费**

映射到本案例，应理解为：

1. **分类定义中心**
   - `_type_registry.py` 提供 `project_type / parent_type / specialty_tag` 的权威字典
2. **分类检测中心**
   - `project_type_detector.py` 或 `requirements_analyst_agent` 完成项目类型初判
3. **状态写入中心**
   - `requirements_nodes.py` 将 `project_type / space_object_hint / physical_context` 写入主状态
4. **语义注入中心**
   - `ontology_loader.get_layered_ontology()` 按项目类型 + 专家角色注入分析维度
5. **交互消费中心**
   - 问卷与审阅层按 `project_type` 决定“空间类型配置 / 功能分区 / 追问逻辑”
6. **交付消费中心**
   - `deliverable_id_generator_node` 后续按 `space_type` 生成交付命名

因此，本案例里“七里坪山地民宿”并不只是一个自然语言标签，它在系统里意味着：

- 这是一个需要进入 `hospitality / tourism / branded interior` 相关类型语境的项目
- 它会牵动问卷、执行层本体注入、交付命名乃至后续维度选择
- 它不是“审美风格词”，而是底盘中的**分类锚点**

### 为什么之前看起来只有几句话

- 它会参与分类

这种写法能说明“**有参与**”，但不能让人感知：

- 到底**有哪些类型**

### 激活图谱告诉系统：同样是空间，重心完全不同

`activation_profiles` 又把类型框架往前推进了一层。它不是再写一遍类型定义，而是规定：

- 这一类项目重点激活哪些本体议题（如 `E1~E9`）
- 这一类项目通常分析到 `L1 / L2 / L3 / L4` 哪一层
- 这一类项目有哪些典型“不可回避的张力”

例如：

| 类型 | 重点激活 | 典型深度 | 典型张力 |
|---|---|---|---|
| `commercial_hospitality` | `E3 光` `E4 材料` `E5 时间性` | `L2-L4` | 品牌标准化 vs 在地独特性；服务可见度 vs 宁静感；旺季容量 vs 淡季空置 |
| `commercial_office` | `E1 体量` `E2 身体体验` `E8 技术系统` | `L1-L3` | 协作开放 vs 专注安静；层级表达 vs 平等文化 |
| `healthcare_wellness` | `E2 身体体验` `E3 光` `E8 技术系统` | `L0-L4` | 监控效率 vs 患者尊严；感染控制 vs 空间温度 |
| `commercial_retail` | `E1 空间体量` `E3 光` `E9 经济伦理` | `L1-L3` | 体验面积 vs 陈列面积；品牌一致性 vs 在地化 |
| `rural_regeneration_urban_renewal` | `E4 材料` `E5 时间` `E9 价值分配` | `L2-L4` | 原真性 vs 现代宜居；原住民利益 vs 外来投资 |

这就意味着：

- 酒店不是用办公的眼睛看
- 养老不是用零售的逻辑看
- 城市更新不是用单纯住宅美化的方式看

底盘真正丰满的地方，就在这里。

### 本案例在类型底盘中的命中链，不应只写成“山地民宿”四个字

如果把本案例放回真实底盘链条，应更完整地写成：

| 层级 | 本案例命中 |
|---|---|
| `project_type` | `commercial_hospitality` |
| 中文标签 | `酒店民宿/度假` |
| `parent_type` | `hospitality` |
| `specialty_tag` 候选 | `b_and_b` / `boutique_hotel`（取决于表述精度） |
| 本体框架 | `commercial_hospitality` |
| 激活重心 | `E3 光作为设计材料`、`E4 材料物性与时间性`、`E5 时间与时序动态` |
| 典型张力 | 品牌标准化 vs 在地独特性；社交活力 vs 山地静谧；旺季容量 vs 平日松弛 |

于是，本案例的很多判断，才真正能解释为“为什么是这些重点”：

- 为什么文档会强调**光感、材质温度、季节与时段切换**
   - 因为 `commercial_hospitality` 的底盘激活重心本来就偏 `E3 / E4 / E5`
- 为什么会强调**公共社交要低压、可退出**
   - 因为民宿/度假空间的公共区不是单纯效率型大厅，而是宾客旅程与社交动力学的一部分
- 为什么会强调**品牌不能做成陈列馆**
   - 因为酒店文旅项目的核心张力之一，本来就是“品牌一致性 vs 在地独特性”

这时，底盘就不再只是“参与过”，而是能解释“为什么系统会这样判断”。

### 空间类型底盘对本案例的真实贡献，不止分类，而是四次给方向

具体到这份案例，空间类型底盘至少在四个地方给了方向：

1. **先把题目归对类**
    - 避免把它误读成单纯住宅风格题、品牌展厅题、或景观设计题。

2. **告诉系统应优先看什么**
    - 对酒店民宿，不是先问“造型够不够特别”，而是先看宾客旅程、在地性、服务方式、公共区社交动力学。

3. **告诉系统主要矛盾是什么**
    - 不是泛泛的“既要又要”，而是行业里反复出现的那几类硬张力：品牌 / 在地、社交 / 静谧、旺季 / 淡季、标准化 / 个性化。

4. **告诉系统输出该往哪种任务书冻结**
    - 对这类项目，冻结对象更应是“宾客体验结构 + 公共空间组织 + 品牌转译原则 + 运营边界”，而不是先冻结材料型号和装饰风格词。

### 复盘结论：你看到的“几句话”只是入口，不是库的全貌

因此，这一层更准确的结论应该写成：

- 之前文档中呈现的“空间类型参与”，**只够证明它有接线**；
- 但从真实底盘看，空间类型库实际上已经具备：
   - **项目类型注册表**
   - **父类桶**
   - **专项标签**
   - **类型化本体框架**
   - **激活图谱与典型张力**
   - **专家扩展注入能力**
- 所以它不是几句话的“背景注释”，而应该被理解为：

> **需求分析系统里最核心的知识组织入口之一。**

这也是为什么，本案例如果要更真实地还原系统，就必须把“山地民宿 × HAY”放回这个完整谱系里，而不能只写成一句“类型会影响后续流程”。

## 空间类型底盘如何逐层约束本案例判断

如果继续把这份案例往“系统真实运行”方向还原，那么空间类型底盘对本案例的作用，不应停在“命中 `commercial_hospitality` 就结束”，而应继续展开成一条**逐层约束链**：

> **题目文本 → 类型命中 → 父类归桶 → 专项标签候选 → 本体框架注入 → 激活图谱聚焦 → 专家视角增强 → 四个设计判断落地**

### 第 1 层：文本命中不是在识别风格，而是在识别任务语境

本题中的高价值触发词并不是“HAY”本身，而是：

- `山地`
- `民宿`
- `轻度度假`
- `公共社交空间`

这些词会把系统优先推向：

- `commercial_hospitality`

这一步的关键价值在于：系统先知道自己面对的是**住宿 / 度假 / 公共区并存的 hospitality 任务**，而不是：

- 住宅美学问答
- 品牌展厅设计
- 单纯景观概念题

如果第一步归类错了，后面再聪明也会越跑越偏——这就是空间类型底盘的第一道价值。

### 第 2 层：`parent_type = hospitality` 让系统切换到“宾客旅程”而不是“户型优化”视角

一旦进入：

- `parent_type = hospitality`

系统就会天然把问题理解成：

- 人如何到达
- 人如何停留
- 公共区如何组织
- 客人如何在共享与私密之间切换
- 服务如何出现又不过度打扰

这也是为什么本案例后面的分析重点，会自然落到：

- 公共社交节点
- 停留方式
- 山地度假节奏
- 品牌如何通过使用被感知

而不是先冲向：

- 客厅电视墙怎么做
- 柜子收纳够不够
- 标志性造型够不够强

说白了，`parent_type` 做的事情，就是帮系统选对“看问题的镜头”。

### 第 3 层：`specialty_tag` 候选会继续压缩判断口径

对于本案例，若文本更明确，系统进一步可能命中：

- `b_and_b`
- `boutique_hotel`

这两个候选标签虽然看起来只是细分，但它们会继续改变分析口径：

| 候选标签 | 对判断口径的影响 |
|---|---|
| `b_and_b` | 更强调低压停留、类家感、人与景的日常关系、非标准化温度 |
| `boutique_hotel` | 更强调品牌一致性、精致体验、识别度与体验编排 |

而本案例之所以会形成“**有品牌感，但不能做成强展示；有社交，但不能做成强聚会**”的判断，恰恰就是因为它在这两个细分口径之间取了一个中间版本：

- 既不是完全家常型民宿
- 也不是完全品牌秀场型精品酒店

这不是拍脑袋调和，而是类型细分带来的判断压缩。

### 第 4 层：`commercial_hospitality` 本体框架决定系统优先提取哪些问题

一旦进入 `ontology.yaml` 的 `commercial_hospitality`，系统看到的重点不再是通用问题，而会偏向三组：

1. **宾客旅程**
   - 到达与第一印象
   - 客房作为“第二个家”
   - 公共空间的社交动力学

2. **地域身份**
   - 在地性表达
   - 文旅融合深度
   - 季节性与可持续性

3. **服务模式**
   - 服务可见度
   - 标准化与个性化平衡
   - 技术赋能程度

这三组问题，几乎直接决定了本案例四个关键设计判断的框架：

| 本体关注组 | 在本案例中转成的判断 |
|---|---|
| 宾客旅程 | 公共空间必须支持“进入—停留—相遇—退出”的行为链 |
| 地域身份 | 山地感不能做成表皮装饰，而要转成光、材料、视线与时序体验 |
| 服务模式 | 品牌感与服务感都要低压出现，不能让空间变成过度表演型 hospitality 场景 |

### 第 5 层：激活图谱把本案例的注意力集中到 `E3 / E4 / E5`

`activation_profiles` 对 `commercial_hospitality` 的建议重心是：

- `E3 光作为设计材料`
- `E4 材料物性与时间性`
- `E5 时间与时序动态`

这一步非常关键，因为它解释了：

为什么这份案例不是靠“风格词堆砌”成立，而是靠三类更底层的空间判断成立。

#### 1. 对色彩系统的约束

因为 `E3 / E4` 被激活，所以色彩系统不会被理解成平面配色题，而更像：

- 在山地光线中的综合色偏移问题
- 在不同材质表面上的显色与温度问题
- 在晨雾、午后、夜间三种状态下的气氛控制问题

所以本案例才会得出：

- 低饱和基础色为主
- 强调色只做节奏点
- 冷灰体系需要适度暖化

#### 2. 对家具策略的约束

因为 `E4 / E5` 被激活，家具不是只看“像不像 HAY”，而要同时看：

- 触感与材料温度
- 湿润环境下的耐久与维护
- 高峰 / 低峰时段的重组能力

所以本案例才会落到：

- 模块化家具
- 品牌单品 + 在地材料包裹
- 可移动、可替换、可重组

#### 3. 对空间尺度控制的约束

因为 `E3 / E5` 被激活，尺度控制也不会只看平面开间，而会连同：

- 光的进入方式
- 人在不同时段的停留强度
- 山地度假中“想看景、想静一会儿、想可退可进”的身体状态

所以才会形成：

- 公共开放
- 半公共收拢
- 私密包裹

这种三级尺度系统。

#### 4. 对公共社交组织的约束

因为 `commercial_hospitality` 本体本来就包含“公共空间社交动力学”，再叠加 `E5 时间性`，系统自然不会把公区理解成单一大厅，而会更像：

- 某些时段是早餐效率场
- 某些时段是窗边停留场
- 某些时段是夜间小聚场

所以本案例才会冻结为：

- 必经社交
- 可选社交
- 可退出社交

这其实就是空间类型底盘在替案例决定“社交结构应该长什么样”。

### 第 6 层：如果换类型，本案例的答案会被彻底改写

为了证明底盘不是装饰性名词，可以反向看：如果本题被判成别的类型，结论会明显不同。

| 若误判类型 | 会被拉向什么方向 | 为什么这会错 |
|---|---|---|
| `personal_residential` | 更关注家庭成员、私密动线、收纳与日常生活仪式 | 会把山地民宿误读成私宅装修题 |
| `brand_experience` | 更关注品牌叙事、展示触点、视觉识别强度 | 会把民宿做成品牌展馆 |
| `landscape_outdoor` | 更关注生态系统、路径体验、微气候 | 会弱化室内宾客旅程与服务模式 |
| `commercial_retail` | 更关注浏览动线、转化区、坪效与陈列层级 | 会把公共空间变成消费型空间 |

这反过来也证明：

> 空间类型底盘不是“分析之后的标签”，而是“分析之前就决定方向的前提系统”。

### 第 7 层：本案例真正冻结的，其实是一个 hospitality 类型任务书

如果把这次输出重新命名得更准确一点，它冻结的并不是“一个 HAY 风格概念”，而是一个更完整的对象：

> **山地 hospitality 项目中，品牌化民宿公共 / 半公共 / 私密体验系统的任务书候选**

这意味着它真正冻结的是：

- 宾客如何在山地环境中进入空间
- 品牌如何不靠高强度陈列仍被识别
- 公区如何支持低压社交与可退出停留
- 色彩、家具、尺度、时段切换如何共同维持度假体验

换句话说，本案例现在已经不只是“用类型库解释自己”，而是可以反过来说：

> **它本身就是一个由 hospitality 类型底盘驱动出来的任务书原型。**

## S1 理解输入

### 专业知识底盘参与（S1）

1. 项目地点位于**四川峨眉山七里坪**，场地语境为山地自然景观环境。

   - 品牌辨识度的建立
5. 用户要求的结果不是一句风格口号，而是**完整设计框架**，并明确点名四个展开维度：

   - 公共社交空间组织

  - 轻盈但不轻浮

  - 功能优先但不无聊
  - 日常化但有识别度

  - 山雾、林地、坡地、湿润、安静、呼吸感、视线层次

### 一主两辅入口判断

根据 `02-需求分析一主两辅方法-2026-03-11.md`，本题在 `S1` 阶段应先完成三类初始识别：

- 品牌感要通过比例、留白、家具与节奏建立

- 运维、湿度、峰谷使用强度会压缩表达方式

### 空间命题

本项目真正要解决的问题，不是“把 HAY 风格贴到民宿里”，而是：

> 在七里坪山地自然语境中，以 HAY 的年轻、克制、功能主义为品牌语法，建立一个兼顾自然沉浸、轻度度假松弛感与低压社交体验的山地民宿室内系统，并使品牌辨识度通过空间组织而非装饰堆砌被感知。

这意味着本项目的主线对象不是“风格”，而是一个可被继续设计和执行的**空间命题**：

- 民宿应成为人与山地关系的过滤器，而不是屏蔽器。
- 品牌识别应体现在空间秩序与家具逻辑中，而不是喧宾夺主的视觉符号中。
- 公共空间应鼓励相遇，但不强迫停留；应支持社交，但保留退出权。

### 空间类型 → 空间任务 → 空间命题

为更完整体现“一主两辅”的主线推进，本题的主线应明确写成三段：

1. **空间类型**
   - 山地民宿
   - 室内概念阶段
   - 兼具住宿、停留、观景、轻社交、品牌识别等复合属性

2. **空间任务**
   - 让住客从城市节奏切换到山地度假节奏
   - 让品牌气质被日常使用感知，而不是通过符号灌输
   - 让公共区同时支持相遇、短停、观景、阅读、小规模社交和自主退出

3. **空间命题**
   - 以 HAY 的年轻、克制、功能主义为组织语法，把山地民宿从“风格化住宿空间”推进为“兼顾自然沉浸、品牌识别和低压社交的度假空间系统”。

这样写的意义在于：文档冻结的不是“北欧审美偏好”，而是一个能继续进入设计、拆解和执行的**空间任务对象**。

### 驱动力排序

结合项目类型与题目语义，当前驱动力排序建议如下：

1. **自然体验驱动力**
   - 山地场景是项目的第一现场，空间必须服务于看山、停留、放松、转换节奏。
2. **品牌表达驱动力**
   - HAY 的品牌气质不是装饰附加项，而是本项目概念成立的识别核心。
3. **轻度度假行为驱动力**
   - 住客需要的是“松弛但不无聊”的空间体验，既能独处，也能轻社交。
4. **运营效率驱动力**
   - 民宿需要维护便利、家具耐用、空间可复用、公共区域高峰期不失控。

> 结论：本项目的正确方向不是“品牌优先压过一切”，也不是“在地优先吞没品牌”，而是让品牌成为**组织自然体验的语法**。

### 人的驱动力修正轴

按照“一主两辅”原方法，驱动力不是背景说明，而是对空间命题的持续修正。就本题而言，至少存在以下几类主体：

- **品牌方 / 主理方**：希望空间可被识别为 HAY 气质的延伸，而不是普通山地民宿。
- **住客 / 使用者**：希望获得放松、观景、松弛、轻交流、不过度被打扰的度假体验。
- **运营方**：希望空间好维护、好切换、在高峰和低峰时段都不失控。

这些驱动力并不天然一致，因此本轮冻结的权重关系是：

1. 山地度假体验不能被牺牲，否则空间失去场地根基；
2. 品牌表达不能消失，否则项目失去命题独特性；
3. 运营效率不能被忽略，否则概念无法长期成立。

换句话说，人的驱动力在这里真正修正的是：

- 品牌感不能只靠视觉冲击，而要靠可使用的空间秩序体现；
- 社交空间不能只为拍照而生，而要服从真实停留行为；
- 山地感不能只是材料化装饰，而要转化为节奏、视线与停留方式。

### 关键冲突对

#### 1. 品牌辨识度 vs 在地自然融入

- 风险一端：若品牌表达过强，空间会像被搬进山里的城市陈列场。
- 风险另一端：若在地表达过强，HAY 的品牌存在感会被稀释成普通山地民宿。
- 当前判断：**品牌通过形式系统显现，在地通过材料与光感显现。**

#### 2. 克制感 vs 民宿温度感

- 风险一端：过度克制会导致空间显冷、显疏离。
- 风险另一端：过度温暖会把 HAY 的清爽感与功能秩序冲淡。
- 当前判断：**保留克制的骨架，用材质、光线和触感补温。**

#### 3. 开放社交 vs 山地静谧体验

- 风险一端：公共区若过强社交，会破坏山地的安静感。
- 风险另一端：若完全避社交，公共空间会失去民宿应有的共享气氛与品牌场景活力。
- 当前判断：**建立三级社交节点，而不是单一大堂。**

#### 4. 松弛度假感 vs 功能组织效率

- 风险一端：太松会导致流线松散、运营失效。
- 风险另一端：太规整会让度假体验像酒店流程空间。
- 当前判断：**运营逻辑隐藏在清晰秩序中，但使用感受要保持松弛。**

### 边界压缩结果

#### 场地边界

- 山地景观要求室内空间优先处理**看、停、转身、借景**关系。
- 湿润气候要求材料与家具策略优先考虑耐久、保养、触感稳定性。
- 山地的安静气质要求公共社交空间避免高密度、高噪音、高刺激的表达方式。

#### 运营边界

- 民宿家具和公共空间不能高度依赖复杂维护。
- 公共区应支持早餐、阅读、短会面、夜间小聚等多模式切换。
- 家具与灯具策略宜模块化，便于季节切换、清洁和局部替换。

#### 品牌边界

- HAY 的识别度更适合通过：
  - 颜色配比
  - 家具轮廓
  - 物件尺度
  - 留白秩序
  - 功能布局清晰度
  来建立。
- 不建议用大面积品牌符号、强硬色块铺陈或过度陈列化方式建立品牌感。

### 边界压缩后的结果

为体现“边界不是最后兜底，而是全过程压缩”，本题有几类设想已被明确压缩或阶段化：

- **被压缩的设想 1：高强度品牌展示空间**
   - 原因：会迅速把山地民宿拉向城市零售 / 展示逻辑。
   - 处理：改为在家具、色彩节点和比例秩序中建立识别。

- **被压缩的设想 2：单一大型开放社交厅**
   - 原因：与山地静谧体验和轻度度假客群行为不匹配。
   - 处理：改为“必经社交 + 可选社交 + 可退出社交”三级节点。

- **被阶段化的设想 3：高复杂度定制装置与材料表达**
   - 原因：维护、湿度适应、运营替换成本尚未验证。
   - 处理：本轮只冻结原则，不冻结具体做法，留给后续执行阶段结合预算与维护模型展开。

- **被阶段化的设想 4：客群细分下的功能强化**
   - 原因：亲子、团建、长住疗愈等模式尚未确认。
   - 处理：本轮先冻结“轻度度假 + 低压社交”的主版本，不提前做题外加法。

- `invalidated`：因主线重构或关键前提翻转而失效

从 AnalyticalCoverageTracker 的角度，本案例当前覆盖的是：

- S2：空间命题、核心冲突、关键约束已形成

也就是说，S3 底盘最重要的价值不是提供新知识，而是提供：

1. 建立一个**既能被识别为 HAY 气质，又能被感知为山地度假空间**的室内概念系统。

### 空间命题

本项目的空间任务，是为山地民宿建立一个以 HAY 品牌语法组织的室内系统：

- 以克制、清晰、功能主义的方式组织空间秩序；
- 以温润、安静、可停留的方式回应山地环境；
- 以“可相遇、可停留、可退出”的方式组织公共社交；
- 以家具、色彩、比例与留白构成品牌识别，而非依赖表面装饰。

### 驱动力结构

- 主导驱动力：自然沉浸体验
- 第二驱动力：品牌识别与品牌一致性

已冻结的权重逻辑：

- 场地语境是第一约束，不可牺牲；
- 品牌表达是第一识别线，不可消失；
- 使用行为是组织公共空间的校准器，不可忽视；
- 运营效率是执行层的稳定器，不可缺席。

### 实施边界

#### 硬约束

- 必须与山地景观共存，不可形成与场地断裂的城市室内感。
- 公共空间必须可运营、可清洁、可切换，不得高度依赖复杂摆场。
- 家具与材料需考虑潮湿环境下的稳定性与维护性。

#### 软约束

- 品牌识别建议通过控制而非铺张实现。
- 色彩系统应以低饱和和中低明度为主，强调色只作为节奏点使用。
- 公共社交氛围应偏向轻交流，而非强互动。

#### 不在本轮范围内

- 精准客房数与运营模型测算
- 完整软装采购品牌表
- 施工级细节与节点深化

### 关键取舍

- 已冻结优先级：自然体验 > 品牌可识别性 > 轻社交体验 > 展示性表达
- 已接受牺牲项：削弱强打卡属性、削弱过度装饰性、削弱高饱和品牌视觉轰炸
- 不可突破红线：破坏山地静谧、破坏舒适度、破坏品牌基本秩序
- 延后处理项：具体型号、预算、施工节点、运营细化

### 不确定性与后续展开项

- `[推断]` 客群的平均停留时间与年龄结构仍需后续验证。
- `[推断]` 淡旺季公共空间使用强度差异需要结合真实运营数据修正。
- `[推断]` 品牌色温与在地材料综合色偏移的容差需与品牌方进一步确认。
- 后续执行阶段建议重点补问：
  - 客房数量与公区面积比例
  - 是否有餐饮联动或联名零售需求
  - 是否需要兼顾亲子/小团体使用场景
  - 运营高峰时段与夜间使用策略

## 1. 色彩系统

### 1.1 基础策略

色彩系统建议采用“**低饱和基础色 + 节制强调色 + 山地光感校准**”的三层结构。

#### 基础色

- 暖灰白
- 石雾灰
- 亚麻米白
- 松木浅褐
- 炭灰黑（少量用于轮廓压线）

这些颜色承担的不是装饰功能，而是建立 HAY 式的清爽秩序感与功能背景。

#### 强调色

强调色不宜多，建议控制在 1–2 组小面积节点：

- 鼠尾草绿
- 雾蓝
- 柔和砖橘 / 山地晚霞铜调

`[推断]` 相较于标准偏冷的北欧语境，七里坪山地环境更适合把灰调向暖石灰、把强调色略微调暖，以减少空间冷感并与自然光线更兼容。

### 1.2 配比原则

- 基础中性色：约 70%–80%
- 木、石、织物等材质自然色：约 15%–20%
- 强调色节点：约 5%–10%

结论不是“颜色越少越高级”，而是：**颜色必须服务于节奏、识别与停留感。**

### 1.3 品牌识别边界

品牌识别应通过以下位置出现：

- 公共主厅中的核心家具簇
- 吧台 / 接待 / 阅读区的局部色块
- 可被重复感知的灯具、椅子、边几系统

不建议：

- 大面积品牌色刷墙
- 高对比图形化地面
- 强视觉轰炸式陈列

## 2. 家具策略

### 2.1 总体原则

家具应成为本项目品牌识别的主要载体之一，但前提是：

- 能被使用
- 能被重组
- 能适应山地民宿维护强度
- 能与在地材料和自然光关系协同

因此建议采用“**模块化 + 局部品牌单品 + 在地材料包裹**”的组合策略。

### 2.2 模块化策略

- 公共区沙发与坐具采用可拆分、可重组系统，适配不同人数和时段。
- 边几、单椅、软垫凳形成可移动微节点，支持“临时相遇”与“快速撤离”。
- 长桌 / 拼桌系统适合早餐、共创、阅读、轻办公等复合模式。

### 2.3 品牌识别家具

品牌识别建议集中在以下几类单品：

- 轮廓简洁但比例鲜明的单椅
- 具有轻盈感的边几与茶几
- 色彩受控但识别度高的餐椅 / 吧椅
- 结构清晰、不过度厚重的灯具系统

这些单品的作用不是“把品牌摆满”，而是让住客在使用过程中逐步感知品牌逻辑。

### 2.4 在地材料协同

家具系统宜与在地材料形成互补而非竞争：

- HAY 系家具负责精确、轻盈、秩序感
- 在地木、石、织物负责温度、触感、沉静感

建议策略：

- 框架与移动家具偏品牌化
- 固定台面、壁龛、坐榻、背景界面偏在地化

### 2.5 可移动与可重组原则

- 公共社交空间的家具应支持 2 人、4 人、6–8 人不同级别聚合。
- 家具之间保留足够留白，避免公区视觉拥堵。
- 不宜使用过多深体量、难挪动、难清洁的厚重民宿家具。

## 3. 空间尺度控制

### 3.1 总体尺度逻辑

建议采用“**公共开放 + 半公共收拢 + 私密包裹**”的三级尺度系统。

尺度不是只看尺寸，而是看：

- 人是否愿意进入
- 进入后是否愿意停留
- 停留后是否保留退出权

### 3.2 公共尺度

公共主厅应具备视觉开敞感，但不建议做成单一巨厅。

建议：

- 通过天花、家具簇、灯光和地面材质轻微分区
- 保持视线可穿透，形成与山景的连续关系
- 在入口、吧台、景观面之间建立清晰秩序

空间感关键词：

- 轻
- 通
- 有秩序
- 不喧闹

### 3.3 半公共尺度

半公共区域是本项目最关键的舒适层，应承担“可停留、可轻聊、可读书、可等人”的功能。

建议设置：

- 壁炉 / 茶歇角
- 窗边阅读位
- 长桌侧边的小组沙发簇
- 靠墙 / 靠柱 / 靠景观界面的低压坐区

这些空间的尺度应比主厅略收，营造心理安全感。

### 3.4 私密尺度

私密空间不论是客房还是静坐角，都应体现：

- 被包裹感
- 安静感
- 对外界自然的选择性连接

建议：

- 用较柔和的材质与更低刺激的颜色处理
- 保留一处明确的“看山 / 看树 / 看雾”的定点停留位置
- 控制视觉杂讯，避免品牌表达进入过强

## 4. 公共社交空间组织

### 4.1 组织原则

公共社交空间不应被理解为“做一个热闹大堂”，而应被理解为：

> 通过不同压力等级的节点安排，允许住客在山地环境中自然发生相遇、停留、交流与退出。

因此建议采用三级节点：

- 必经社交
- 可选社交
- 可退出社交

### 4.2 必经社交节点

这些节点承担民宿运营必需的共享行为：

- 接待前厅
- 早餐 / 餐饮区
- 吧台 / 茶水点
- 主流线转折口

策略：

- 保持开放、清晰、易识别
- 家具更简洁，流线更明确
- 品牌识别在这里应较清楚，但不应压迫使用效率

### 4.3 可选社交节点

这些节点承担“可参与但不强迫”的社交行为：

- 窗边长凳
- 小组沙发簇
- 阅读角
- 半围合茶叙位

策略：

- 适合 2–4 人互动
- 保留一定距离与声学缓冲
- 让人既能加入，也能只作为观察者停留

### 4.4 可退出社交节点

这是山地民宿区别于城市酒店的重要部分，建议重点设计：

- 靠景观边缘的单人位 / 双人位
- 远离主流线的边角坐区
- 面向山景但不暴露于中心视线的位置

策略：

- 允许一个人停留而不感到尴尬
- 允许两人低声交流而不被打扰
- 形成“在共享空间里保有个人边界”的体验

### 4.5 时间段切换逻辑

同一公共空间在不同时段应呈现不同状态：

- 早餐时段：偏开放、清晰、效率导向
- 下午时段：偏分散、阅读、观景、轻交流
- 夜间时段：偏收拢、温暖、低照度、小聚落

因此空间组织重点不是做更多区域，而是让同一空间通过灯光、家具、距离与氛围切换出不同使用模式。
