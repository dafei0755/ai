> **补充目的**：展示每个武器的输入来源、输出对象、下游消费关系
> **补充位置**：插入到主模拟文档每个武器输出后

## S2 阶段武器协作链

### B1 任务目标提炼器 — 武器协作链

| 项目 | 内容 |
|------|------|
| **武器 ID** | B1 |
| **武器名称** | 任务目标提炼器（Task Target Refiner） |
| **执行轴** | S2 必说（ALWAYS_SPEAK_S2, order=1） |
| **方法轴** | 主线推进（advance_mainline）+ 驱动力修正（correct_driver，副标签） |
| **输入来源** | ① A1 信号包（`structured_requirements`）<br>② F2 根本需求（`root_needs`）<br>③ F3 关键洞见（`key_insights`）<br>④ B4 使用者身份（`identity_mode`）<br>⑤ L2 矩阵（`commercial_hospitality` 框架）<br>⑥ L4 项目记忆（`user_history`） |
| **输出对象** | `jtbd_statement: {situation, job, motivation, full_text}` |
| **输出示例** | 当 一群对设计敏感、厌倦了传统民宿「木石民族风」的城市年轻人，想在峨眉山找一个周末可以抵达的山地度假目的地时，他们想要 住进一个「看起来不像民宿」的地方——空间克制、安静、有当代设计感，同时能真正感受到山的存在，因为 他们需要的不是「逃进山里」，而是「带着城市审美进入自然，在自然中确认自己的生活方式仍然成立」。 |
| **下游消费** | → B2 目标冲突诊断器（B2 消费 `jtbd_statement` + F3 洞见）<br>→ B3 全局影响扫描器（B3 消费 `jtbd_statement`）<br>→ S4 任务书（JTBD 进入"空间命题 / 核心任务"章节）<br>→ F7 优先级反事实验证器（验证 B1 优先级稳健性） |
| **VoiceSlot 状态** | pending → delivered（展示给用户）→ responded（用户确认） |
| **TriggerIntent** | `advance_mainline`（推进空间命题主线：从"山地民宿集群"推进到"让城市年轻人在山地环境中获得既属于自然、又属于当代生活的空间体验"） |
| **Reframe 依赖** | 若 B1 被否定（reframe），则 B2/B3/C1/C2/C3/D1 → invalidated |
| **质量门控** | G1（输出锐度门控）：确保任务定义具体可执行<br>F5（套话替换）：去掉「以人为本」「注重体验」等空洞表述 |

### B2 目标冲突诊断器 — 武器协作链

| 项目 | 内容 |
|------|------|
| **武器 ID** | B2 |
| **武器名称** | 目标冲突诊断器（Goal Conflict Diagnostician） |
| **执行轴** | S2 必说（ALWAYS_SPEAK_S2, order=2） |
| **方法轴** | 主线推进（advance_mainline）+ 横切校验（cross_validate，副标签） |
| **输入来源** | ① B1 输出（`jtbd_statement`）<br>② F3 关键洞见（`key_insights`）<br>③ L1 规则（冲突规则库）<br>④ L2 矩阵（`commercial_hospitality` 常见冲突模板）<br>⑤ L3 案例（福州雅诗阁、狮岭村的冲突案例） |
| **输出对象** | `conflict_pairs: [{goal_a, goal_b, conflict, if_both, type}]` |
| **输出示例** | 冲突 1：品牌克制感 vs 山地感官丰富性<br>冲突 2：功能主义标准化 vs 在地性独特表达<br>冲突 3：社交开放性 vs 度假私密性 |
| **下游消费** | → B3 全局影响扫描器（B3 调整影响扫描重点）<br>→ S3 张力冻结（`conflict_pairs` 是决策矩阵的行）<br>→ D1 设计前提校验器（S3 会专门挑战 B2 给出的冲突诊断） |
| **VoiceSlot 状态** | pending → delivered → responded（用户确认冲突存在） |
| **TriggerIntent** | `advance_mainline`（识别核心矛盾，推进空间命题从"任务"到"命题"） |
| **Reframe 依赖** | 若 B2 被否定（"这不是冲突"），则 B3/C1/C2/C3/D1 → invalidated |
| **质量门控** | G1（输出锐度门控）：冲突描述必须具体，不接受「目标 A 和目标 B 存在一定张力」等模糊表达<br>必须明确「若两者都不让步，最可能牺牲的是 X」 |

### D2 约束条件识别器 — 武器协作链

| 项目 | 内容 |
|------|------|
| **武器 ID** | D2 |
| **武器名称** | 约束条件识别器（Constraint Condition Identifier） |
| **执行轴** | S2 必说（ALWAYS_SPEAK_S2, order=3，但在 v3.0 中移到 S3） |
| **方法轴** | 边界压缩（compress_boundary）+ 驱动力修正（correct_driver，副标签） |
| **输入来源** | ① A1 约束信号（`constraint_signals`）<br>② F1 标注的 [FACT] 类信号<br>③ B3 全局影响扫描结果<br>④ D1 挑战结论（隐含约束）<br>⑤ L1 规则（硬约束库）<br>⑥ L2 矩阵（`commercial_hospitality` 约束模板） |
| **输出对象** | `confirmed_constraints: {never_do: [], hard_limits: [], soft_preferences: []}` |
| **输出示例** | 绝对红线：① 不做「HAY 展厅复刻」② 不做「木石堆砌 + 民族符号」③ 不牺牲景观资源<br>硬限制：① 年均湿度 75%+ 材料限制 ② 山地运输限制 ③ HAY 气质方向<br>软性偏好：① HAY 成品家具 ② 社交媒体传播力 ③ 低饱和色彩 |
| **下游消费** | → S3 张力冻结（`confirmed_constraints` 与冲突对并列进入决策矩阵）<br>→ F8 下游专家问题生成器（专家必须说明约束合规性）<br>→ F9 创新边界授权生成器（`never_do` 列表 = 绝对不可突破边界）<br>→ S4 任务书（约束清单是任务书核心条款） |
| **VoiceSlot 状态** | pending → delivered → responded（用户确认约束分类） |
| **TriggerIntent** | `compress_boundary`（压缩可行域，建立红线/硬限制/软偏好三级边界） |
| **Reframe 依赖** | 若 D2 被否定（约束分类错误），则需重新分类，但不影响其他武器 |
| **质量门控** | G1：约束描述必须具体，不接受「尽量使用环保材料」等模糊表达<br>D2 确认后写入 `confirmed_constraints`，设为只读 |

### X4 品牌-空间转译引擎 — 武器协作链

| 项目 | 内容 |
|------|------|
| **武器 ID** | X4 |
| **武器名称** | 品牌-空间转译引擎（Brand-Space Translation Engine） |
| **执行轴** | S2 条件触发（X1 判断为"品牌参考型"时自动激活） |
| **方法轴** | 主线推进（advance_mainline）+ 驱动力修正（correct_driver，副标签） |
| **运行模式** | **参考品牌转译**（非旗舰模式）— HAY 不拥有该民宿，提取 HAY 给目标客群带来的情感体验 |
| **输入来源** | ① X1 客户端类型（`client_type_profile`）<br>② A1 项目简报（`project_brief`）<br>③ X3 意象空间参数（如有隐喻输入）<br>④ L2 品牌知识库（HAY 品牌档案） |
| **输出对象** | `brand_space_translation: {brand_name, emotional_contract, brand_user_identity, aesthetic_stance, core_space_language: {color, material, proportion, light, touch}, brand_forbidden_zone, adaptation_note}` |
| **输出示例** | 情感契约：被赋予一种轻松的审美自信<br>审美主张：功能主义的年轻版本<br>空间语言：低饱和但不无色、金属/混凝土/薄型胶合板、紧凑尺度、自然光优先、表面触感偏"干"<br>禁止区：大面积深色实木、奢侈品级材料、过度装饰 |
| **下游消费** | → B1 机构版（用 `brand_space_translation` 替代 JTBD 框架）<br>→ F3 关键洞见（洞见应基于品牌价值观转译）<br>→ X6 文化深度校验（校验品牌转译是否停在表面拼贴）<br>→ S4 设计框架（色彩/材料/尺度直接引用 X4 输出） |
| **VoiceSlot 状态** | pending → delivered → responded（用户确认品牌理解方向） |
| **TriggerIntent** | `advance_mainline`（将品牌气质转译为可操作的空间语言参数） |
| **质量门控** | G1：X4 的空间语言输出必须通过锐度门控（避免输出「提供豪华感受」之类的套话）<br>必须输出具体参数（色温 3000-3500K，而非"温暖光线"） |

### C3 用户行为模式引擎 — 武器协作链

| 项目 | 内容 |
|------|------|
| **武器 ID** | C3 |
| **武器名称** | 用户行为模式引擎（User Behavior Pattern Engine） |
| **执行轴** | S2 条件触发（relevance_score ≥ 0.55） |
| **方法轴** | 驱动力修正（correct_driver）+ 主线推进（advance_mainline，副标签） |
| **触发条件** | A1 场景复杂度 + B4 身份置信度 → 轻度度假场景 + 城市年轻客群 → 触发 |
| **输入来源** | ① A1 场景信号（`scenario_complexity`）<br>② B4 使用者身份（`identity_mode`）<br>③ L2 矩阵（`commercial_hospitality` 行为模式库）<br>④ L3 案例（福州雅诗阁客群行为、狮岭村游客行为） |
| **输出对象** | `user_behavior_priority_translation: [{behavior_pattern, space_need, design_implication}]` |
| **输出示例** | 慢醒来 → 卧室景观面 + 优质晨光<br>散步式探索 → 室内外过渡空间比室内面积更重要<br>低密度社交 → 社交梯度而非单一大厅<br>景观消费 → 窗是最重要的"家具"<br>拍照传播 → 2-3 个自然形成的画面感场景<br>夜间收缩 → 小型公共空间 |
| **下游消费** | → B1 任务定义（行为模式修正任务定义的"情境"和"动因"）<br>→ B2 冲突诊断（行为模式揭示"社交开放性 vs 度假私密性"冲突）<br>→ S4 设计框架（公共社交空间组织直接基于 C3 行为模式） |
| **VoiceSlot 状态** | pending → delivered → responded（用户确认行为模式准确） |
| **TriggerIntent** | `correct_driver`（识别真实使用行为，修正空间主线方向） |
| **质量门控** | G1：行为模式描述必须具体，不接受「用户希望舒适」等空洞表达<br>必须明确"空间需求"和"设计含义" |

### X6 文化深度校验器 — 武器协作链

| 项目 | 内容 |
|------|------|
| **武器 ID** | X6 |
| **武器名称** | 文化深度校验器（Cultural Depth Validator） |
| **执行轴** | S2 条件触发（relevance_score ≥ 0.6，文化类品牌旗舰项目） |
| **方法轴** | 横切校验（cross_validate） |
| **触发条件** | X4 品牌转译 + 跨文化嫁接（北欧功能主义 × 川西山地）→ 触发 |
| **输入来源** | ① X4 品牌转译输出（`brand_space_translation`）<br>② A1 文化信号（`cultural_keywords`）<br>③ L3 案例（跨文化嫁接失败案例库） |
| **输出对象** | `cultural_depth_validation: [{dimension, risk, conclusion}]` |
| **输出示例** | 材料真实性：需修正（金属件防潮处理）<br>色彩语境：需修正（色彩稍暖以适应绿色背景）<br>尺度感：需修正（座深和间距放松 10-15%）<br>文化嫁接：通过（嫁接点是方法论而非符号） |
| **下游消费** | → X4 品牌转译（X6 修正 X4 输出的"气候适应"部分）<br>→ S4 设计框架（色彩/材料/尺度的"气候修正"直接引用 X6 结论）<br>→ D2 约束识别（X6 发现的硬约束进入 D2 清单） |
| **VoiceSlot 状态** | pending → delivered → responded（用户确认修正方向） |
| **TriggerIntent** | `cross_validate`（检验品牌转译是否停在表面拼贴，防止主题酒店化） |
| **质量门控** | G1：校验结论必须具体，不接受「需要注意文化融合」等模糊表达<br>必须明确"需修正"或"通过"，并给出具体修正方向 |

| **输入来源** | ① B1+B2+B3 输出（S2 全部结论）<br>② L1 规则（硬约束复核）<br>③ L3 案例（前提假设失败案例库） |

| **Reframe 依赖** | 若 D1 发现前提错误且用户确认，则 D2 → invalidated，回退到 S2 |

> **关键发现**：武器不是孤立运行的"黑盒"，而是通过明确的输入输出链形成协作网络。每个武器的输出都有明确的下游消费者，形成"证据链 → 分析链 → 决策链 → 交接链"的完整流程。
