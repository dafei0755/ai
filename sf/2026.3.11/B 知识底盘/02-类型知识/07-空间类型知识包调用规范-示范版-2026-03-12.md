# 空间类型知识包调用规范（示范版 · 2026-03-12）

> 适用范围：需求分析阶段（S1~S4）  
> 目标：把“专业知识底盘”从说明文字变成可复用、可审计、可交接的调用模板。  
> 使用方式：每个新项目先复制本模板，再按项目填充。

---

## 1. 最小调用合同（必须具备）

### 1.1 输入合同
- `project_input_text`
- `session_id`
- `project_type_preliminary`（可空）
- `space_context_hint`（可空）

### 1.2 输出合同
- `type_stack`
- `ontology_bundle`
- `rule_bundle`
- `case_bundle`
- `memory_bundle`
- `trace_bundle`

### 1.3 证据字段（强制）
- `source`
- `tier`（L1/L2/L3/L4）
- `confidence`
- `version`
- `empty_reason`（空返回时必填）

## 3. 调用顺序（系统标准流程）

1. `get_project_type_context()`  
目的：确定 `type_stack` 与类型框架入口（L2）。
2. `query_rules()`  
目的：拉取 L1 红线、门禁阈值、一致性规则。
3. `retrieve_cases()`  
目的：补充 L3 成功/失败模式，校准增强武器阈值。
4. `get_project_memory()`  
目的：读取 L4 会话记忆，保障 S3/S4 一致性。
5. `compile_handoff`  
目的：将 type+rule+case+memory 编译进任务书证据索引。

---

## 4. S1~S4 挂接规则（必须按阶段）

### S1（理解输入）
- 强制挂接：`L2 + L1`
- 输出：`type_stack`、`intent_baseline`、`initial_gap_map`
- 禁止：直接用 L3 案例替代类型判断

### S2（看清重点）
- 强制挂接：`L1 + L2`
- 条件挂接：`L3`
- 输出：`space_proposition`、`conflict_pairs`、`confirmed_constraints`
- 原则：`L1` 与 `L3`冲突时，`L1` 优先

### S3（定下取舍）
- 强制挂接：`L4 + L1`
- 输出：`tradeoff_baseline`、`driver_priorities`、`freeze_summary`
- 原则：仅消费上游结果，不新增分析主线

### S4（确认任务书）
- 强制挂接：`L4 + L1/L2 证据索引`
- 条件挂接：`L3`（仅参考）
- 输出：`confirmed_design_brief` + 证据链 + 推断标注

---

## 5. 门禁标准（类型知识包专用）

### 5.1 blocker 条件
- `project_type` 与 `space_type` 未稳定
- `hard_constraints` 缺失
- `trace_bundle` 缺关键链路（TriggerIntent 或 gate_results）

### 5.2 warn 条件
- `case_bundle` 置信度偏低
- `specialty_tag` 仍存在多候选并列
- `memory_bundle` 有冲突但可解释

### 5.3 pass 条件
- type/rule/case/memory 四包齐全
- 核心字段均具备 `source/tier/confidence/version`
- S3 冻结条目可被 S4 直接编译

## 6. 本案示范（HAY × 七里坪）

### 6.1 Type Stack（示范值）
- `parent_type`: `commercial`
- `project_type`: `commercial_hospitality`
- `space_type`: `hospitality_tourism`
- `specialty_tag`: `mountain_short_stay`, `nature_immersion`, `light_holiday`
- `extracted_spatial_zones`: `arrival_buffer`, `social_lobby`, `quiet_viewing`, `guestroom_cluster`, `service_backstage`

### 6.2 Ontology Bundle（示范值）
- `type_framework_dimensions`: `guest_journey`, `place_identity`, `service_model`
- `elevated_topics`: `E3`, `E4`, `E5`
- `key_tensions`:
  1. 品牌标准化 vs 在地独特性
  2. 服务可见度 vs 空间宁静
  3. 旺季容量 vs 淡季空置

### 6.3 Rule Bundle（示范值）
- `hard_constraints`: 耐候性、眩光控制、关键视线走廊、服务动线不冲突
- `soft_constraints`: 识别触点密度、社交强度、场景切换弹性

### 6.4 Case Bundle（示范值）
- `positive_patterns`: 低饱和+模块化+分层社交
- `failure_patterns`: 高饱和视觉过载、单一大开间噪声外溢

### 6.5 Memory Bundle（示范值）
- `confirmed_decisions`: 四专题冻结条目
- `rollback_anchors`: S2 冲突框架 / S3 权重排序

---

## 7. 复用清单（落地前必过）

1. 是否完成 `type_stack` 五字段填充。  
2. 是否具备 L1/L2/L3/L4 四层证据，不以单层替代全层。  
3. 是否记录 `trigger_intent_trace` 与 `gate_results`。  
4. 是否在 S4 输出证据索引与 `[推断]` 对应来源。  
5. 是否明确回退锚点（仅回 S2 或 S3，不推翻全稿）。
