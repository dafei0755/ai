## 2. 对象总览

建议把民宿知识底盘对象命名为：

- `HomestayKnowledgeProfile`

它可以拆成八个一级分组：

1. `identity_profile`：身份识别
2. `site_context_profile`：场地语境
3. `product_experience_profile`：产品与体验
4. `operation_profile`：运营模型
5. `brand_business_profile`：品牌与商业意图
6. `evidence_feedback_profile`：案例证据与用户反馈
7. `decision_profile`：关键张力、优先级、冻结对象
8. `meta_profile`：元信息与适用范围

## 3. 字段字典

## 3.1 `identity_profile`

### `core_type`
- 类型：`string`
- 是否必填：是
- 作用：标识它属于哪类主类型知识对象
- 建议值：`homestay`

### `hospitality_subtype`
- 类型：`enum<string>`
- 是否必填：是
- 作用：标识民宿所属住宿产品基本盘
- 建议枚举：
  - `b_and_b`
  - `boutique_stay`
  - `resort_stay`
  - `retreat_lodge`
  - `glamping_stay`

### `carrier_archetype`
- 类型：`enum<string>`
- 是否必填：是
- 作用：标识主要建筑载体
- 建议枚举：
  - `old_house_renovation`
  - `village_cluster`
  - `new_resort_cluster`
  - `treehouse`
  - `stone_house`
  - `courtyard`
  - `modular_glamping`

## 3.2 `site_context_profile`

### `landscape_archetype`
- 类型：`enum<string>`
- 是否必填：是
- 作用：标识主要景观原型
- 建议枚举：
  - `mountain`
  - `coastal`
  - `riverside`
  - `lakeside`
  - `forest`
  - `farmland`
  - `plateau`
  - `snowfield`
  - `desert`
  - `canyon`

### `cultural_geography`
- 类型：`enum<string>`
- 是否必填：建议必填
- 作用：标识文化地域背景
- 建议枚举：
  - `jiangnan`
  - `lingnan`
  - `southwest_ethnic_highland`
  - `northern_frontier`
  - `central_plain`
  - `coastal_fishery_region`

## 5. 冲突与约束规则建议

## 5.1 强冲突组合

以下组合若同时出现，应触发系统提醒：

### 规则 A
- 条件：
  - `guest_segment_profile` 同时包含 `parent_child_family` 与 `healing_retreat_guest`
- 提醒：
  - 需优先区分空间分区或时间分段，否则客群冲突高

### 规则 B
- 条件：
  - `personalization_depth = deep_customized`
  - `strategic_business_intent = profit_first`
  - `price_tier_profile <= upper_midscale`
- 提醒：
  - 个性化成本可能无法被价格带覆盖

### 规则 C
- 条件：
  - `signature_selling_points` 包含 `star_gazing`
  - `social_intensity_profile = community_friendly` 或 `event_active`
- 提醒：
  - 夜间噪声可能破坏卖点兑现

### 规则 D
- 条件：
  - `brand_mode_profile = chain_boutique_brand`
  - `brand_expression_level = anonymous_local`
- 提醒：
  - 品牌一致性与匿名在地性逻辑可能冲突

## 5.2 优先级提升规则

### 规则 E
- 条件：
  - `price_tier_profile` 为 `premium_boutique` 或 `luxury_destination`
- 提升项：
  - `selling_point_delivery`
  - `service_stability`
  - `maintenance_quality`

### 规则 F
- 条件：
  - `landscape_archetype = coastal`
- 提升项：
  - `anti_corrosion`
  - `solar_protection`
  - `peak_cleaning_capacity`

### 规则 G
- 条件：
  - `experience_core` 包含 `healing_retreat`
- 提升项：
  - `acoustic_quietness`
  - `night_mep_noise_control`
  - `privacy_nodes`

## 6. YAML 草案示例

下面给出一个“山地疗愈型民宿”的 YAML 草案示例。

```yaml
HomestayKnowledgeProfile:
  identity_profile:
    core_type: homestay
    hospitality_subtype: retreat_lodge
    carrier_archetype: village_cluster

  site_context_profile:
    landscape_archetype: mountain
    cultural_geography: southwest_ethnic_highland
    climate_maintenance_profile:
      - humid_mildew_risk
      - heavy_rainfall
    site_constraints:
      - steep_arrival_path
      - limited_parking

  product_experience_profile:
    experience_core:
      - healing_retreat
      - viewing_landscape
      - silence_rest
    stay_mode:
      - short_escape
      - slow_travel
    guest_segment_profile:
      - urban_couple
      - healing_retreat_guest
    social_intensity_profile: low_pressure_shared
    style_language_profile:
      - vernacular_natural
      - minimal_warm
    material_palette_profile:
      - wood_dominant
      - stone_dominant
      - mixed_local_materials
    signature_selling_points:
      - negative_ion_forest_breathing
      - sunrise_sunset_view
      - tea_meditation
    personalization_depth: host_curated

  operation_profile:
    operation_model: owner_hosted
    service_visibility: light_touch_service
    seasonality_profile:
      - weekend_peak
      - strong_off_season
    maintenance_capacity: medium
    guest_journey_profile:
      arrival: 山路到达需要被设计成减压而非负担
      check_in: 入住应轻量、安静、不过度仪式化
      room_use: 客房应支持休息、看景、轻阅读
      public_area: 公区应鼓励停留但不强迫社交
      night_experience: 夜间灯光必须克制，避免破坏安静感
      check_out: 离店应顺畅，不制造新的疲惫

  brand_business_profile:
    price_tier_profile: premium_boutique
    brand_mode_profile: independent_host_brand
    brand_expression_level: soft_branded
    strategic_business_intent: lifestyle_expression
    revenue_structure:
      - room_revenue
      - food_beverage
      - activity_workshop
    capex_profile: medium
    opex_profile: medium
    profitability_model: 依赖房晚溢价 + 小型疗愈活动 + 在地餐食增强复购

  evidence_feedback_profile:
    failure_case_patterns:
      - 公区过大导致淡季空置与维护压力过高
      - 卖疗愈但夜间机电噪音破坏体验
    success_experience_patterns:
      - 停留节点丰富但总公区规模克制
      - 景观与安静体验一致兑现
    review_signal_clusters:
      high_frequency_praises:
        - 安静
        - 空气好
        - 风景真实
      high_frequency_complaints:
        - 潮
        - 路难走
        - 餐食弱
      selling_point_validation:
        - 森林呼吸感能被真实感知
    experience_pain_points:
      - 雨季潮湿
      - 冬季夜间保暖不足
    experience_delight_points:
      - 发呆停留感
      - 山景层次感
      - 安静睡眠体验

  decision_profile:
    key_tensions:
      - landscape_openness_vs_privacy
      - personalization_vs_operational_efficiency
      - quiet_healing_vs_weekend_peak_capacity
    recommended_focus:
      - 借景结构
      - 安静度
      - 夜间照明策略
      - 防潮维护边界
    risk_flags:
      - strong_off_season_pressure
      - humidity_maintenance_risk
      - food_experience_weakness
    freeze_template:
      - 公区社交压力等级
      - 借景与停留层级
      - 夜间光与噪音控制策略
      - 材料与防潮维护边界
      - 卖点兑现方式

  meta_profile:
    version: v0.1-draft
    source_mode: mixed_curated_and_feedback
    confidence_level: medium
    applicable_stage:
      - requirements_analysis
      - review
      - handoff
```

## 7. 如何落到系统里

如果后续要真正落地，这份草案可以继续演化成三种形式：

### 7.1 YAML 配置库
- 适合人工维护、知识工程与版本管理

### 7.2 JSON Schema / Pydantic Model
- 适合运行时校验、接口交换与前后端联动

### 7.3 Mixed Mode
- 枚举和规则由代码约束
- 经验字段和案例字段由 YAML / 数据库承载

这是比较现实的路径：

- 稳定字段 → 代码约束
- 易演化知识 → 配置与数据承载
