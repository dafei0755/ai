# 05-知识底盘详细画像：多学科与一主两辅耦合（2026-03-12）

> 文档定位：在既有 `01~04` 基础上，给出“知识底盘到底是什么、怎么工作、怎么扩展”的系统画像。  
> 核心问题：多学科如何有效支撑并转译到一主两辅，而不是停留在灵感层。  
> 一句话：**知识底盘是决策供给系统，不是决策主系统。**

---

## 一、地位与边界（先定权责）

### 1.1 系统地位

1. 决策主系统：`一主两辅`（空间命题主线 + 驱动力修正 + 边界压缩）  
2. 供给系统：`知识底盘`（规则、矩阵、经验、记忆 + 跨学科桥接）  
3. 编译系统：`S4 compile_handoff`（任务书定版与交接）

结论：
- 知识底盘负责“给证据、给变量、给候选动作”。
- 一主两辅负责“定方向、做取舍、冻结基线”。

### 1.2 三条硬边界

1. 底盘不直接替代流程裁决。  
2. 类比/意象/跨学科启发不能覆盖 L1 硬约束。  
3. 未验证结论不能直接进入冻结基线，必须标 `[推断]`。

---

## 二、知识底盘完整剖面

## 2.1 静态结构（知识形态）

### L1 规则层（Hard Rules）
- 内容：法规、规范、红线、门禁阈值、一致性规则。  
- 特征：低频更新、强约束、可追溯版本。  
- 权力：否决权（blocker）。

### L2 矩阵层（Type-Mode Matrix）
- 内容：类型/标签/模式/冲突模板/推荐武器/TriggerIntent 启动建议。  
- 特征：中频更新、结构化路由、单一事实源。  
- 作用：让“同类问题”可复用。

### L3 经验层（Case & Pattern）
- 内容：成功体会、失败案例、边界样本、用户评价模式。  
- 特征：高频更新、软证据、可检索。  
- 作用：校准策略强度与风险。

### L4 项目记忆层（Project Memory）
- 内容：会话内冻结条目、回退锚点、重排轨迹。  
- 特征：强隔离、随项目演化。  
- 作用：保证 S3/S4 一致性，不污染行业知识。

### L2.5 跨域桥接层（Bridge Layer，新增画像）
- 内容：文学/哲学/艺术/电影/奢侈品/社会学/人类学/世代等跨域信号的转译对象。  
- 形态：`bridge_packet` + 跨域词典 + 转译规则。  
- 作用：把“跨学科启发”变成“可执行候选动作”。

---

## 2.2 动态机制（运行态）

### 输入
- 项目输入（空间、业务、人群、约束）
- 人物画像（量化因子）
- 跨域信号（文本、意象、风格、品牌语法）

### 处理中枢
- `KnowledgeRegistry`：统一接入、统一返回结构。  
- 返回字段必须包含：`source / tier / confidence / version / empty_reason`。

### 输出
- 给 S1：类型与初始边界供料
- 给 S2：冲突模板、驱动力变量、跨域候选动作
- 给 S3：取舍排序与风险校验供料
- 给 S4：证据索引与可追溯编译对象

---

## 三、与一主两辅的耦合关系（核心）

### 3.1 一主（空间命题主线）吃什么
- 优先供给：L2 类型矩阵 + L2.5 跨域叙事转译 + L3 经验样本  
- 典型学科来源：文学、艺术、电影、奢侈品语法  
- 产物：空间命题、叙事序列、尺度与氛围策略

### 3.2 辅轴1（驱动力修正）吃什么
- 优先供给：人物量化向量 + 社会学/人类学/世代变量 + L3 用户评价模式  
- 典型学科来源：心理学、社会学、人类学、世代研究  
- 产物：人群权重、冲突裁决、社交组织策略

### 3.3 辅轴2（边界压缩）吃什么
- 优先供给：L1 规则 + 经营指标 + feasibility 结果  
- 典型学科来源：商业、运营、工程、法规  
- 产物：可行域压缩、红线、让位项、回退触发条件

## 四、多学科转译方法论（可扩展，不靠手工穷举）

## 4.1 统一“中间语”（必须）

所有跨学科输入先转为：

`源信号 -> 语义意图 -> 空间动作 -> 风险标记 -> 证据等级`

证据等级：
- `hard_rule`
- `analogy`
- `creative_hint`

## 4.2 预加工策略（小人工 + 大自动）

### 人工定标（小样本）
- 建高质量种子词典/模板（如 100~300 条）
- 定义转译边界和质量标准

### 自动扩展（规模化）
- 向量检索召回相似信号
- 模板迁移生成候选映射
- 弱监督打标与评分
- LLM 仅生成候选，不直接入基线

## 4.3 双评分器（过滤噪声）

1. 语义一致性分：源信号与转译动作是否同义。  
2. 可执行性分：能否落到尺度/动线/材质/光/运营。  

低分策略：
- 降级为 `creative_hint`
- 或直接丢弃

## 五、人物维度如何进入底盘

人物是“一主两辅”核心之一，必须量化进入底盘：

- 使用 `Person-Design Vector (PDV)`（0-5 分）
- 输出 6 大策略簇分值（叙事、秩序、社交、恢复、材质、运营）
- 将分值写入 L4 项目记忆与 S3 冻结依据

最关键规则：
- 人物高叙事分不能直接压过运营红线
- 若 `narrative高 + operations低`，强制触发 `cross_validate`

---

## 六、业务与体验闭环（必须可经营）

知识底盘不是美学仓库，必须携带经营与体验数据：

### 经营面
- `investment_profile`（capex/opex/回收期）
- `profitability_profile`（ADR/入住率/毛利）

### 体验面
- `user_experience_targets`（到达/睡眠/社交/维护感知）
- `user_review_focus`（评论焦点词）

闭环机制：
- 成功策略回写 L3
- 失败样本同样回写 L3（反例优先级高）

---

## 七、门禁与治理（防“高概念失控”）

### 7.1 门禁
- pass：可继续
- warn：可继续但必须风险留痕
- blocker：必须回退修正

### 7.2 治理规则
1. L1/L2 变更走审核发布，不可运行时直写。  
2. L3 可自动增量摄入，但需可回滚。  
3. L4 与 L1/L2/L3 物理隔离，禁止混写。  
4. 所有输出必须可追溯到 `source/tier/version`。

---

## 八、可观测指标（衡量底盘是否“真有用”）

### 8.1 决策质量
- 冻结后回退率
- 冲突解算成功率
- blocker 命中准确率

### 8.2 经营表现
- ADR 与入住率偏差
- 维护成本偏差
- 回收期预测误差

### 8.3 用户表现
- 睡眠/安静/到达体验评分
- 评论关键词正负比
- 复购率/NPS

### 8.4 知识表现
- 词典命中有效率
- 候选转译采纳率
- 反例回写覆盖率

---

## 九、实施路线（建议）

### Phase A：结构冻结
- 冻结底盘分层与接口字段合同
- 冻结证据等级与门禁规则

### Phase B：桥接接入
- 接入跨域桥接层（L2.5）
- 启用词典与 `bridge_packet` 对象

### Phase C：人物量化接入
- 接入人物评分问卷与计算器
- 将人物分值写入 S2/S3 调度

### Phase D：闭环优化
- 跑 2-3 个灰度项目
- 回写成功/失败样本
- 校准评分器与路由阈值

---

## 十、最终画像（摘要）

知识底盘的成熟形态不是“资料库”，而是：

1. 有层级（L1~L4 + L2.5）  
2. 有合同（统一字段与证据等级）  
3. 有算力（评分、路由、门禁）  
4. 有闭环（结果回写与迭代）  

它服务一主两辅，但不取代一主两辅。  
它把多学科变成可执行决策供给，而不是装饰性知识堆叠。
