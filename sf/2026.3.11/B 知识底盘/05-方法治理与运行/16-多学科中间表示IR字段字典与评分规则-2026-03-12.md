# 多学科中间表示 IR 字段字典与评分规则（2026-03-12）

> 目的：承接 `15-多学科预加工与可扩展转译方法-2026-03-12.md`，把“中间表示”从方法论进一步压成一份可落库、可评分、可投影、可冻结的正式协议草案。  
> 核心结论：**多学科要想稳定进入一主两辅，必须先拥有统一 IR（Intermediate Representation）结构；否则桥接词典、案例解释、项目冻结之间永远无法形成可计算闭环。**

---

## 1. 为什么还需要一层 IR 协议

目前体系里其实已经有两样非常重要的东西：

- `10-跨域知识桥接层-设计草案-v2-2026-03-12.md`：定义了 `bridge_packet`
- `11-跨域桥接词典初始库-100条-2026-03-12.md`：提供了标准化桥接词条

但这两者之间还缺一层真正能“算”的结构：

- 词条命中后，如何变成统一语义向量？
- 不同学科的输出，如何进入同一评价坐标？
- 如何判断它更影响一主、驱动力轴还是边界轴？
- 如何给冻结资格一个更稳定的量化辅助？

这就是 IR 层的任务。

一句话说透：

> **bridge_packet 解决“怎么装包”，词典解决“怎么触发”，IR 协议解决“怎么统一计算”。**

---

## 2. IR 在整体架构中的位置

建议把结构明确成：

$$
Raw\ Sources \rightarrow Bridge\ Terms \rightarrow IR\ Encoding \rightarrow Projection\ to\ 一主两辅 \rightarrow Freeze\ Qualification
$$

其中：

- **Raw Sources**：诗歌、电影、哲学文本、人物、评论、访谈
- **Bridge Terms**：桥接词典命中的语义触发器
- **IR Encoding**：统一的中间表示
- **Projection**：映射到一主 / 驱动力轴 / 边界轴
- **Freeze Qualification**：进入 A/B/C 冻结级别

IR 这一层的最大作用，是让不同来源的知识不再“各说各话”。

---

## 3. IR 的设计原则

设计 IR 时建议坚持四个原则：

### 3.1 跨学科同构

不管输入来自文学、电影、宗教、心理学还是人物研究，最后都应该能映射到同一套字段。

### 3.2 可投影

每个字段都必须有机会影响：

- 一主
- 驱动力轴
- 边界轴

否则这个字段只是描述信息，不是系统信息。

### 3.3 可冻结

IR 不能只描述“感觉”；它必须能进一步生成：

- 主命题候选
- 驱动力解释
- 边界提醒
- 审阅提示
- 风险项

### 3.4 可回退

任何字段如果被证明误判，都必须能追溯到来源并回退，不得形成无法解释的黑箱结论。

---

## 4. IR 顶层对象模型（建议）

建议把每条跨学科输入最终编码成一个 `ir_packet`。

```yaml
ir_packet:
  ir_id: string
  source_refs: []
  source_domains: []
  evidence_tier: hard_rule|stable_pattern|analogy|creative_hint
  confidence: 0.0-1.0
  semantic_axes: {}
  projection_scores: {}
  freeze_candidates: {}
  risk_flags: []
  validation_hooks: []
  trace:
    bridge_terms: []
    extraction_method: rule|embedding|llm|hybrid
    reviewer: optional
```

这里最重要的三个区块是：

- `semantic_axes`
- `projection_scores`
- `freeze_candidates`

## 5. semantic_axes：建议统一成 8 大语义轴

为了让不同来源的材料最后都能比较，建议先统一成 8 个语义轴。

### 5.1 emotion_axis（情绪轴）

描述空间希望引发或避免的情绪气候。

建议子字段：

- `calm`
- `intimacy`
- `solemnity`
- `vitality`
- `tension`
- `playfulness`
- `restoration`
- `mystery`

### 5.2 relation_axis（关系轴）

描述人与人之间、人与环境之间的关系结构。

建议子字段：

- `solitude`
- `companionship`
- `collective_presence`
- `social_optionality`
- `gaze_exposure`
- `boundary_need`

### 5.3 behavior_axis（行为轴）

描述被鼓励的动作和停留方式。

建议子字段：

- `linger`
- `pass_through`
- `gather`
- `ritual_action`
- `explore`
- `rest`
- `work`
- `observe`

### 5.4 body_axis（身体轴）

描述身体状态与感官阈值。

建议子字段：

- `stimulation`
- `comfort`
- `enclosure`
- `openness`
- `touch_sensitivity`
- `mobility_support`
- `acoustic_protection`
- `thermal_tolerance`

### 5.5 time_axis（时间轴）

描述时间节奏与序列组织。

建议子字段：

- `slow_rhythm`
- `ceremonial_peak`
- `cyclical_repeat`
- `transition_density`
- `arrival_emphasis`
- `departure_emphasis`

### 5.6 aesthetic_axis（审美轴）

描述形式与风格倾向。

建议子字段：

- `plainness`
- `ornamentation`
- `material_authenticity`
- `theatricality`
- `precision`
- `roughness`
- `warmth`
- `coolness`

### 5.7 order_axis（秩序轴）

描述组织方式与空间纪律。

建议子字段：

- `symmetry`
- `porosity`
- `centrality`
- `layering`
- `legibility`
- `flexibility`

### 5.8 meaning_axis（意义轴）

描述价值观、文化观、精神性与场所观。

建议子字段：

- `dwelling`
- `locality`
- `sacredness`
- `identity_expression`
- `status_signal`
- `daily_life_priority`
- `memory_density`

这 8 轴并不完美，但已经足够构成一个可用的通用坐标系。

## 6. IR 字段字典：建议分成 6 组必填字段

### 6.1 来源组（source group）

| 字段 | 类型 | 说明 |
|---|---|---|
| `ir_id` | string | IR 唯一编号 |
| `source_refs` | list | 原文、案例、评论或访谈引用 |
| `source_domains` | list | literature / film / psychology / religion ... |
| `source_time_context` | string | 来源时代/语境 |
| `evidence_tier` | enum | hard_rule / stable_pattern / analogy / creative_hint |
| `confidence` | float | 当前可信度 |

### 6.2 语义组（semantic group）

所有 `semantic_axes.*` 字段统一用 $0 \sim 1$ 评分。

例如：

- `emotion_axis.calm = 0.82`
- `behavior_axis.linger = 0.77`
- `aesthetic_axis.theatricality = 0.15`

### 6.3 投影组（projection group）

| 字段 | 类型 | 说明 |
|---|---|---|
| `projection_scores.mainline_score` | float | 对一主的影响强度 |
| `projection_scores.driver_score` | float | 对驱动力轴的解释强度 |
| `projection_scores.boundary_score` | float | 对边界轴的修正强度 |
| `projection_scores.stage_fit_s1` | float | 更适合在 S1 进入的程度 |
| `projection_scores.stage_fit_s2` | float | 更适合在 S2 进入的程度 |
| `projection_scores.stage_fit_s3` | float | 更适合在 S3 审查的程度 |
| `projection_scores.stage_fit_s4` | float | 更适合在 S4 编译的程度 |

### 6.4 冻结组（freeze group）

| 字段 | 类型 | 说明 |
|---|---|---|
| `freeze_candidates.mainline_statement` | string | 可冻结的一主表述候选 |
| `freeze_candidates.driver_statement` | string | 可冻结的驱动力解释候选 |
| `freeze_candidates.boundary_statement` | string | 可冻结的边界提醒候选 |
| `freeze_candidates.review_tip` | string | 审阅提示 |
| `freeze_candidates.freeze_level` | enum | A / B / C |

### 6.5 风险组（risk group）

| 字段 | 类型 | 说明 |
|---|---|---|
| `risk_flags` | list | 风险标签列表 |
| `misread_risk` | float | 文化/语义误读风险 |
| `execution_risk` | float | 落地执行风险 |
| `maintenance_risk` | float | 维护运营风险 |
| `ethics_risk` | float | 伦理与边界风险 |

### 6.6 追溯组（trace group）

| 字段 | 类型 | 说明 |
|---|---|---|
| `trace.bridge_terms` | list | 命中的桥接词条 |
| `trace.extraction_method` | enum | rule / embedding / llm / hybrid |
| `trace.reviewer` | string | 审阅人 |
| `trace.notes` | string | 关键说明 |

## 7. 怎么打分：建议采用“轴内评分 + 投影评分”两段式

### 7.1 第一段：轴内评分

先不直接讨论一主两辅，而是先判断该材料在各语义轴上的强弱。  
评分范围统一为：

$$
score \in [0,1]
$$

建议解释如下：

- $0.00 \sim 0.19$：基本不存在
- $0.20 \sim 0.39$：弱存在
- $0.40 \sim 0.59$：中等存在
- $0.60 \sim 0.79$：强存在
- $0.80 \sim 1.00$：核心特征

### 7.2 第二段：投影评分

在语义轴打分后，再映射成三类投影分数：

- `mainline_score`
- `driver_score`
- `boundary_score`

建议使用加权方式：

$$
mainline\_score = \sum (semantic\_axis_i \times w_i)
$$

$$
driver\_score = \sum (semantic\_axis_i \times d_i)
$$

$$
boundary\_score = \sum (semantic\_axis_i \times b_i)
$$

权重 $w_i, d_i, b_i$ 并不是固定 universal 常数，而应该按空间类型微调。

例如：

- 民宿项目里，`emotion_axis + behavior_axis + time_axis` 对 `mainline_score` 权重更高；
- 医疗/康养项目里，`body_axis + boundary_risk` 对 `boundary_score` 权重更高；
- 奢侈酒店项目里，`aesthetic_axis + meaning_axis.status_signal` 对 `driver_score` 权重更高。

## 8. 从 IR 到一主两辅：推荐 3 条投影规则

### 8.1 投到一主的规则

当以下条件满足时，优先影响一主：

- `mainline_score >= 0.68`
- `emotion_axis`、`behavior_axis`、`meaning_axis` 至少两个高于 0.60
- 可生成稳定的 `mainline_statement`

典型结果：

- “生活性优先于打卡性”
- “恢复性优先于戏剧性”
- “克制陪伴优先于强展示”

### 8.2 投到驱动力轴的规则

当以下条件满足时，优先影响驱动力轴：

- `driver_score >= 0.60`
- `meaning_axis.identity_expression` 或 `aesthetic_axis` 或 `relation_axis` 有明显高分
- 能解释“为什么有人会偏好这个空间方向”

典型结果：

- 品牌需要更低调但更精准的身份表达
- 客群偏好弱打扰、可社交但不强迫的共处方式

### 8.3 投到边界轴的规则

当以下条件满足时，优先影响边界轴：

- `boundary_score >= 0.55`
- 任一风险分值高于 0.50
- 能生成明确的“不能做什么”表述

典型结果：

- 不得用高反差戏剧照明破坏睡眠恢复
- 不得把宗教元素符号化装饰处理
- 不得让在地叙事覆盖真实运营与维护边界

## 9. 从 IR 到冻结资格：建议增加一个辅助判定公式

虽然冻结最终仍需人工审阅，但可以增加一层量化辅助：

$$
freeze\_index = 0.35 \times projection\_fit + 0.25 \times evidence\_strength + 0.20 \times executability + 0.20 \times (1 - risk\_penalty)
$$

其中：

- `projection_fit`：是否清楚地挂到一主/驱动力/边界之一
- `evidence_strength`：来源级别是否足够稳定
- `executability`：是否能写成可执行条目
- `risk_penalty`：误读、执行、维护、伦理风险综合惩罚

建议分段：

- $freeze\_index \ge 0.75$ → 倾向 A 级
- $0.50 \le freeze\_index < 0.75$ → 倾向 B 级
- $freeze\_index < 0.50$ → 倾向 C 级

这不是替代人工，而是把“为什么这条只是灵感而不是冻结项”说得更清楚。

## 10. 示例：把一首诗编码成 IR

以“明月松间照，清泉石上流”为例，不直接说“适合禅意空间”，而是先编码：

```yaml

  source_domains:
    - literature
  evidence_tier: analogy
  confidence: 0.74

  semantic_axes:
    emotion_axis:
      calm: 0.86
      mystery: 0.52
      vitality: 0.31
    relation_axis:
      solitude: 0.68
      companionship: 0.22
      social_optionality: 0.55
    behavior_axis:
      linger: 0.72
      observe: 0.81
      gather: 0.18
    body_axis:
      stimulation: 0.20
      comfort: 0.64
      acoustic_protection: 0.58
    time_axis:
      slow_rhythm: 0.84
      ceremonial_peak: 0.20
      arrival_emphasis: 0.43
    aesthetic_axis:
      plainness: 0.79
      material_authenticity: 0.69
      theatricality: 0.14
      coolness: 0.63
    order_axis:
      porosity: 0.74
      layering: 0.57
      legibility: 0.61
    meaning_axis:
      dwelling: 0.58
      locality: 0.44
      daily_life_priority: 0.66
      memory_density: 0.49

  projection_scores:
    mainline_score: 0.73
    driver_score: 0.46
    boundary_score: 0.57
    stage_fit_s1: 0.71
    stage_fit_s2: 0.82
    stage_fit_s3: 0.63
    stage_fit_s4: 0.48

  freeze_candidates:
    mainline_statement: "以低刺激、缓节奏、可停留的自然陪伴感作为核心体验"
    driver_statement: "目标客群偏好低显性、非强打卡式的审美认同"
    boundary_statement: "避免高反差灯光、过强装饰与高密度社交组织"
    review_tip: "可用于山地民宿、茶空间、康养休憩空间，但不宜直接复制为高活力公共商业语法"

  risk_flags:
    - over_symbolization
    - overcooling

    bridge_terms: [月下, 松风, 留白]
    extraction_method: hybrid
```

注意：这里的价值不在“解释得很诗”，而在于它终于能被别的项目重复调用。

## 11. IR 与 bridge_packet 的关系：谁先谁后

建议顺序如下：

1. 原始材料先命中桥接词条  
2. 桥接词条形成 `bridge_packet` 草案  
3. `bridge_packet` 再被编码为 `ir_packet`  
4. `ir_packet` 参与项目投影与冻结评估

也就是说：

- `bridge_packet` 更像“中间运输箱”
- `ir_packet` 更像“统一结算货币”

前者负责承接多样性，后者负责建立可计算性。

## 12. 实施建议：先做窄，再做宽

如果马上全面铺开，系统很容易过重。  
建议按三步推进：

### 第一步：先固定 20~30 个高频字段

不要一开始就做 200 个字段。  
先从最稳定的开始，例如：

- calm / intimacy / linger / rest / slow_rhythm / plainness / theatricality / boundary_need

### 第二步：先在 2~3 个空间类型试跑

优先选：

- 民宿
- 精品酒店
- 康养/疗愈空间

因为这些类型对情绪、行为、时间、身体反应最明显。

### 第三步：用项目反馈反修权重

真正的权重，不应该只靠理论拍脑袋。  
应通过项目反馈修正：

- 评论关键词
- 睡眠/安静评分
- 社交舒适评分
- 复购率
- 维护偏差

这样 IR 就会逐渐从“概念结构”变成“经验结构”。

## 13. 最后的判断

把这篇文档收成一句最关键的话：

> **多学科能否规模化进入一主两辅，不取决于你写了多少漂亮解释，而取决于你是否建立了一套统一 IR，让桥接词典、案例经验、项目投影和冻结规则进入同一计算框架。**

如果进一步压缩成一句工程化表述：

> **没有 IR，多学科只能被“理解”；有了 IR，多学科才可能被“计算、比较、投影与冻结”。**

---

## 14. 可直接接入现有体系的新增规则

建议在现有体系上追加四条规则：

1. **任何跨学科输入进入 S2 前，优先生成 `ir_packet` 草案。**  
2. **任何拟进入 S3/S4 的跨学科输入，必须至少具备 `projection_scores + freeze_candidates`。**  
3. **任何 A 级冻结条目，必须保留 `trace.bridge_terms + source_refs`。**  
4. **任何高风险高分条目，必须经过反例校验后才能升入任务书。**

一句收尾：

> **15 解决了“该不该预加工”，16 解决的是“预加工之后到底长成什么结构，才能真正参与系统判断”。**
