# 体验命题词表与底盘结构模板（2026-03-12）

> 目的：承接 `21-感觉与非理性的项目转译路径-2026-03-12.md`，把“体验命题”从概念进一步压成知识底盘中的正式对象，明确它在底盘里到底该长成什么样、存什么字段、如何治理。  
> 核心结论：**知识底盘不应直接保存空泛的“感觉”，而应保存被命题化、可投影、可追溯、可带禁忌的体验命题对象。体验命题不是灵感笔记，而是跨学科高级感觉进入系统后的第一类正式中层资源。**

---

## 1. 底盘为什么要单独存“体验命题”

如果底盘里只有：

- 原始材料
- 桥接词
- IR 字段
- 类型条目

系统仍然缺一层最贴近人的判断语言。

原因是：

- 原始材料太散，太依赖阅读能力；
- 桥接词太短，只能触发，不能裁决；
- IR 太结构化，适合计算，不适合直接承接感觉；
- 类型条目更偏业态和空间类型，不够细腻。

所以必须增加一类中层对象，用来保存：

- 已经被提炼出的体验气候
- 已经被项目化的感觉判断
- 已经被验证过的高级表达路径

这一类对象就是：`experience_proposition`。

---

## 2. 体验命题在底盘中的位置

建议把它放在下面这条链的中部：

$$
Raw\ Sources \rightarrow Bridge\ Terms \rightarrow Experience\ Proposition \rightarrow IR\ Profiles \rightarrow Projection\ Templates \rightarrow Freeze\ Rules
$$

对应关系可以理解为：

- `Raw Sources`：诗、电影、哲学、人物、宗教、音乐
- `Bridge Terms`：松风、转场、栖居、静默、节制
- `Experience Proposition`：低刺激的陪伴感、克制而不冷的尊贵感
- `IR Profiles`：体验命题对应的 8 轴语义倾向
- `Projection Templates`：它更容易进入一主、体验组织还是边界
- `Freeze Rules`：什么条件下可进入任务书

一句话说透：

> **桥接词负责点亮感觉，体验命题负责保存感觉，IR 负责计算感觉。**

---

## 3. 体验命题对象模型（建议）

建议每条体验命题在底盘中用统一对象保存。

```yaml
experience_proposition:
  xp_id: string
  name: string
  category: climate|relation|rhythm|value
  summary: string
  source_domains: [string]
  typical_bridge_terms: [string]
  mainline_effect: string
  experience_effect: [string]
  taboo_lines: [string]
  ir_tendency:
    emotion_axis: {}
    relation_axis: {}
    behavior_axis: {}
    body_axis: {}
    time_axis: {}
    aesthetic_axis: {}
    order_axis: {}
    meaning_axis: {}
  preferred_projection:
    primary: mainline|driver|boundary
    secondary: mainline|driver|boundary
  suitable_space_types: [string]
  common_misuse: [string]
  evidence_tier: stable_pattern|analogy|creative_hint
  maturity_level: 1-5
  validation_cases: [string]
  status: raw_candidate|structured_candidate|review_pending|sandbox_only|gray_release|stable_release|restricted_release|deprecated
```

## 4. 必填字段怎么理解

### 4.1 `name`

命题名称必须是项目化判断，不宜只是学科词。

建议：

- 用“感觉 + 关系/价值指向”的形式命名

例如：

- 低刺激的陪伴感
- 有边界的亲密
- 克制而不冷的尊贵感
- 慢节奏的恢复性

不建议：

- 王维感
- 电影感
- 哲学感
- 高级感

因为这些都太泛。

### 4.2 `summary`

用一两句话说明这条体验命题到底在描述什么感受状态。

### 4.3 `mainline_effect`

说明它进入一主后会如何拔高主命题。

### 4.4 `experience_effect`

说明它常对应哪些体验组织倾向，例如：

- 光感
- 动线
- 社交密度
- 材料触感
- 节点节奏
- 声环境

### 4.5 `taboo_lines`

这是体验命题和普通知识条目最大的区别之一。  
必须显式保存“做俗、做浅、做错”的常见方式。

### 4.6 `ir_tendency`

不要求每条都精确打分，但至少要保存相对倾向，说明它通常会拉高或压低哪些语义轴。

### 4.7 `preferred_projection`

用来告诉系统：

- 这类体验命题更适合先进一主
- 还是更适合先进边界
- 还是先进入驱动力解释

## 5. 体验命题的四类基础词表

建议底盘先按 4 类建立初始词表。

### 5.1 气候型

适合保存整体感受气候。

初始词表示例：

- 低刺激的陪伴感
- 清透而可呼吸的安静
- 克制而不冷的尊贵感
- 温暖可达的归属感
- 带有轻微神圣感的肃静

### 5.2 关系型

适合保存人与人、人与空间的关系方式。

初始词表示例：

- 有边界的亲密
- 可进入也可退出的社交
- 被尊重的独处
- 弱连接式陪伴
- 被温和接纳的公共性

### 5.3 节奏型

适合保存时间与序列感。

初始词表示例：

- 渐入式抵达
- 峰值后缓慢收束
- 有停顿的章节感
- 回旋式重逢
- 日常节律优先于高潮堆叠

### 5.4 价值型

适合保存项目的精神立场。

初始词表示例：

- 日常性高于表演性
- 身体舒适高于视觉纪念性
- 真实高于装饰
- 内在秩序高于外部符号
- 被照护感高于被震撼感

## 6. 三条典型结构模板

为了让底盘中每条体验命题都可直接调用，建议统一保存三种文本模板。

### 6.1 主命题模板

格式：

- “空间应服务……，而不是……”

例如：

- 空间应服务恢复性停留，而不是景观消费

### 6.2 体验组织模板

格式：

- “通过……、……、……来实现”

例如：

- 通过低刺激光感、可停留节点、声环境过滤来实现

### 6.3 禁忌模板

格式：

- “禁止把……做成……”

例如：

- 禁止把克制做成冷硬
- 禁止把诗意做成布景

## 7. 示例条目

### 7.1 低刺激的陪伴感

```yaml
experience_proposition:
  xp_id: xp_climate_001
  name: 低刺激的陪伴感
  category: climate
  summary: 在安静、低压、可停留的环境中，让人感到被温和承托，而不是被过度刺激或强行社交。
  source_domains: [literature, psychology, philosophy]
  typical_bridge_terms: [松风, 月下, 静默, 恢复性, 栖居]
  mainline_effect: 空间应服务恢复性停留，而不是高强度景观消费或社交表演。
  experience_effect:
    - 低反差光感
    - 可停留节点优先
    - 弱连接社交
    - 声环境过滤
    - 真实触感材料
  taboo_lines:
    - 禁止把安静做成压抑
    - 禁止把诗意做成布景
    - 禁止用高刺激节点破坏恢复性
  ir_tendency:
    emotion_axis: { calm: high, restoration: high, tension: low }
    relation_axis: { companionship: medium, social_optionality: high }
    behavior_axis: { linger: high, rest: high, gather: low }
    time_axis: { slow_rhythm: high }
    meaning_axis: { daily_life_priority: high, dwelling: medium_high }
  preferred_projection:
    primary: mainline
    secondary: boundary
  suitable_space_types: [mountain_homestay, retreat_hotel, tea_space]
  common_misuse:
    - 过度留白导致空洞
    - 把低刺激误作低识别
  evidence_tier: stable_pattern
  maturity_level: 3
  validation_cases: [mountain_homestay_case_01]
  status: gray_release
```

### 7.2 克制而不冷的尊贵感

适合：

- 高端酒店
- 精品度假
- 轻奢会所

典型风险：

- 把“克制”做成冷硬
- 把“尊贵”做成价格炫耀
- 把“安静”做成空与疏离

### 7.3 有边界的亲密

适合：

- 茶空间
- 文化会所
- 高净值接待空间

典型风险：

- 社交距离失控
- 私密不足
- 把“亲密”做成压迫性近距离

## 8. 入库与治理建议

体验命题不应像普通桥接词一样轻量，也不应像规则条目一样极硬。  
建议采用中等治理强度。

### 8.1 入库最小门槛

至少满足：

1. 有明确来源域
2. 有至少 3 个桥接词可支持
3. 有清楚的主命题效应
4. 有至少 3 条体验组织倾向
5. 有至少 2 条禁忌句

### 8.2 升级条件

从 `gray_release` 升到 `stable_release` 建议至少满足：

- 被 3 个以上项目有效调用
- 没有出现重大误用
- IR 映射趋于稳定
- 禁忌句能有效拦截常见误判

### 8.3 降级条件

- 经常被误解
- 在多个项目中失效
- 与类型知识或边界规则持续冲突

---

## 9. 与其他条目的边界

### 9.1 它不是桥接词

桥接词更小，更像触发器。  
体验命题更完整，更像中层判断。

### 9.2 它不是 IR

IR 更适合计算。  
体验命题更适合承接人类判断语言。

### 9.3 它不是案例

案例记录一次演算。  
体验命题保存可复用的感觉结构。

### 9.4 它不是任务书条目

任务书条目是最终编译结果。  
体验命题是通向任务书之前的中层资源。

---

## 10. 最后的判断

如果知识底盘想真正保存跨学科里的高级感觉，它就不能只存原文、桥接词和规则。  
还必须保存一类更接近大师判断语言的对象。

这类对象就是：

> **被命题化、可投影、可禁忌、可治理的体验命题。**

一句话总结：

> **知识底盘里真正该存的，不是“感觉本身”，而是感觉被系统化之后的可调用形态。体验命题就是这种形态。**
