# 知识底盘与需求分析阶段大模型的关系（2026-03-13）

> 目的：梳理知识底盘、大模型、一主两辅、多学科四者之间的关系，确立方法论同频原则。
> 核心结论：**一主两辅定规则，底盘存弹药，大模型当枪手，多学科供养分。四者方法论同频，合则无缝衔接，分则各自独立运行。底盘为应用而生，应用反哺底盘进化。**

---

## 一、四角关系总图

```
一主两辅（总组织法则 / 裁判）
    ↓ 约束所有产出的格式和质量标准
大模型（执行引擎）←→ 知识底盘（认知供给）
    ↑ 增益
多学科（高阶素材源）
```

这不是"大模型 vs 底盘"的二元关系，而是四个角色各司其职。

---

## 二、四个角色各自的本质

### 大模型：活水

- 无穷的跨学科知识和推理能力
- 不需要底盘也能工作
- 但随机性强、不稳定、容易跑偏
- 本质：生生不息，无边无际，但需要约束

### 知识底盘：水库

- 经过验证的、结构化的、可控的知识
- 是示范、样板、预加工、预制菜
- 有了更快、更稳、可靠可控
- 但内容有限、覆盖面有限、有固化风险
- 本质：少而精，稳而准

### 一主两辅：河道

- 不生产知识，也不执行转译
- 定义推进主线（空间命题）、修正轴（驱动力）、压缩轴（实施边界）
- 定义冻结标准（什么能进任务书）
- 不管知识从哪来，最终都要经过一主两辅的裁决
- 本质：组织、约束、裁决

### 多学科：养分

- 文学、哲学、艺术、建筑经典、电影、音乐、宗教、人类学...
- 不直接进入项目，必须经过转译
- 两条进入路径：通过底盘预制 / 通过大模型实时调用
- 本质：让项目从"做对"升级为"做深"

## 三、核心原则：方法论同频

### 3.1 什么叫同频

底盘入库和大模型运行时，用的是同一套方法论。具体包括：

**同一套转译协议（五步法）：**

```
底盘入库时：
  素材 → Step1感觉核心 → Step2空间机制 → Step3命题 → Step4挂接 → Step5验证

需求分析运行时（无底盘时）：
  业主表达 → Step1感觉核心 → Step2空间机制 → Step3命题 → Step4挂接 → Step5验证
```

完全相同的步骤，完全相同的产出格式。

**同一套命题格式：**

> 在[空间/时刻]，[谁]应该能[做到什么]，同时[不会发生什么]

分级都是 A/B/C，挂接都是一主两辅。

**同一套质量标准：**

- 可验证性：能不能在建成空间中被检查？
- 风险提醒：最容易被误读为什么？
- 边界约束："不会发生什么"是否明确？

**同一套上位约束（一主两辅）：**

不管是底盘预制、大模型转译、还是多学科预加工，产出的命题都必须能挂到一主两辅上。挂不上的，不进系统。

### 3.2 同频的意义

有底盘时：调用预制结果，快速高效。

没底盘时：大模型用同一套协议实时执行，产出格式和质量标准一致。

两者合作时：底盘提供起点，大模型做二次校验和补充，无缝衔接。

> **合则默契高效，分则各自独立运行。**

## 四、六种协作模式

### 模式1：底盘命中，大模型校验

```
底盘匹配到预制命题 → 大模型校验：
  - 当前项目语境下还成立吗？
  - 有没有入库时没考虑到的特殊条件？
  - 需不需要改写或降级？
→ 校验后的命题进入 S2
```

底盘提供速度，大模型提供精度。

### 模式2：底盘缺失，大模型独立执行

```
底盘没有匹配 → 大模型独立执行五步法
→ 产出候选命题进入 S2
```

因为方法论同频，产出格式和底盘预制命题完全一致。

### 模式3：底盘部分命中，大模型补充

```
底盘匹配到3条 → 但业主还有底盘没覆盖的诉求
→ 大模型对已命中的做校验 + 对未覆盖的独立执行五步法
→ 两部分合并进入 S2
```

最常见的情况。

### 模式4：大模型对底盘内容做语境化加强

```
底盘命题："客房隔声量不低于45dB"
→ 大模型判断：这个项目是疗愈民宿，45dB不够，建议40dB
→ 改写后的命题进入 S2
```

避免入库时的勉强和局限。底盘给的是通用值，大模型根据具体项目做精调。

### 模式5：需求分析产出回流底盘

```
项目完成 → 回评哪些命题有效
→ 有效且通用 → 回流入库成为预制命题
→ 大模型改写版优于原版 → 替换原版
→ 发现新张力模式 → 新增零件
```

底盘的进化机制。每个项目都是一次实战检验。

### 模式6：大模型发现底盘错误

```
底盘命题："停车场坡度不宜超过15%"
→ 大模型发现当地法规要求不超过12%
→ 标记修正 → 人工审核后更新底盘
```

大模型不只是执行者，也是底盘的审计员。

## 五、运行时完整序列

```
项目输入（业主说"我想要有诗意的疗愈民宿"）
    │
    ▼
一主两辅启动：识别空间主线、驱动力、边界
    │
    ├──→ 知识底盘被查询
    │     ├── 类型知识命中：民宿类型包加载
    │     ├── 经验零件命中：3条相关经验规则
    │     ├── 预制命题命中：2条增辉命题
    │     └── 缺失部分标记："诗意"没有精确匹配
    │
    ├──→ 大模型介入
    │     ├── 对底盘命中内容做二次校验（语境适配）
    │     ├── 对缺失部分实时执行五步法
    │     └── 实时调用多学科素材（LLM自身知识）辅助转译
    │
    ▼
候选命题池（底盘预制 + 大模型实时生成，格式统一）
    │
    ▼
一主两辅裁决：S2碰撞 → S3取舍 → S4冻结
    │
    ▼
任务书（只有经过裁决的命题才进入）
    │
    ▼
项目完成后回评
    ├── 有效命题 → 回流底盘（沉淀层）
    ├── 大模型改写版优于原版 → 替换底盘原版
    └── 发现底盘错误 → 标记修正
```

## 六、四个角色的不可替代性

| 角色 | 不可替代的能力 | 如果缺了它 |
|------|-------------|-----------|
| 一主两辅 | 组织、裁决、冻结 | 分析跑偏，产出无法收口 |
| 知识底盘 | 稳定、快速、可控 | 每次从零开始，效率低，质量波动大 |
| 大模型 | 无穷、灵活、语境化 | 只能用预制内容，遇到新情况就卡住 |
| 多学科 | 深度、感性、拔高 | 项目能成立但没有灵魂，工匠水平 |

## 七、底盘与应用的共生关系

### 底盘为应用而生

知识底盘不是为了"存知识"而存在。它唯一的价值是让需求分析更快、更稳、更可控。没有应用场景的底盘就是死库。

### 应用反哺底盘进化

每个项目都是底盘的一次实战检验：
- 发现底盘的盲区 → 补充新条目
- 发现底盘的错误 → 修正旧条目
- 大模型的实时产出优于底盘预制 → 替换升级
- 新的张力模式被发现 → 新增零件

### 大模型是底盘进化的加速器

- 大模型可以对库内内容二次复核补充加强
- 避免入库时的勉强和局限
- 在具体项目语境中发现底盘的通用结论不够精确
- 从而实现底盘的持续进化

> **底盘是大模型的起跑线，大模型是底盘的进化引擎。两者不是替代关系，而是共生关系。**

---

## 八、一句总结

> **一主两辅是宪法，底盘是法典，大模型是法官，多学科是人文修养。法典让法官判得更快更稳，法官让法典越来越完善，宪法保证所有判决的合法性，人文修养让判决有温度有深度。四者方法论同频，缺一不可。**
