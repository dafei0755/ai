# 工作流运行器与状态广播契约（2026-03-09）

> **导航提示：** 建议先读 [README](README.md) 与 [01-运行时实时链路与断线恢复](01-运行时实时链路与断线恢复-2026-03-11.md)；本文对应本目录的 [02-工作流运行器与状态广播契约](02-工作流运行器与状态广播契约-2026-03-11.md) 中控入口。

> **定位：** 补齐 `workflow_runner` 作为运行时“中控层”的可执行契约，约束节点执行、会话状态写入、WebSocket 广播与归档触发的一致语义。

---

## 一、代码事实锚点

- 文件：`intelligent_project_analyzer/api/workflow_runner.py`
- 关键函数：
  - `run_workflow_async(session_id, user_input)`
  - `broadcast_to_websockets(session_id, message)`
  - `get_or_create_async_checkpointer()`
- 进度单一源：`NODE_PROGRESS` 来自 `workflow/workflow_contract.py`

---

## 二、运行器职责边界

| 职责 | 说明 |
|---|---|
| 工作流生命周期控制 | 创建 workflow、执行 `astream`、处理 interrupt、完成/失败收口 |
| 状态写入 | 将 `status/progress/current_node/detail/history` 写入 session manager |
| 事件广播 | 广播 `node_update`、`status_update`、`interrupt` |
| 事件补偿接线 | 广播前写 EventStore，支持断线回放 |
| 归档触发 | 完成后触发 checkpoint 同步与归档（不阻断主流程） |

**非职责（避免越界）：**
- 不在运行器内定义业务节点规则（节点策略应在 workflow/nodes 层）
- 不在运行器内维护独立进度映射（必须复用 `workflow_contract.NODE_PROGRESS`）

## 四、运行时不变量

1. 进度来源唯一：`NODE_PROGRESS`（不得在运行器硬编码第二份映射）
2. 进度不可回退：新进度低于旧进度时保持旧值
3. `interrupt` 出现时，先写会话为 `waiting_for_input`，再广播
4. 广播失败不应导致工作流主执行中断
5. 归档失败仅告警，不回滚已完成状态

---

## 五、错误与降级策略

| 场景 | 行为 |
|---|---|
| Postgres checkpointer 不可用 | 按开关决定是否回退 SQLite（严格模式下直接失败） |
| Redis Pub/Sub 发布失败 | 回退本地 WebSocket 广播 |
| EventStore 写入失败 | 记录 debug 日志，继续广播 |
| 节点输出包含 error/rejected | 收口为 `failed` 或 `rejected` 并广播 |

## 六、验证清单（建议加入回归）

1. `NODE_PROGRESS` 变更后，运行器无需改代码即可体现新进度
2. interrupt 触发后，前端可在重连时拿到 `interrupt_data`
3. EventStore 可通过回放接口补齐 `after_seq` 之后事件
4. 完成态会触发 checkpoint→Redis 同步，再尝试归档
