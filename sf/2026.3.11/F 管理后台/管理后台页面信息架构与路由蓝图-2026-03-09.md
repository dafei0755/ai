  - `admin_config`

  - `admin_health`

## 二、页面信息架构（IA）

建议后台前端（`frontend-nextjs`）采用如下路由：

| 页面路由 | 页面名称 | 对应后端域 |
|---|---|---|
| `/admin` | 总览（Dashboard） | metrics + health |
| `/admin/sessions` | 会话管理 | sessions |
| `/admin/database` | 数据库与归档 | database |
| `/admin/config` | 配置中心 | config |
| `/admin/domain` | 领域管理 | domain |
| `/admin/ontology` | 本体管理 | ontology |
| `/admin/showcase` | 案例与展示 | showcase |
| `/admin/audit` | 操作审计（聚合视图） | 由上述域事件聚合 |

---

## 三、页面模块设计

### 3.1 `/admin` 总览（首屏）

卡片建议：
1. 会话总量 / 活跃会话 / 异常会话
2. 主链健康：`health`、`readiness`
3. 运行态：最近失败节点、中断待确认数
4. 实时链路：WebSocket 在线连接数、回放请求量

### 3.2 `/admin/database`

重点强调边界：
- 必须在页面明确“当前统计范围”（archive-only / 全链路）
- 展示 checkpoint/archive 可写状态
- 展示最近归档成功率、失败原因 TopN

### 3.3 `/admin/sessions`

- 会话检索、状态筛选（running/waiting/completed/failed/rejected）
- 会话详情侧栏显示：当前节点、detail、最近事件
- 提供“只读事件流”面板（关联 EventStore 回放链路）

---

## 四、交互不变量

1. 管理后台只读能力优先，写操作必须显式二次确认
2. 所有“危险操作”必须展示影响范围与回滚路径
3. 页面字段与后端契约同名，避免 UI 二次翻译导致歧义
4. 监控页应区分“实时状态”与“持久化统计”，避免口径混淆

---

## 五、实施顺序（建议）

| 阶段 | 交付 | 优先级 |
|---|---|---|
| Phase A | `/admin` 总览 + `/admin/sessions` + `/admin/database` | P0 |
| Phase B | `/admin/config` + `/admin/health` 深化 | P1 |
| Phase C | `/admin/domain` + `/admin/ontology` + `/admin/showcase` 联动 | P1 |
| Phase D | `/admin/audit` 审计汇总与操作回放 | P2 |
