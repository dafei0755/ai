# 专家概念图生成与交互重生成链路（2026-03-09）

> **导航提示：** 建议先读 [README](README.md) 与 [01-专家角色体系与成果化主线](01-专家角色体系与成果化主线-2026-03-11.md)；本文对应本目录的 [02-专家概念图生成与交互重生成](02-专家概念图生成与交互重生成-2026-03-11.md) 专题入口。

> 范围：专家执行后自动生图 + 报告页交互重生成。  
> 目标：沉淀“生成、存储、聚合、前端交互”全链路契约。

---

## 1. 全链路概览

```
专家执行节点
  → image_generator（按角色/交付物生成）
  → agent_results[*].concept_images
  → result_aggregator 提取
  → final_report.generated_images_by_expert
  → 前端报告展示 + 交互重生成 API
```

---

## 2. 后端核心模块

关键模块：
- `services/image_generator.py`：提示词生成与模型调用
- `services/image_storage_manager.py`：文件落盘与元数据维护
- `api/image_routes.py`：增删改查、重生成接口
- `report/result_aggregator.py`：聚合到 `generated_images_by_expert`

核心字段：
- 过程态：`agent_results[role_id].concept_images`
- 交付态：`final_report.generated_images_by_expert`

---

## 3. 运行开关与降级

核心开关：
- `IMAGE_GENERATION_ENABLED`

推荐策略：
1. 开关关闭时明确记录“跳过生图”日志。
2. 单角色失败不阻断整体流程（局部降级）。
3. 聚合层始终保持字段结构稳定，避免前端崩溃。

---

## 4. 前端交互重生成

前端通过图像相关 API 进行：
- 新增图
- 重生成（带上下文）
- 删除图
- 历史对话持久化

交互原则：
1. 原图与新图版本可并存（可回退）。
2. prompt 与 prompt_used 分离存储，便于审计。
3. 显示层优先使用 `image_url`，后端兼容 `url`→`image_url` 映射。

---

## 5. 存储契约

推荐目录：
- `data/generated_images/{session_id}/...`

约束：
1. 禁止将大体积 base64 直接长期塞入会话状态。
2. 元数据索引中保留：角色、交付物、prompt、时间戳、文件 URL。
3. 报告读取只消费 URL，不依赖内存原图。

---

## 6. 回归要点

- 生图开关关闭时，主流程照常完成。
- 生成成功时，`generated_images_by_expert` 结构稳定。
- 交互重生成失败时，不影响已有图展示。
- 报告接口输出图片 URL 可直接访问。
