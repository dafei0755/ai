## 一、核心定位

**方案图谱是旁路观察面（Observer Plane），不是工作流控制层。**

| 职责 | 是否承担 |
|---|---|
| 观察——将项目讨论结果可视化为关系图 | ✅ |
| 显示——展示概念聚类、关系强度、认知空白区 | ✅ |
| 提醒——无声指出结构性盲区（"这里没想清楚"） | ✅ |
| 导航——点击节点查看来源片段（只读） | ✅ V1.5 |
| 修改项目状态 / 对象 | ❌ |
| 推动流程跳步 / 触发冻结 / 触发执行 | ❌ |
| 直接写入 `DesignTaskBook` / 会话级执行编排（按需） | ❌ |
| 作为任何阶段的真相源 | ❌ |

**一句话定性：图谱只能读领域对象，不能反向定义领域对象。真相源始终是核心对象链。**

### 文档边界（v3 校正）

为避免“图谱机制”与“观察员方法论”混写，本文只回答以下问题：

## 二、页面布局规格

### 交互策略

**默认以形态 A（单窗口分栏）打开，在界面上提供"打开观察屏"按钮，让用户主动决定是否拆成独立窗口。**

- 单屏用户：始终在形态 A 工作，得到最佳的分栏 + 可拖拽体验
- 双屏用户：点击"打开观察屏"后，形态 B 自动激活，将图谱迁移到第二块显示器

### 形态 A：单窗口分栏（默认）

```
┌─────────────┬──────────────────────────────────────┐
│             ╎                                      │
│  方案图谱    ╎        主对话与生产窗口               │
│  观察面板    ╎        (唯一生产入口)                 │
│             ╎                                      │
│  默认 35%    ╎              默认 65%                │
│             ╎  [打开观察屏 ↗]                      │
└─────────────┴──────────────────────────────────────┘
              ↑ 可拖拽分割线，左右自由调节
```

分割线可左右拖动，实时调整两侧宽度比例。这是唯一拥有可拖拽分割线的形态——两侧同属一个浏览器窗口，CSS + JS 可完全控制。

| 模式 | 图谱宽度 | 主窗口宽度 | 触发方式 |
|---|---|---|---|
| **默认**（生产优先） | 35% | 65% | 页面初始状态 |
| **自由调节** | 任意 | 任意 | 拖拽分割线 |
| **纯生产** | 折叠（0%） | 全屏（100%） | 一键折叠按钮 |

**硬规则**：折叠图谱时不销毁图谱状态，重新展开后即时恢复，无需重新请求数据。

### 形态 B：独立观察屏（用户主动触发）

点击"打开观察屏"后：
1. 方案图谱在独立浏览器窗口中打开
2. 主窗口内的图谱面板自动折叠，主窗口回到全宽生产视图
3. 两窗口通过 `BroadcastChannel` 保持状态同步

```
主窗口（全宽）                        副窗口 / 观察屏
┌────────────────────────┐           ┌──────────────────────┐
│                        │           │                      │
│   主对话与生产窗口       │ ←──同步──→ │     方案图谱           │
│   （全宽，无分栏）       │           │    （独立窗口，只读）   │
│                        │           │                      │
│   [关闭观察屏 ✕]        │           │                      │
└────────────────────────┘           └──────────────────────┘
        BroadcastChannel：同步事件 + 对象 ID（不同步 DOM）
```

| 屏幕配置 | 操作方式 |
|---|---|
| **单屏** | 两个浏览器窗口并排（Win+左/右箭头），各自用 OS 方式拖边缘调大小 |
| **双屏** | 将观察屏窗口拖到第二块显示器即可 |

**边界说明**：形态 B 下两个独立窗口之间没有可拖拽的共享分割线——这是 Web 平台固有限制，浏览器无法跨窗口联动 resize。每个窗口大小由用户通过 OS 窗口管理独立调整。

关闭观察屏后，主窗口自动恢复形态 A（图谱面板重新展开）。

#### 形态 B 实现

```typescript
// 主窗口：打开并复用命名窗口
window.open('/scheme-graph?session=' + sessionId, 'ObserverWindow',
  'width=1200,height=800');

// 主窗口：广播状态变更
const channel = new BroadcastChannel('scheme-graph-sync');
channel.postMessage({ type: 'GRAPH_UPDATE', sessionId, nodeId });

// 观察屏窗口：接收广播并刷新
const channel = new BroadcastChannel('scheme-graph-sync');
channel.onmessage = (e) => {
  if (e.data.type === 'GRAPH_UPDATE') refreshGraph(e.data);
};
```

同步规则：
- 同步的是**事件和对象 ID**，不是整棵 DOM 或完整数据
- 观察屏只读，只做高亮、聚焦
- 主窗口状态变更 → BroadcastChannel 广播 → 观察屏被动刷新
- 观察屏关闭 → 主窗口图谱面板自动恢复展开

`BroadcastChannel` 在所有主流浏览器中广泛可用（Chrome/Edge/Firefox/Safari），同源窗口间双向通信，无需 WebSocket 中转。

### V2：布局记忆

用户关闭观察屏后，下次进入同一项目时自动恢复双窗布局。

持久化内容（存入 localStorage，按 sessionId 索引）：
- 是否开启观察屏（`observerWindowEnabled: boolean`）
- 观察屏上次的窗口大小和位置（`width`, `height`, `screenX`, `screenY`）
- 单窗模式下的分栏比例（`splitRatio: 0.35`）

恢复逻辑：进入项目时读取布局记忆 → 若 `observerWindowEnabled = true` → 自动调用 `window.open` 在记忆位置恢复观察屏，无需用户手动点击。

## 三、数据架构

### 核心原则：双层读模型（Dual-Layer Derived Read Model）

**v2 修订（2026-03-15）**：原"只读稳定交付物与稳定事件"原则过于保守，升级如下：

> **方案图谱分为稳定层与过程层：稳定层只承载冻结结果，过程层承载形成中的认知结构；过程层节点必须来自语义归约事件（不直读 token 流），并通过提级机制（用户确认或自动审批）进入稳定层。**

这与主架构的核心定义完全对齐——主架构明确：S3 冻结的是取舍，不是原始信息；S2 内部可以持续推进、修正、压缩。因此过程态有资格被观察，但必须与冻结态的可信等级分开承载，不能混用同一节点样式、同一存储层、同一可信等级。

**仍然禁止直读的内容**（与 v1 一致）：

- 原始 prompt 文本流（语言生成痕迹，噪声极大）
- LLM token 级中间输出（过渡句、铺垫句、试探句，不构成认知结构）
- 未经语义归约的前端临时状态

> **直读 token 流会造成图谱像心电图一样高频抖动，破坏信任感，且形成不可维护的实现依赖。**

**允许进入过程层的内容**（必须经过语义归约）：

- Agent 节点的语义摘要（如"正在识别核心冲突…"，由 Agent 主动发射，不是 token 采样）
- `node_started` / `node_completed` WS 事件携带的结构化 `graph_hint`
- 已识别但待确认的语义节点（张力、信息缺口、候选任务维度等）
- 用户确认或系统审批事件

> 过程层不是"什么都能进"的缓冲区——它的入口是 **语义事件**，不是原始流。

### 双层数据架构

方案图谱同时维护两个数据层，互相不干扰：

| 层 | 内容 | 来源 | 生命周期 |
|---|---|---|---|
| **稳定语义层** | 从已完成对象中提取的概念节点与聚类关系 | 领域对象（见下表） | 随 session 持久化 |
| **动态过程层** | 反映 Agent 思考过程的三态节点 | WebSocket 运行事件 | 内存 + session，TTL 受限 |

动态过程层不写入领域对象，只在前端 GraphStore 中维护，图谱关闭/重建后可根据 WS 事件快照重建。

### 合法数据源

| 数据源 | 描述 |
|---|---|
| `RawBriefPacket` | 用户输入完成后 → 初始概念抽取 |
| `GateDecision` | 门禁判定结果 |
| `DesignTaskBook` | 需求分析冻结后 → 关系结构投影 |
| 会话级执行编排（按需） | 方案高参阶段 → 本轮动作依赖网络 |
| `DeliveryBundle` | 交付后 → 最终概念总图 |
| `IntentSeed` / `ConsensusPack` | 对话态草稿对象 → 讨论热点可视化 |
| 审计事件 / 冻结快照 | 运行时治理层的事件广播 |

### 动态过程层：三态模型（v2 新增）

动态过程层通过现有 WebSocket 事件驱动，将 Agent 执行过程可视化为三种状态的节点，展现"思考中的图谱"而非仅显示已完成的交付物。

**三态定义（v2 扩展为四态）**

| 状态 | 触发条件 | 视觉规格 | 持久化 |
|---|---|---|---|
| `streaming` | `node_started` WS 事件 | 脉冲动画 + 30% 透明度 + 无完整标签 | 内存，TTL 30s 自动清除 |
| `pending` | `node_completed` WS 事件 | 虚线边框 + 70% 透明度 + 完整标签 | session 内存 |
| `stable` | 用户确认中断点 / 系统自动审批 | 全色 + 聚类着色 + 全标签 | 持久化 |
| `deprecated` | 用户否决 / 系统回退 / 被替代节点 | 灰化 + 删除线或折角 + hover 显示"失效原因" | 持久化（归档，不销毁） |

> `deprecated` 态是第四状态，对应主架构明确定义的回退/被否决路径。它不销毁，因为"出现过但已退出基线"本身是有价值的认知历史，支持 V2 决策演化时间轴的回放能力。

**三态转换规则**

```
           node_started          node_completed        用户确认/自动审批
[不存在] ─────────────▶ streaming ──────────────▶ pending ─────────────────▶ stable
                                   \ TTL 超时                                   │
                                    ▼                用户否决/系统回退          │
                                 [清除]          ◀────────────────────────── pending/stable
                                                              │
                                                              ▼
                                                         deprecated
                                                    （归档，不删除）
```

**节点语义约定**

- `streaming` 节点：仅当前正在执行的 Agent 节点本身（同时最多 1 个），不显示 token 流，不显示原始 prompt
- `pending` 节点：Agent 完成后输出的语义节点（张力、信息缺口、任务维度等），已有内容但尚待用户确认
- `stable` 节点：经过用户确认（或系统自动审批）后落定的语义节点，进入聚类布局

**前端 GraphStore（Zustand）**

```typescript
interface GraphStore {
  streaming: Set<string>;                     // nodeId → 内存，TTL 30s
  pending: Map<string, GraphNode>;            // nodeId → node data，session
  stable: Map<string, GraphNode>;             // nodeId → node data，持久
  stableEdges: Map<string, GraphEdge>;        // edgeId → edge data
  deprecated: Map<string, GraphNode>;         // nodeId → 归档节点（可展示失效原因）
  addStreaming: (nodeId: string) => void;
  promoteToPending: (nodeId: string, data: GraphNode) => void;
  promoteToStable: (nodeId: string) => void;
  promoteAllPendingToStable: () => void;      // 用户确认触发
  markDeprecated: (nodeId: string, reason: string) => void;  // 否决/回退触发
}
```

**过程层噪声过滤规则**

保证过程层不退化为信息毛球：

| 规则 | 描述 |
|---|---|
| **语义聚合进入** | Agent 只发射语义摘要（如 `graph_hint.label = "正在识别核心冲突"`），不做 token 级节点 |
| **TTL 保护** | `streaming` 节点若在 30s 内未收到 `node_completed` 事件，自动从内存清除（不进入 deprecated） |
| **pending 可恢复** | 图谱关闭/重建后 `pending` 节点可从 WS 事件快照重建，不依赖持久化 |
| **用户可隐藏过程层** | 前端提供开关：隐藏 `streaming` + `pending` 节点，仅显示 `stable` + `deprecated`（只改视图） |
| **deprecated 折叠** | `deprecated` 节点默认折叠为小灰点，hover/点击展开，不占用主视觉区域 |

**WS 消息扩展（后端 Phase 2 实施）**

向现有 WS 消息中新增可选字段 `graph_hint`，不破坏原有消息格式：

```typescript
interface GraphHint {
  node_id: string;        // 如 "tension_analysis_001"
  label: string;          // 显示标签
  stability: 'streaming' | 'pending' | 'stable';
  cluster?: string;       // 聚类 ID，stable 态时提供
}
```

前端 Phase 1 可通过模拟事件验证三态渲染，`graph_hint` 实际接入在 Phase 2 实施，不阻塞前端开发。

### 后端服务

新增独立只读服务：`ObserverGraphProjection`

- 订阅现有事件总线（EventBus）广播
- 在各阶段交付物生成后异步触发概念提取（LLM 提取，不阻塞主链）
- 图谱数据通过现有 WebSocket 通道推送到前端
- 图谱失败（LLM 超时、计算错误）不影响主生产链任何功能
- 图谱数据随 session 生命周期存储，不写入核心领域对象

### 架构层挂接（极简扩展）

| 现有架构层 | 方案图谱的挂接方式 |
|---|---|
| **入口交互层** | 新增方案图谱面板组件；监听 WS 更新渲染；处理节点 tooltip 交互 |
| **流程编排层** | 不改动；仅暴露只读当前节点状态查询接口 |
| **领域对象层** | 不改动；图谱只读已有对象，不写回 |
| **能力执行层** | 不改动 |
| **基础能力接口层** | 不改动 |
| **知识与记忆层** | 不改动；利用已有知识链接查询接口，展示"引用"关系 |
| **运行时与治理层** | 事件总线新增对象创建/更新/删除广播；Checkpoint 支持只读历史快照查询 |

## 四、图谱展示内容

### V1（MVP，优先落地）

**1. 项目核心概念簇**

- 从讨论内容中抽取关键维度节点：品牌、场地、用户、造价、规范、功能、材料、运营、情绪…
- 节点大小 = 讨论频度（中介中心性）
- 颜色 = 自动聚类分组（Louvain 算法）
- 作用：让设计师一眼看到"我们聊了什么维度，哪个维度过密，哪个维度缺位"

**2. 冲突-取舍关系**

- 红色连线标注已识别的对立面（如：自然沉浸 vs 品牌识别）
- 连线粗细 = 冲突强度
- 作用：提醒用户当前在解什么矛盾，避免被表面关键词带偏

**3. 认知空白区（盲区检测）**

- 聚类间连接密度低于阈值 → 标记为虚线区域
- 悬停显示："空间规划与预算约束之间缺少关联思考"
- 作用：无声地指出"这里你还没想清楚"，比 AI 说话更高级

**节点数上限**：150 个（防止大项目变成信息毛球）
**弱边过滤**：权重低于阈值的边默认隐藏，避免噪声

### V2（V1 验证稳定后扩展）

**4. 阶段性冻结结果投影**

- 已锁定主命题（绿色节点）/ 红线（红色节点）/ 可让位项（灰色节点）/ 本次不做项（虚框）
- 作用：让用户从图上看见系统在"形成判断"而非"堆观点"

**5. 草稿对象沉淀**

- 对话态中的 `IntentSeed`、`ConsensusPack` 之间的逻辑关系可视化
- 蓝灰色区分"草稿态"与"已冻结态"

**6. 决策演化时间轴**

- 图谱底部时间轴滑块，拖动查看历史快照
- 完全只读，不影响当前项目状态

## 七、技术选型（v2 确认，2026-03-15）

### 前端图渲染栈

| 项 | 选型 | 理由 |
|---|---|---|
| 图渲染引擎 | **Sigma.js** | WebGL Canvas 渲染，万节点级性能；InfraNodus 官方栈，与本系统长期演进目标对齐 |
| 图数据结构 | **Graphology** | Sigma.js 官方配套图数据库，支持有向/无向/混合图，节点/边属性 API 完整 |
| 力导向布局 | **graphology-layout-forceatlas2** | Graphology 生态官方布局，与 Graphology 深度集成 |
| 社区聚类 | **graphology-communities-louvain** | Graphology 生态 Louvain 实现，识别概念聚类 |
| 前端状态管理 | **Zustand**（已安装） | GraphStore 管理三态节点；streaming/pending/stable 分层存储 |
| 动画 | **framer-motion**（已安装） | streaming 态脉冲动画；节点状态转换过渡 |
| XYFlow | 不用于方案图谱 | XYFlow 是流程图引擎，不适合自由聚类图；继续用于后端工作流可视化 |

> **选型理由（对比 Cytoscape.js）**：当前节点规模（50–150）两者均可，但方案图谱的后续升级路径（全屏双窗 + 多项目对比 + 深度认知分析）需要 WebGL 能力。Sigma.js 是该路径的唯一成本可控选项；Cytoscape.js 迁移到 WebGL 代价高且生态割裂。

### npm install（Phase 1 实施前需执行）

```bash
npm install sigma graphology graphology-layout-forceatlas2 graphology-communities-louvain graphology-metrics
```

**关于 React Flow / XYFlow 的交叉验证（回应参考意见 d）**

参考意见 d 建议用 React Flow（xyflow）替代 Sigma.js 作为方案图谱的渲染引擎，理由是"天生为 LLM 思考过程可视化设计"。经评估，此建议不适用于本场景：

| 维度 | React Flow (XYFlow) | Sigma.js + Graphology |
|---|---|---|
| 擅长场景 | DAG / 有向流程图（节点有明确位置/连接语义） | 力导向自由聚类图（节点位置由关系强度决定） |
| 社区检测 | 不支持 | graphology-communities-louvain ✅ |
| 结构空洞/盲区检测 | 不支持 | 聚类间连接密度阈值 ✅ |
| 节点自组织布局 | 不支持（须手动定位或写 layout 算法） | ForceAtlas2 原生 ✅ |
| 已有使用场景 | 后端工作流可视化（本项目已在用） | 方案图谱（本项目新增）|

结论：React Flow 是正确的 DAG 工具，本项目已在后端工作流可视化中使用；但方案图谱的核心价值（聚类布局 + 间隙检测 + 中心性分析）是 InfraNodus 风格的网络分析，这是 Sigma.js + Graphology 的使用场景。两个工具没有互斥关系，各司其职。

### 后端图计算栈

| 项 | 选型 | 理由 |
|---|---|---|
| 图计算 | **NetworkX** | 已随 LangGraph 安装（3.4.2 验证可用），零增量成本 |
| 数据序列化 | `nx.readwrite.json_graph.cytoscape_data(G)` | 输出格式与 Graphology 兼容，前后端无需维护额外转换层 |
| 概念提取 | 后端 LLM | 从稳定交付物提取，不在前端做 NLP |
| 盲区检测 | 聚类间连接密度 | 密度低于阈值 → 标记结构性盲区 |
| 数据通道 | 现有 WebSocket | 复用已有通道，不新增连接；新增可选 `graph_hint` 字段 |
