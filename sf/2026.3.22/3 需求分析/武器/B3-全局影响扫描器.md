# B3 — 全局影响扫描器

> **组别**：B 组（框架选型必说）| **阶段**：S2 | **类型**：互动·必说
> **原始编号**：L7 系统性影响评估 | **发声顺序**：B 组第 3 件

---

## 一分钟定义

在方向确定之前，**快速扫描该项目方向在时间和领域两个维度上的系统性影响**，防止局部优化伤害整体，让用户提前规避已知风险。

---

## 功能详述

B3 扫描 3×4 矩阵中的突出风险点（不要求填满每格，只标注值得关注的）：

|        | 社会影响 | 环境影响 | 经济影响 | 文化影响 |
|--------|---------|---------|---------|---------|
| **短期** | — | — | — | — |
| **中期** | — | — | — | — |
| **长期** | — | — | — | — |

**面向用户的展示**：不展示完整矩阵（避免信息过载），只展示 2~3 个「值得提前规避的突出影响」。

**B3 的定位**：不是全面评估（可行性分析的任务），而是「提前亮黄灯」，让用户意识到某些影响的存在，决定是否需要在方向上做调整。

---

## 输入

```
jtbd_statement     # B1 任务定义（扫描对象：这个方向）
conflict_pairs     # B2 冲突对（重点扫描冲突放大的影响领域）
```

---

## 输出

```python
system_impact_notes: {
    "notable_impacts": [
        {
            "dimension":   "长期经济",
            "description": "高端材料若超预算，会导致施工阶段迫于成本缩减面积",
            "severity":    "medium" | "high",
            "avoidance":   "提前锁定核心区域的材料预算"
        },
        ...
    ],
    "full_matrix": {...}   # 背景存储，不直接展示
}
```

---

## 激活条件

- B2 responded（用户确认冲突诊断后）
- S2 强制执行，不可跳过

---

## 执行方式

- **执行器**：LLM 调用
- **重点扫描**：B2 识别的冲突对会在 B3 中放大扫描，因为冲突本身是系统性风险的高发区
- **数量控制**：展示给用户的「突出影响」最多 3 个；severity=low 的影响写入 full_matrix 但不展示
- **不深入评估**：B3 的「影响」是定性描述，不是量化评估；量化工作属于可行性分析（feasibility_analyst）

---

## 用户交互

**有**。展示格式：

```
沿这个方向推进，有几个值得提前注意的影响：

1. [描述] → 建议：[规避方向]
2. [描述] → 建议：[规避方向]

你需要在方向上做调整，还是继续推进并在后续设计中处理这些风险？
```

用户只需回答「继续」或「调整方向」，不需要逐条确认。

## 协作关系

```
上游（依赖）：
  ← B1 任务目标提炼器
  ← B2 目标冲突诊断器

下游（供给）：
  → state.confirmed_constraints（B3 标记的高 severity 影响可能成为 D2 的约束候选）
  → 可行性分析节点（full_matrix 提供预分析上下文）
  → S4 任务书（突出影响写入「风险与边界提示」一节）
```

---

## 常见误用

1. **把 B3 当作可行性分析**
   纠偏：B3 是「提前亮灯」，不是完整评估；完整技术/成本/工期评估由下游 feasibility_analyst 完成

2. **把整个 3×4 矩阵都展示给用户**
   纠偏：B3 对用户只展示「值得规避的突出点」，全矩阵是背景数据；用矩阵轰炸用户会造成决策疲劳

3. **B3 结论过于保守，凡事都是「风险」**
   纠偏：B3 的作用不是吓退用户，而是帮助提前规划；severity=low 的项不应出现在用户界面

## 扩展优化方向

- **行业风险库**：室内设计领域的常见系统性风险（材料涨价、施工期延误、用途变化等）预置为知识库，B3 可快速匹配
- **风险优先级排序**：基于项目预算/周期/用途，自动标注哪类影响对该项目最具威胁
