# C2 — 多方利益梳理器

> **组别**：C 组（框架扩展·条件触发）| **阶段**：S2 | **类型**：互动·条件触发
> **原始编号**：L2.5 利益相关者系统 | **触发阈值**：relevance_score ≥ 0.5

---

## 一分钟定义

画出项目中**所有独立决策方的角色、诉求、影响关系**，识别隐性利益冲突——专门针对「用户以为只有自己一个决策方，其实有多方需要平衡」的情况。

---

## 功能详述

适用场景（只要符合其一即触发）：
- 业主不等于最终使用者（例：企业主装修 vs 员工使用）
- 有明确的第三方约束方（物业/规划局/品牌方）
- 家庭成员之间诉求明显不同（例：业主 vs 配偶 vs 孩子 vs 父母）
- 商业空间有多层客户（例：商场承租方 vs 消费者 vs 品牌形象要求）

**C2 的不同之处**：B1/B2 处理的是「用户自己的目标冲突」，C2 处理的是「不同人之间的利益冲突」。两者不重合。

---

```

```

---

## 激活条件

`relevance_score(C2) ≥ 0.5` 时触发。

**主要触发信号**：
- A1 信号包中第三方角色数量 > 2
- 场景信号中出现明确的「家庭成员分歧」「多方审批」表述
- 项目类型为商业/公共/企业办公（多方利益的出现概率显著高于住宅）

**有**。展示格式：

```
这个项目涉及几个不同的利益方，他们的诉求可能有冲突：

• [角色 A]：想要 [诉求]
• [角色 B]：想要 [诉求]
• [约束方 C]：要求 [约束]

你需要主动平衡哪些关系？有没有某一方的诉求可以稍作牺牲？
```

## 协作关系

```
上游（依赖）：
  ← A1 需求信号解析器（利益方信号）
  ← insight_distiller（relevance_score）

下游（供给）：
  → D2 约束条件识别器（约束方的「硬限制」直接进入 D2 的约束清单）
  → S4 张力冻结（多方利益冲突点进入决策矩阵的补充行）
```

---

## 常见误用

1. **把 C2 和 B2 混用（把利益冲突当作目标冲突）**
   纠偏：B2 处理「同一个用户自己的目标之间的冲突」；C2 处理「不同人之间的诉求冲突」——两者分析对象不同，不可合并

2. **强制触发 C2 于单人决策的住宅改造**
   纠偏：单身用户或夫妻完全一致的住宅项目，C2 几乎没有价值，relevance_score 会自然低于阈值

## 扩展优化方向

- **影响力网络图**：前端可视化各方影响关系（谁对谁有一票否决权、谁需要谁的审批）
- **历史冲突模式库**：商业空间/家庭居住等常见的三方博弈模式预置为知识，提升 C2 的识别精度
