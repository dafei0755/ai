# C3 — 使用者行为模式引擎

> **组别**：C 组（框架扩展·条件触发）| **阶段**：S2 | **类型**：互动·条件触发
> **原始编号**：10_Mode_Engine（sf 套件）| **触发阈值**：relevance_score ≥ 0.55

---

## 一分钟定义

从 10 种空间使用行为模式中，识别目标用户的**主导模式**，将「使用者行为习惯」翻译成「空间应优先支持什么功能」——解决「设计师根据风格定义空间，而不是根据行为方式定义空间」的问题。

---

## 功能详述

### 10 种行为模式（sf 套件 10_Mode_Engine）

| 模式 | 核心描述 | 空间优先需求 |
|------|---------|------------|
| **积累者** | 大量收藏物品，储存 = 生活秩序 | 深度储物系统，分类展示区 |
| **流动者** | 空间必须随活动快速切换 | 灵活隔断，多功能桌面，留白区 |
| **专注者** | 单一活动高密度沉浸 | 屏蔽干扰，光线可控，隔音 |
| **交汇者** | 人际连接是核心体验 | 多人聚集区，视线流通，开放厨房 |
| **展示者** | 空间是身份/品味的表达载体 | 视觉焦点，精选展陈，入口仪式感 |
| **修复者** | 在家是恢复能量而非创造 | 感官降噪，柔性材料，私密角落 |
| **创造者** | 持续创作，混乱是工作状态 | 容错表面，展开工作台，就近灵感库 |
| **仪式者** | 日常仪式（早晨/晚间）是生活重心 | 固定动线支撑，专属仪式区 |
| **探险者** | 对新鲜体验的持续寻求 | 模糊边界，可重新排列的开放结构 |
| **守护者** | 家 = 安全边界的守护，控制感强 | 清晰分区，可掌控的入口，稳定秩序 |

## 输入

```
identity_mode           # B4 使用者身份识别结果（影响模式匹配）
scenario_signals        # A1 场景信号（行为特征线索）
relevance_score_C3      # insight_distiller 计算
```

---

## 输出

```python
behavior_mode_profile: {
    "primary_mode":    "专注者",
    "secondary_mode":  "创造者",     # 可为空
    "confidence":      0.78,
    "space_priorities": [
        "屏蔽干扰（隔音/光线可控）",
        "允许展开的大工作台面",
        "就近材料/灵感库"
    ]
}
```

---

## 激活条件

`relevance_score(C3) ≥ 0.55` 时触发。

**主要触发信号**：
- 用户描述中有明确的特殊使用场景（在家工作/创作/收藏/接待）
- B4 识别的身份模式为「创作者」或「探索者」
- A2 评估信息「充足」（说明用户对自己的使用方式描述详细，C3 识别质量高）

## 协作关系

```
上游（依赖）：
  ← B4 使用者身份识别器（身份模式参考）
  ← A1 需求信号解析器（场景信号）
  ← insight_distiller（relevance_score）

下游（供给）：
  → S4 张力冻结（space_priorities 进入决策矩阵的「空间功能优先级」行）
  → S4 任务书（行为模式写入「用户画像 / 使用模式」章节，驱动后续专家任务分配）
  → project_director（F8 专家问题生成时参考行为模式匹配专业能力）
```

## 常见误用

1. **把行为模式等同于风格偏好**
   纠偏：「专注者」不是在说用户「喜欢极简风」，而是在说用户的**行为需求**要求屏蔽干扰——风格是外表，模式是功能驱动

2. **把 C3 的输出直接暴露为「你是 X 类型用户」标签**
   纠偏：类似 B4，模式标签不直接展示；向用户展示的是「这意味着空间应支持什么」，让用户确认需求而不是接受分类

## 扩展优化方向

- **混合模式权重**：支持「主 + 次 + 弱」三级模式，混合驱动 space_priorities 的权重分配
- **模式演变轨迹**：追踪同一用户在多次项目中的模式变化，判断是否有模式漂移
- **验证测试题**：为 C3 识别结果低置信度的情况，提供 2~3 个非直接的「行为情境题」帮助判断主导模式
