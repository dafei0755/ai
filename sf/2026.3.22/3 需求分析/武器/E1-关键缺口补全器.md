# E1 — 关键缺口补全器

> **组别**：E 组（关键补缺）| **阶段**：S2 内部 | **类型**：互动·按需
> **原始编号**：Q3 空字段回填（互动部分）+ step3_gap_filling 交互逻辑

---

## 一分钟定义

以**最少追问轮次**补完「继续推进所必须的信息缺口」，不追求信息完整，只追求「问题足以冻结、任务书可以稳定编译的最低信息门槛」。

---

## 功能详述

E1 不再作为独立的 S5 阶段存在，而是作为 **S2 内部的关键补缺机制** 使用。它处理两类缺口：

| 缺口来源 | 内容 | 优先级 |
|---------|------|-------|
| A2 初始缺口 | S1 时就发现的信息不足 | 高（核心字段缺失） |
| S2 新增缺口 | 看清重点过程中暴露的新必需信息 | 高（会影响冻结） |

**E1 的「最小化原则」**：
- 每轮最多 3 个问题
- 最多 2 轮（共 6 个问题上限）
- 若用户拒绝回答，不强迫，交 G3 用推断值填充
- **不重问已在 S2/S3 讨论过的内容**——避免用户感觉被反复追问同一件事

**偏好补充入口**：E1 允许用户补充前序分析里未被显式记录、但会影响当前冻结判断的偏好说明。

---

## 输入

```
gap_list               # A2 输出的缺口清单（含重要性标注）
problem_framework      # 当前问题框架 / 空间命题候选
confirmed_constraints  # D2 约束清单（约束类信息不需要再问）
agreed_problem_frame   # 当前已收敛的主问题表达
```

---

## 输出

```python
gap_answers: {
    "project_type": "住宅·三室两厅",       # 用户回答
    "timeline": "[推断] 约 6 个月",         # G3 自动填充，标[推断]
    "special_user_needs": "女儿有哮喘，
                           需要特别关注空气质量"
}

preference_notes: {
    "extra": "如果实在要取舍，宁愿牺牲书房面积，保留餐厅面积"
}
```

---

## 激活条件

- A2 `gap_list` 非空，且其中存在**会影响冻结判断**的关键缺口
- 或 S2 过程中暴露出新的关键缺口
- 若缺口不影响冻结，则不触发 E1，由 G3 在后续编译时兜底

---

## 执行方式

- **问题优先级**：gap_list 按「重要性」排序，每轮取前 3 个最高优先级的缺口提问
- **去重检查**：提问前检查「这个缺口是否已在 S2 中被间接回答」，若已有，更新字段，不重问
- **G3 触发**：用户跳过的问题或超出 2 轮限制的剩余缺口，交 G3 自动用推断值填充

---

## 用户交互

**有（按需）**。展示格式：

```
还有几个关键信息需要确认，才能继续冻结当前判断：

1. [缺口问题 1]
2. [缺口问题 2]
3. [缺口问题 3]

如果有什么不确定的，直接跳过也可以——我会用合理的推断补全。
另外，有没有什么关于偏好的补充，想在这里加上？
```

---

## 协作关系

```
上游（依赖）：
  ← A2 信息充足度评估器（gap_list）
  ← S4 张力冻结（E1 在 S4 完成后才运行）
  ← D2 约束条件识别器（已确认的约束不重复追问）

下游（供给）：
  → G3 空字段自动兜底（用户跳过的缺口交给 G3 处理）
   → S3 冻结候选（补完后才允许继续定下取舍）
   → S4 任务书（gap_answers + preference_notes 作为编译输入）
   → state.registered_assumptions（所有 `[推断]` 值汇总，S4 时可选择性展示给用户）
```

---

## 常见误用

1. **把 E1 当做全面信息收集环节，追问所有未知信息**
   纠偏：E1 只补「继续推进所必须的」缺口，不是「把所有能知道的都问完」——用户的耐心是有限的

2. **把 E1 拖到任务书阶段再处理**
   纠偏：会影响冻结的关键缺口必须在 S2 内部解决；到了 S4 只允许编译性补注，不应重开分析

3. **E1 第二轮还问第一轮用户跳过的问题**
   纠偏：用户跳过 = `skipped_by_user`，第二轮不重问，直接交给 G3 推断填充

---

## 扩展优化方向

- **智能追问合并**：若 3 个缺口之间有内在联系，合并成 1 个综合问题（如：面积和户型同时问）
- **用推断计算最优追问数量**：根据缺口的「推断准确率」动态决定是否值得追问（推断很可靠的缺口不值得追问）
