# F1 — 事实推断分离器

> **组别**：F 组（后台引擎）| **阶段**：S1 | **类型**：后台·与 A1 并行
> **原始编号**：L1 事实解构

---

## 一分钟定义

区分用户输入中的**三类性质截然不同的内容**（事实 / AI推断 / 用户偏好），防止把「AI觉得用户大概是这个意思」当作「用户说了这个事实」来使用。

---

## 功能详述

| 标注类型 | 含义 | 处理规则 |
|---------|------|---------|
| `[FACT]` | 用户明确陈述的可验证事实 | 直接使用，高置信度 |
| `[INFERRED]` | AI 根据线索推断的内容 | 使用时必须标注「推断」，不可以事实身份传下游 |
| `[PREFERENCE]` | 用户表达的偏好或意愿 | 使用时区分「偏好」与「需求」，不可直接转化为约束 |

**举例**：

原始输入：「我想要一个温馨的家，有两个孩子，大概 130 平米左右，不想花太多钱。」

| 内容 | 标注 | 理由 |
|------|------|------|
| 有两个孩子 | `[FACT]` | 明确陈述 |
| 130 平米左右 | `[FACT]` | 明确陈述（「左右」表示近似，仍为事实） |
| 温馨 | `[PREFERENCE]` | 风格偏好，非客观事实 |
| 不想花太多钱 | `[PREFERENCE]` | 偏好，无具体数字，不能当约束用 |
| 孩子需要独立房间 | `[INFERRED]` | 未说，但 AI 根据「有两个孩子」推断 |

---

## 输入

```
user_input   # 与 A1 同时处理原始文本
```

---

## 输出

```python
fact_inference_map: {
    "facts":        ["有两个孩子", "约 130 平米"],
    "inferred":     ["孩子需要独立房间（推断）"],
    "preferences":  ["温馨风格", "预算控制倾向"]
}
```

---

## 激活条件

S1 强制执行，与 A1 并行运行（两者互不依赖，可同时进行）。

---

## 用户交互

**无**。后台静默，结果写入内部状态。

---

## 协作关系

```
上游（依赖）：用户原始输入（无武器依赖）

下游（供给）：
  → F2 根本需求追溯器（只在 [FACT] + [PREFERENCE] 层面追溯，不追溯推断）
  → D2 约束条件识别器（[FACT] 类约束是最高优先级约束）
  → G3 空字段自动兜底（[INFERRED] 类值填写时统一标注来源）
```

---

## 常见误用

把 `[INFERRED]` 内容传给 B1 时当 `[FACT]` 使用，导致任务定义基于未经验证的推断。

---

## 扩展优化方向

- **置信度分层**：不只是三类，而是加置信度评分（0.0~1.0），高置信推断 vs 低置信推断处理方式不同
