# F6 — 深层动机追问器

> **组别**：F 组（后台引擎）| **阶段**：S1 | **类型**：后台·A1 完成后
> **原始编号**：L4.5 五层追问

---

## 一分钟定义

通过五层内部追问，**推断用户没有明说的真实驱动力**，为 B4（使用者身份识别）和 B1（任务目标提炼）提供「深层动因」这个难以从表面获取的维度。

---

## 功能详述

五层追问框架（内部执行，不向用户展示）：

```
第 1 层 — 行为层：用户做了什么？想做什么？
   ↓「为什么？」
第 2 层 — 目标层：这个行为要实现什么具体目标？
   ↓「为什么这件事重要？」
第 3 层 — 价值观层：这个目标背后什么价值观在驱动？
   ↓「对你来说，这意味着什么？」
第 4 层 — 身份认同层：完成这件事，会让你成为什么样的人？
   ↓「如果没做，你担心什么？」
第 5 层 — 深层动因层：最根本的驱动力 → 输出供 B4/B1 使用
```

**举例**：

```
用户说：「我想要一个有品质感的客厅」
→ 第 1 层：想要品质感的装修
→ 第 2 层：让来访的朋友留下深刻印象
→ 第 3 层：社交认可，希望被视为高品味
→ 第 4 层：在圈子里建立有品位的形象
→ 第 5 层：深层动因 = 身份认同验证（不是审美追求）
```

F6 完成的追问越深，B4 识别的身份模式越准，B1 的 JTBD 动因越有洞见。

---

## 输入

```
target_signals      # A1 识别的目标信号
preference_signals  # A1 识别的偏好信号
```

---

## 输出

```python
deep_motivation: {
    "surface_want":   "品质感客厅",
    "root_motivation": "在社交圈建立品味身份",
    "identity_hint":  "展示者模式（强烈）",
    "implication":    "设计重心应在「会被他人注意到」的焦点区域"
}
```

---

## 激活条件

A1 完成后，S1 阶段强制执行（所有项目）。

---

## 用户交互

**无**。五层追问完全在后台进行，用户不参与，不知道这个过程的存在。

---

## 协作关系

```
上游（依赖）：← A1 需求信号解析器（目标+偏好信号）
下游（供给）：
  → B4 使用者身份识别器（identity_hint 是 B4 的重要输入）
  → B1 任务目标提炼器（root_motivation 是 JTBD「因为」的原材料）
```

---

## 常见误用

追到太抽象的层面（第 5 层结论：「追求幸福生活」→ B1 无法使用），需要停在「设计动作可响应的层面」。

---

## 扩展优化方向

- **五层追问结果对比校验**：F6 追问结果和 F2 裸需求追溯结果相互验证，不一致时标注分歧
