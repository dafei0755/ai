## 一分钟定义

根据已确认约束与冻结决策，**为项目生成一份「创新边界授权书」**：明确列出哪些边界绝对不可突破（用户明确拒绝），哪些边界可突破。对可突破者附上授权声明，让专家知道自己被允许在什么范围内大胆创新。

---

## 功能详述

F9 解决一个设计执行的痛点：专家往往不知道「我到底被允许走多远」。

| 边界类型 | 来源 | 处理方式 |
|---------|------|--------|
| **绝对不可突破**（hard-stop）| D2 `never_do` | 明确列出，加粗警告，违反即驳回 |
| **硬性限制**（hard-limit）| D2 `hard_limits` | 列出，需要明确的设计合理化说明 |
| **可挑战的既有假设** | D1 核心挑战 | 生成授权声明：「允许挑战[具体假设]」 |
| **用户未明确限制的区域** | B1~C3 输出 | 生成探索授权：「[具体方向] 有探索空间」 |

---

## 输入

```
confirmed_constraints   # D2 完整三级约束清单
tension_decisions       # S4 冻结的张力决策
core_challenges         # D1 输出的核心挑战
problem_framework       # B1 等 S2 核心输出
```

---

## 输出

```python
innovation_authorization: {
    "absolute_boundaries": [
        "不得提议推倒重建（业主明确保留原结构）",
        "预算严禁超过 60 万（硬限无弹性）"
    ],
    "authorized_to_challenge": [
        "允许挑战：餐厅必须独立成区的假设",
        "允许挑战：工作区必须有门的假设（用声学方案替代物理隔断）"
    ],
    "open_exploration_zones": [
        "入口仪式感方案：完全开放，无历史限制",
        "材料选择：超出常规，只要符合哮喘约束"
    ]
}
```

## 激活条件

S3 冻结候选形成后，且 feasibility 结果允许继续时，在 S4 确认任务书前与 F8 同时后台运行。

---

## 用户交互

**无**。授权书直接进入 project_director，不对用户展示。

---

## 协作关系

```
上游（依赖）：← D2 三级约束 ← D1 核心挑战 ← S4 冻结决策
下游（供给）：→ project_director（专家调度包含此授权书）
              → 与 F8 question list 打包交付
```

---

## 关键约束

**D2 的 never_do = F9 的 absolute_boundaries（完全继承，不得修改）**。F9 只负责格式化输出，不重新判断边界。

---

## 常见误用

在 F9 的「可挑战」列表里加入 D2 明确列为 never_do 的项目（绝对禁止，会误导专家越界）。

---

## 扩展优化方向

- **人机确认**：将 F9 授权书作为 S4 任务书确认协议的一部分展示，让用户知道专家在什么范围内工作
