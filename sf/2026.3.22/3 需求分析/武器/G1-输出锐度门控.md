# G1 — 输出锐度门控

> **组别**：G 组（质量门控）| **阶段**：全流程 | **类型**：门控·拦截器
> **原始编号**：Q1 输出锐度检查 | **消费方**：所有互动武器（B/C/D/E 组）

---

## 一分钟定义

**检查所有即将展示给用户的输出是否具备锐度**（明确、可执行、无内部矛盾），**不合格则拦截并触发重生成，不暴露给用户**。

---

## 功能详述

G1 是语义质量过滤器，拦截三类输出缺陷：

| 缺陷类型 | 判断标准 | 典型坏例 |
|---------|---------|---------|
| **模糊**（Vague）| 含有套话词汇（见 F5 清单）或无法被具体行动回应 | 「注重舒适体验的生活方式」 |
| **不可执行**（Non-actionable）| 没有具体行动方向，设计师无法据此做决策 | 「需要一个好的方案」 |
| **自相矛盾**（Contradictory）| 与同一轮对话中已确认的信息冲突 | 先说「工作区优先隔音」后又说「建议完全开放式工作区」 |

---

## 输入

```
pending_output        # 任意即将展示给用户的互动武器输出
confirmed_context     # 当前已确认的状态（用于矛盾检查）
```

---

## 输出

```python
gate_result: {
    "pass": bool,
    "fail_reason": str | None,    # "vague" | "non_actionable" | "contradictory"
    "flagged_segment": str | None # 具体问题片段
}
```
- **pass=True**：放行，输出可正常展示
- **pass=False**：拦截，触发原武器重生成；重生成后再次经过 G1

---

## 激活条件

**B 组 / C 组 / D 组 / E 组**的任何武器，在输出展示给用户之前，必须先通过 G1。

---

## 执行方式

```
互动武器输出 → G1 检查 → pass → 展示给用户
                         → fail → 原武器 regenerate(fail_reason) → G1 再次检查
                                   （最多 2 次重试，仍失败则降级：展示简化版输出 + [低置信度标记]）
```

---

## 用户交互

**无**。G1 是透明后台过滤器，用户从不感知。

---

## 协作关系

```
上游（被检查）：← B1/B2/B3/C1/C2/C3/D1/D2/E1 的输出
下游（放行至）：→ 用户界面
               → F5 套话替换过滤器（G1 过滤后，F5 再替换套话）
```

---

## 重要设计决策

G1 和 F5 的分工：
- **G1 检查「整体输出是否锐利」**（结构层面）
- **F5 检查「表述是否有套话」**（措辞层面）
- 执行顺序：G1 通过 → F5 过滤 → 输出

---

## 常见误用

1. 把 G1 检查失败和重生成的过程展示给用户（「正在优化输出…」之类的提示），增加焦虑感，应该静默处理
2. 对 G 组自身的输出（如 G2 报告、G3 兜底结果）再次跑 G1（没有意义，G 组输出不面向用户）

---

## 扩展优化方向

- **动态锐度阈值**：B4 识别为「决策者」时提高锐度要求（更少冗余），识别为「探索者」时适当允许更多视角性表述
