# Y2 — 城市治理利益网络解析器

> **组别**：Y 组（战略升级·新增）| **阶段**：S2/S3 | **类型**：互动·城市/治理项目专用
> **优先级**：P0 | **触发条件**：X1 判断为 `城市/区域型` | **消费方**：C2、D1、S4

---

## 一分钟定义

针对城市更新、社区改造、政府主导示范项目，**把问题从“空间需求”提升为“治理网络”**：识别谁受益、谁受损、谁拍板、谁会阻碍、谁必须被先对齐。

---

## 功能详述

Q151–Q180 这类项目失败，往往不是因为空间做得不美，而是因为**利益结构没有被看见**。老居民、街道办、开发主体、运营方、商户、游客、年轻品牌、原住民——每一方都在拉扯项目方向。

Y2 不是画普通 stakeholder map，而是要输出**治理网络图**。

### 四层网络

| 层级 | 关注问题 | 输出 |
|-----|---------|------|
| **权力层** | 谁能拍板？谁能否决？ | `power_nodes` |
| **收益层** | 谁从项目中获得利益？ | `benefit_nodes` |
| **阻力层** | 谁最可能反对？为什么？ | `resistance_nodes` |
| **合法性层** | 项目对外靠什么获得社会正当性？ | `legitimacy_story` |

### 典型输出示例

```python
governance_network: {
    "power_nodes": ["区政府", "街道办", "平台公司"],
    "benefit_nodes": ["新品牌商户", "本地居民", "游客经济"],
    "resistance_nodes": [
        {"actor": "原底商", "risk": "租金上涨导致被替换"},
        {"actor": "老居民", "risk": "日常生活肌理被旅游化侵蚀"}
    ],
    "legitimacy_story": "不是商业改造，而是以社区服务能力提升为先导的温和更新",
    "must_align_first": ["街道办", "原居民代表", "核心运营方"]
}
```

### 为什么它重要

因为城市/治理题的核心并不是：
- 用什么材料
- 入口怎么做

而是：
- 谁会支持
- 谁会反对
- 先对齐谁
- 以什么叙事让项目有合法性

## 输入

```
client_type_profile     # X1：城市/区域型
project_brief           # 项目简报
raw_input_text          # 原始描述
C2_outputs              # 如已有多方利益梳理，可吸收
```

---

## 激活条件

- X1 判断为 `城市/区域型`
- 项目包含：政府、社区、开发、更新、示范区、街区、新区、乡村振兴等语义

---

## 用户交互

**有（最多 2 个问题）**。核心是识别“谁会反对”：

> 「如果这个项目推进最快，但引发最大反弹，最可能先站出来反对的是谁？」

---

## 协作关系

```
上游（依赖）：← X1 城市/区域型判断 ← C2 多方利益梳理
下游（供给）：→ D1（挑战治理前提）
             → S4（不是冻结风格，而是冻结治理优先级）
             → Y4（决策推进路径按 must_align_first 排序）
```

---

## 常见误用

1. 把 Y2 当作普通的 stakeholder list（Y2 必须输出谁会阻碍、为何阻碍、如何获得合法性）
2. 用商业零售项目的竞争逻辑替代城市更新的治理逻辑（两者不是同一类问题）
