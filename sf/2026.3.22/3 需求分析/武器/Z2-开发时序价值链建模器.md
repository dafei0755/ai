# Z2 — 开发时序价值链建模器

> **组别**：Z 组（城市底盘·新增）| **阶段**：S2/S3 | **类型**：后台·开发逻辑解析器
> **优先级**：P0 | **触发条件**：开发区、新区、旧改、复合地产类项目 | **消费方**：Y1、Y3、Y4

---

## 一分钟定义

把项目放进**开发时序与价值兑现链条**中理解：谁先投、谁后赚、什么节点回收价值、什么节点最怕出错，防止系统把开发项目误判成单次设计命题。

---

## 功能详述

很多区域开发和更新项目，真正决定方向的不是美学，而是：
- 哪一步先做
- 哪一步回款
- 哪一步造势
- 哪一步建立信心

Z2 的任务，就是给项目建立一条**价值链时间轴**。

### 两条主线

| 主线 | 核心问题 | 输出 |
|-----|---------|------|
| **开发时序线** | 哪些节点必须先发生？ | `development_timeline` |
| **价值兑现线** | 项目的价值在哪些节点开始显现？ | `value_realization_chain` |

### 典型输出

```python
development_value_model: {
    "development_timeline": [
        "先做样板公共界面建立外部信心",
        "再导入首批标志性业态",
        "随后释放二期招商与地产溢价"
    ],
    "value_realization_chain": [
        "短期：社交媒体曝光与到访热度",
        "中期：招商转化与租金信心",
        "长期：区域品牌与资产溢价"
    ],
    "critical_sequence_risks": [
        "若先做大体量招商后做公共界面，项目吸引力不足",
        "若没有样板先行，市场对概念信任不足"
    ],
    "cashflow_sensitivity_nodes": ["入口样板段", "首店引入节点", "主公共空间"]
}
```

### 为什么重要

因为开发类项目不是“把空间做好”就结束，而是“通过空间组织，推动价值按顺序兑现”。

---

## 输入

```
project_brief           # 开发/更新/新区/复合体描述
client_type_profile     # X1 输出
Y1_strategy_profile     # 机构战略意图（如有）
```

---

## 激活条件

- 检测到：新区 / 开发区 / 旧改 / 复合体 / 招商 / 溢价 / 样板 / 首开 / 分期
- 或客户目标中包含显性资本化、招商、资产增值语义

---

## 用户交互

**有（最多 1 个问题）**。  
用于确认价值兑现优先级：

> 「如果只能先证明一件事来带动后续开发，您更需要先证明‘有人来’，还是先证明‘有人愿意付钱’？」

---

## 协作关系

```
上游（依赖）：← Y1 战略意图 ← Z1 政策目标树
下游（供给）：→ Y3（高风险假设往往在时序节点上）
             → Y4（推进顺序以 development_timeline 为骨架）
             → X7（商业可行性需要嵌入时序）
```

---

## 常见误用

1. 把 Z2 理解成单纯施工排期（Z2 关心的是价值兑现顺序，不是工程进度表）
2. 只看最终形态，不看样板/首开/试运营节点

---

## 扩展优化方向

- 引入“阶段性信心指数”模型，帮助判断哪个节点最值得重投建立市场信心
