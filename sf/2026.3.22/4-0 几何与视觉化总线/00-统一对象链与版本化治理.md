# 统一对象链与版本化治理（中轴文档）

> 日期：2026-03-25  
> 作用：作为 `4-1 平面图` 与 `4-2 视觉化呈现` 的共同总纲与术语基线。  
> 适用范围：室内优先，可扩展至建筑/场地/社区/城市。

---

## 1. 统一总线（唯一主干）

```text
UrbanContextBaseline
→ SiteContextBaseline
→ BuildingCarrierBaseline
→ AlignedBrief + SPG
→ FloorPlanIR
→ ElevationIR
→ Massing3DIR
→ VizSpec
→ VizDeliveryPack
→ InitialDesignPack / DeliveryBundle
```

三层真相：

1. 语义真相：`AlignedBrief + SPG`  
2. 几何真相：`FloorPlanIR + ElevationIR + Massing3DIR`  
3. 感知投影：`VizSpec + VizDeliveryPack`

治理铁律：上层约束下层，下层不得反写上层。

---

## 2. 节点与权限边界

- **Node3**：定义问题并冻结语义真相；
- **Node4.3**：几何编译 + 感知挂载；
- **Node4.4**：审阅、门禁、冻结、回写。

若视觉反馈触及上位结构（分区/流线/核心约束）：

- 必须回退 Node3；
- 不允许在 Node4 静默改题。

---

## 3. 三分法对象化（强制）

统一分类：

- `hard_fixed`
- `built_in_system`
- `soft_movable`

对象链要求：

- 三分法标签必须贯穿 `FloorPlanIR -> ElevationIR -> Massing3DIR -> VizSpec`；
- 任一层丢失分类标签即视为治理违规；
- `System 门` 对半固定系统完整性负主责。

---

## 4. 五门制治理（统一法庭）

1. **Contract 门**：绑定、版本、来源、越权；
2. **Geometry 门**：平面-立面-3D 一致性；
3. **System 门**：半固定系统完整性与可施工性；
4. **Perception 门**：风格/色彩/材质/光照/镜头叙事；
5. **Delivery 门**：交付完整性、可追溯性、可回写性。

说明：

- 平面分册与视觉分册共享同一五门制定义；
- 允许门内实现策略差异，不允许门级定义冲突。

---

## 5. 版本链与变更协议

版本规范：

- `spg_version`
- `ir_version`
- `viz_version`
- `deployed_version`

变更协议（`feedback_protocol`）：

1. 接收反馈请求；
2. `impactScope()` 评估影响层；
3. 局部影响走 Node4 内迭代；
4. 上位结构影响回退 Node3 升版；
5. 全程记录 diff/patch 与审计日志。

---

## 6. SpaceTree 接入策略（同源，不并行）

`SpaceTree` 若启用，作为 `SPG` 的结构视图与焦点机制：

- 共享 `zone_id`；
- 不形成并行真相源；
- 作为策略激活入口（`focusNodeId`）驱动上下文注入。

---

## 7. 术语统一表（摘要）

| 术语 | 统一写法 | 说明 |
|---|---|---|
| 空间程序图谱 | `SpatialProgramGraph (SPG)` | 全称+缩写并列 |
| 平面真相源 | `FloorPlanIR` | 几何中间表示 |
| 流线 | `circulation_path` | 推荐单数模型命名 |
| 三维壳体 | `Massing3DIR.shell` | 几何壳体阶段 |
| 三维场景 | `Massing3DIR.scene` | 场景挂载阶段 |
| 视觉参数层 | `VizSpec` | 感知参数，不改几何 |
| 视觉交付层 | `VizDeliveryPack` | 最终投影交付 |
| 越权阻断 | `contract_validation_gate` | Contract门执行点 |
| 反馈协议 | `feedback_protocol` | 统一回写与回退路径 |

---

## 8. 硬约束与实现候选

硬约束（必须）：

- 统一总线；
- 版本链追溯；
- 三分法对象化；
- 五门制治理；
- 回退规则。

实现候选（可替换）：

- 外部工具（Maket/插件等）；
- 渲染/3D 引擎；
- 文件格式栈（在不破坏对象契约前提下）。

---

## 9. 一句话总纲

**方案高参的下一步不是“更会出图”，而是“更会维护一个可计算、可验证、可回退的设计世界状态”。**
