## 0. 文档定位与硬约束

本文是“几何—感知统一总线”中的**平面编译分册**，只负责把冻结语义编译成可计算几何真相，不负责视觉表达裁决。

硬约束：

1. Node3 冻结 `BuildingCarrierBaseline + AlignedBrief + SPG`，Node4 仅派生执行；
2. 下游不得反写上游（视觉层无改题权）；
3. 任意交付需可追溯到同一版本链（`spg_version -> ir_version -> output_version`）；
4. 所有空间产物必须绑定 `zone_id/module_id`；
5. `FloorPlanIR` 必须同时绑定 `spg_version` 与 `building_carrier_ref`，缺少任一则视为编译未完成，ContractValidator 阻断后续门禁流程。

### 0.1 任务接入模式与外部数据边界（原则级）

1. 平面分册支持两类接入：
  - **全链路接入**：按主链冻结后执行平面编译；
  - **片段辅助接入**：用户仅提出局部平面问题（如局部流线优化、局部分区调整），系统按同一对象契约承接。
2. 片段辅助接入仅缩小任务范围，不降低治理要求：凡进入正式版本的平面结果，必须满足 `spg_version`、`building_carrier_ref`、`zone_id/module_id` 绑定；
3. 外部输入（CAD/BIM/图片）是合法入口，但必须先编译为 `BuildingCarrierBaseline draft` 或 `FloorPlanIR draft`，不得直接覆盖冻结对象；
4. 本平台负责“编译、校验、回写建议”，不负责替代外部绘图工具的全流程控制与最终出图生产组织。

## 1. 平面问题的本质：编译，不是画图

平面图难点不在“出图模型”，而在“是否存在稳定中间表示”。

统一总线中的平面链路：

```text
BuildingCarrierBaseline（建筑载体约束：结构/机电/层高/轮廓）
       ↘
        FloorPlanIR（几何真相）→ PNG / SVG / DXF / 3D-shell（多格式投影）
       ↗
SPG（语义宪法：分区/流线/功能矩阵）
```

结论：**平面图是建筑载体约束下、冻结语义的几何真相编译产物，不是视觉层。**

---

## 2. 版本化与世界模型就绪承诺

为向“设计编译器式世界模型”演进，平面层必须满足：

- 有状态：`FloorPlanIR` 可作为可查询状态；
- 有变更：通过 diff/patch 变更，不做整包重写；
- 有验证：变更后自动触发门禁；
- 有回退：触碰上位约束时自动回退 Node3。

版本字段规范：

| 字段 | 说明 |
|---|---|
| `spg_version` | 来源语义版本（Node3 冻结版本） |
| `ir_version` | 当前平面 IR 版本 |
| `deployed_version` | 下游交付版本（PNG/SVG/DXF/3D） |
| `frozen` | 是否进入冻结态（冻结后只能升版，不能覆写） |

---

## 2.5 世界模型贯穿（平面层）

平面分册中的“世界模型”不是抽象口号，而是可执行的状态机闭环：

```text
State（SPG/FloorPlanIR 当前状态）
  → Action（变更提议：改分区/改流线/改开口/改尺度）
  → Prediction（impactScope 影响范围评估）
  → Validation（五门制门禁）
  → Commit or Rollback（提交升版或回退 Node3）
```

平面层职责：

1. 承担可计算状态（`FloorPlanIR`）；
2. 承担结构动作与几何约束传播；
3. 输出可审计的差异记录（diff/patch），不做整包重写。

这意味着平面层不仅“能出图”，还必须“能预测改动后果并可回滚”。

## 3. FloorPlanIR 对象契约（含三分法对象化）

## 3.1 角色边界

- **输入**：冻结 `SPG` + 冻结 `BuildingCarrierBaseline`（可选：同源 `SpaceTree` 视图焦点）；
- **输出**：几何真相 + 约束关系 + 可追溯版本；
- **禁止**：直接消费自由文本绕过 SPG；直接消费建筑载体原始数据（CAD/BIM/文字描述）绕过 `BuildingCarrierBaseline` 对象；直接写回上游冻结对象。

## 3.2 核心字段（统一术语版）

| 字段组 | 字段名 | 说明 |
|---|---|---|
| 几何基础 | `boundary` / `orientation_north_deg` | 外轮廓与朝向 |
| 结构约束 | `core_constraints` / `openings` | 承重、管井、洞口 |
| 拓扑关系 | `adjacency_matrix` / `access_graph` / `circulation_paths` | 邻接、可达、流线 |
| 尺度约束 | `size_ranges` | 分区尺寸下限与目标 |
| 几何原语 | `geometry_primitives` | 墙线/多边形/轴网 |
| 三分法映射 | `zone_3parts_mapping` | `zone_id -> {hard_fixed,built_in_system,soft_movable}` |
| 治理字段 | `spg_version` / `ir_version` / `frozen` / `source_refs` | 版本与来源追踪 |
| 建筑载体绑定 | `building_carrier_ref` / `building_carrier_version` | 来源 BuildingCarrierBaseline 的唯一引用 + 版本号；缺失则 ContractValidator 阻断 |
| 校验字段 | `validation_errors` / `validation_warnings` | 门禁输出 |

## 3.3 总线约束与越权阻断

`ContractValidator` 在平面层至少执行以下阻断：

1. 缺失 `zone_id/module_id` 绑定；
2. 缺失版本来源追溯；
3. 跨区越权（策略作用域与分区不一致）；
4. 视觉/外部输入试图直接改写几何真相。

## 4. Node4.3 平面编译执行链

```text
BuildingCarrierBaseline（frozen）
  ↘
   FloorPlanIRCompiler.compile_from_baselines()
  ↗
SPG（frozen）
  → SpaceTree.sync_to_spg_bindings(...) [若启用SpaceTree]
  → 五门制校验（先Contract/Geometry/System）
  → 输出 PNG/SVG/DXF/3D-shell
```

说明：

- 两个上游对象（`BuildingCarrierBaseline` 与 `SPG`）均须在 Node3 冻结后才能启动编译；`building_carrier_ref` 未绑定则 ContractValidator 阻断，不得进入后续门禁；
- `SpaceTree` 仅作为 SPG 同源结构视图，不形成并行真相源；
- 图像生成必须通过 `FloorPlanImagePromptBuilder` 注入约束，不得直接读取自由文本改题。

### 4.1 CAD/外部平面输入执行链（流程级）

当用户从外部工件切入（而非从 Node1 起步）时，按以下流程执行：

`CAD/PDF/图片` → `ArtifactImportRequest` → `FloorPlanIR draft` / `BuildingCarrierBaseline draft` → 结构校验与风险标注 → 任务路由（片段/临时/正式）

外部底图不得走“上传底图 → 直接生成正式 FloorPlanIR”的单段式链路。底图必须先进入平面编译器候选链：

```text
CAD/PDF/图片
  → PlanCanvasBaseline
  → DetectionLayers / De-clutter
  → WallGraph / ColumnSet
  → Opening Binder
  → Space Topology Solver
  → Contract / Geometry / System Gate
  → Reviewed FloorPlanIR
```

在 Gate 通过前，系统只能展示“候选层 / 复核队列”，不得把识别候选包装为正式 `FloorPlanIR`。详细编译契约与 v0.1 实施边界见 `03-底图到FloorPlanIR精准编译方案-v1.0.md`。

最小执行规则：

1. 导入后必须生成 `parsed_confidence` 与 `missing_constraints`；
2. 仅当绑定合法来源（`draft_ref` 或 `source_frozen_id`）后，才可进入专题执行；
3. 若仅做局部优化，可停留片段任务工作区并导出建议，不强制转正；
4. 若要进入正式交付，必须补齐最小上游约束并通过 Gate。

转正判定（平面层）：

1. 已完成 `building_carrier_ref` 绑定；
2. 已声明 `spg_version`（正式版本或待转正候选）；
3. 已完成 `zone_id/module_id` 映射；
4. 若触及结构改动，已提交 `Impact Matrix`。

## 5. 三阶段产出（平面分册）

| 阶段 | 主产出 | 核心目标 | 冻结节奏 |
|---|---|---|---|
| Phase A | 概念平面（PNG） | 语义可沟通 | hard_fixed 初锁 |
| Phase B | SVG + DXF | 工程可编辑 | hard_fixed + built_in_system 锁定 |
| Phase C | 3D-shell | 体量一致性 | soft_movable 仍可后置调整 |

---

## 6. 五门制在平面层的落位

1. **Contract 门**：绑定、版本、来源、越权；
2. **Geometry 门**：平面几何合法性、闭环、开口可达；
3. **System 门**：半固定系统承接是否完整（接口点、检修、可施工性）；
4. **Perception 门**：平面阶段仅做最低限度风格约束一致性检查；
5. **Delivery 门**：输出文件完整且带版本索引。

---

## 7. 反馈协议与回退判定

平面层反馈统一走 `feedback_protocol`：

1. 接收 `VizFeedbackRequest` 或 CAD/3D 侧反馈；
2. 先跑 `impactScope()` 判定影响范围；
3. 若仅影响视觉参数 → Node4 内迭代；
4. 若影响结构/流线/分区 → 回退 Node3 升版 `SPG`。

---

## 8. 实施边界（实现候选与硬约束分离）

- 硬约束：对象链、版本链、门禁、回退规则；
- 实现候选：具体外部工具、渲染器、CAD引擎、3D引擎；
- 原则：工具可替换，对象契约不可漂移。

## 8.5 扩展路线图（平面层视角：室内→建筑/城市）

结论：**需要在本分册体现**，但只保留“平面编译相关”的最小版本，详细内容以 `4-2 视觉化呈现` 与中轴文档为准。

### 阶段 1（当前）：三输入主线稳定

- 以 `BuildingCarrierBaseline × SPG → FloorPlanIR` 为核心，打稳平面几何真相层；
- 保证 `building_carrier_ref` 绑定、`zone_3parts_mapping`、版本链、五门制全部可执行；
- Node1 强制采集 `building_carrier_pin`（新建/改造/扩建、楼层数、面积、是否有底图、结构/机电限制），Node3 编译 `BuildingCarrierBaseline v1.0` 并冻结；
- 平面层增加"hard_fixed 不可变更边界"（承重/管井/洞口）与"soft_movable 可改造范围"标注，双向约束由 BuildingCarrierBaseline 驱动。

### 阶段 2：场地与景观扩展

- 引入 `SiteContextBaseline`（地形、日照、风环境、出入口）；
- 平面流线与场地动线做一致性校验；
- 地理基线（GeoCoordinateBaseline）中已有的 geo_constraints 与 Site 层协同，避免重复采集。

### 阶段 3：社区与城市扩展

- 引入 `UrbanContextBaseline`（道路、公共服务、邻里界面）；
- 平面分区策略与城市运营约束做同源校验。

扩展原则：

1. 不改 Node1~Node4 主链编号；
2. 通过上游 Baseline 注入约束，而非重写 `FloorPlanIR` 核心语义；
3. 任一上游约束变更必须走版本化与回退规则。

## 9. 最终判断

**平面图是几何真相层的编译产物，不是感知层的美化草图。只要版本链、三分法映射、五门制成立，后续立面/3D/视觉化才不会漂移。**

只有同时冻结建筑载体（`BuildingCarrierBaseline`），平面的"编译"才能摆脱真空态，成为真正约束下游 3D 与视觉化的几何宪法。**平面不是画图，而是编译；编译不能在真空里进行。**
