> 日期：2026-04-13

## 0. 结论

平面沙盘不是轻量 CAD，也不是 AI 生图浮层，而是方案高参体系中的 **AI 平面方案推演工作台**。

它位于项目驾驶舱与方案画布之间：

```text
项目驾驶舱
AlignedBrief + SpatialProgramGraph (SPG) + 资料 / 约束 / 项目判断
        ↓
平面沙盘
FloorPlanIR / 多方案推演 / 指标校核 / 版本冻结
        ↓
方案画布
ElevationIR / Massing3DIR / VizSpec / 视觉表达
        ↓
项目驾驶舱
策略 / 指标 / 风险 / 决策 / 成果回写
```

平面沙盘的价值不是“画得快”，而是把平面方案从一张图变成可计算、可比较、可解释、可回退、可沉淀、可继续驱动下游表达的项目决策资产。

---

## 1. 主架构

页面结构必须与方案画布保持一致：

```text
左侧：平台模块导航
中间：平面沙盘主画布
右侧：方案高参对话窗口
```

### 1.1 左侧

左侧保持平台级导航，不改成平面沙盘专属图层面板。

保留模块：

- 项目驾驶舱
- 空间
- 平面沙盘
- 方案画布
- 思维参谋
- 资源雷达
- 灵感仓库
- 梦幻团队

原因：平面沙盘是项目工作流中的一个模块，不是独立绘图软件。左侧如果改成图层 / 参数 / 约束面板，会破坏全平台统一结构。

### 1.2 中间

中间是唯一主舞台，承载：

- 平面底图
- 功能分区
- 空间模块
- 主客流 / 服务流 / 后勤流
- 风险标记
- 方案版本
- 局部优化范围
- 方案控制卡

参数、指标和方案卡片都集中在中间画布的 **方案控制卡** 中，不放到右侧。

### 1.3 右侧

右侧固定为统一的 **方案高参对话窗口**。

职责：

- 读取当前模块上下文；
- 解释当前方案逻辑；
- 接收自然语言修改指令；
- 预测改动影响；
- 提醒风险；
- 生成回写驾驶舱的结论；
- 组织下一步动作。

右侧不承担参数面板、方案卡列表、指标表职责，避免所有工作都被压进对话。

## 2. 产品定义

平面沙盘是方案高参体系中的 AI 平面方案推演工作台。

它读取项目驾驶舱中的项目目标、空间画像、资料、约束和阶段判断，将上游语义信息编译为可计算、可推演、可验证、可回退的 `FloorPlanIR`，并在中央画布中完成多方案生成、参数调节、指标比选、局部优化和版本冻结。

确认后的方案策略、指标、风险和成果回写项目驾驶舱，形成项目级决策资产。

## 3. 与参考意见的交叉校验

### 3.1 应采纳的共识

两份参考意见共同指出：

1. 平面沙盘不是 CAD；
2. 平面沙盘不是纯图片生成器；
3. 用户操作对象应从“线段 / 图层”转向“目标 / 关系 / 权重 / 分区 / 流线”；
4. 平面层要有结构化中间表示；
5. 方案结果要可比较、可验证、可回退。

这些判断与现有几何总线一致，应完整采纳。

### 3.2 参考 1 的采纳点

参考 1 的系统工程判断成立：

- 平面沙盘是 Node4 中的几何决策层；
- 上游读取 `AlignedBrief + SPG`；
- 中间维护 `FloorPlanIR`；
- 下游投影为 PNG / SVG / DXF / 3D-shell；
- 修改必须支持 `State -> Action -> Prediction -> Validation -> Commit/Rollback`；
- 触及上位结构时必须回退 Node3。

这些内容应作为技术骨架。

### 3.3 参考 2 的选择性采纳点

参考 2 的交互启发成立：

- 功能泡泡适合概念阶段；
- 权重滑杆适合轻量控制；
- 流线热力图适合表达行为模拟；
- Prompt Anchor 可作为方案画布的结构控制输入。

但不采纳“平面沙盘是方案画布左下角浮层”的产品形态。

原因：

1. 与既定左中右主架构冲突；
2. 会削弱平面沙盘作为几何决策层的独立性；
3. 容易让用户误解为生图辅助层；
4. 不利于承接驾驶舱与回写驾驶舱。

替代方案：

> 平面沙盘保持独立模块，但向方案画布输出语义骨架控制网。

## 4. 方案控制卡

方案控制卡是中间画布中的结构化决策容器，集中承载原本容易分散到右侧和底部的信息。

### 4.1 项目继承区

从项目驾驶舱读取：

- 项目名称；
- 空间类型；
- 项目定位；
- 设计目标；
- 使用人群；
- 已上传资料；
- 图纸 / 参考素材；
- 预算 / 工期；
- 结构 / 物业 / 规范限制；
- 已确认的项目判断。

示例：

```text
项目：大堂更新
空间类型：公共接待空间
来源：项目驾驶舱
目标：轻、克制、自然、低干预
约束：保留原空间关系，避免大拆改
资料：原始图纸 1 张，现场图 6 张，参考图 8 张
```

### 4.2 推演任务区

明确当前平面沙盘要解决的问题：

```text
当前任务：
优化大堂的入口识别、接待关系、等候舒适度和服务动线。

推演重点：
- 接待前置但不压迫入口；
- 等候区靠近采光面；
- 后勤动线隐藏；
- 避免大面积造型干预。
```

### 4.3 参数权重区

参数只保留少量决策型滑杆。

通用参数：

- 空间开放度；
- 功能密度；
- 动线效率；
- 展示强度；
- 体验舒适度；
- 改造强度；
- 成本控制；
- 驾驶舱匹配度。

空间类型专属参数：

| 空间类型 | 专属参数 |
|---|---|
| 住宅 | 家庭互动、收纳强度、家务效率、空间弹性、私密梯度 |
| 办公 | 工位效率、协作强度、专注安静度、访客展示性、部门邻近度 |
| 商业 | 客流覆盖、铺位坪效、停留体验、主力引流、后勤效率 |
| 餐饮 | 翻台效率、桌型组合、前后场分流、等位体验、外卖干扰 |
| 展厅 | 叙事强度、展线完整度、核心展项突出、洽谈转化、拥堵风险 |
| 大堂 | 到达识别、等候舒适、服务可达、空间克制度、后勤隐藏度 |

### 4.4 指标摘要区

指标服务决策，不做后台报表。

示例：

```text
当前方案评分
入口识别：86
服务可达：84
等候舒适：80
动线效率：88
改造强度：低-中
实施风险：低
驾驶舱匹配：90
```

`驾驶舱匹配` 是关键指标，用于判断当前方案是否偏离上游项目定义。

### 4.5 方案版本区

方案卡片集中在控制卡内：

```text
A 低干预更新
保留空间秩序，优化接待、等候和导视。

B 到达体验强化
增强入口识别和第一印象，适合展示型需求。

C 运营效率优先
优化服务台、后勤、人流停留和管理关系。
```

点击不同方案，中央画布切换，右侧方案高参同步解释。

### 4.6 决策动作区

保留明确动作：

- 新建推演版本；
- 冻结当前版本；
- 对比 A/B/C；
- 回写项目驾驶舱；
- 发往方案画布；
- 导出成果；
- 回退上一版。

## 5. 数据闭环

### 5.1 驾驶舱传入平面沙盘

传入对象是上游共识：

```text
项目定位
空间类型
人群画像
运营目标
设计目标
资料资产
图纸底图
参考素材
已确认约束
阶段任务
预算和工期
历史决策
```

### 5.2 平面沙盘内部维护

核心对象是：

```text
FloorPlanIR
- 空间边界
- zone_id
- module_id
- 房间 / 区域几何
- 功能分配
- 面积关系
- 动线网络
- 门洞 / 开口
- 核心节点
- 约束绑定
- 指标计算结果
- 版本 diff
```

### 5.3 平面沙盘回写驾驶舱

回写的是决策级结果，不是所有试错过程：

```text
已确认方案方向
关键平面策略
核心指标
方案风险
待决策问题
后续任务
成果文件
关联版本
```

示例：

```text
已确认方向：克制入口强化

关键策略：
- 保留原空间结构；
- 用灯光和导视强化入口识别；
- 服务台保持轻体量；
- 等候区靠近采光面；
- 避免大面积装饰造型。

风险：
- 入口识别主要依赖软性手段，视觉冲击力有限；
- 等候家具尺度需在方案布置阶段继续校核。

下一步：
- 进入方案画布深化服务台、家具、灯光和材料关系。
```

原则：

> 平面沙盘保留推演过程，项目驾驶舱沉淀项目共识。

## 6. 核心交互

平面沙盘的主交互不是“画”，而是：

```text
提出意图 -> 系统推演 -> 多方案比较 -> 影响预测 -> 用户裁决 -> 冻结版本
```

用户输入示例：

```text
给我三个更克制的大堂平面策略。
保留入口识别，但降低改造强度。
把等候区移到采光更好的位置。
不要改变原服务台的大致位置，只优化周边动线。
比较 A 和 C，哪个更符合驾驶舱里的低干预目标？
冻结 B-1，并回写到项目驾驶舱。
```

用户操作对象是：

- 目标；
- 关系；
- 权重；
- 分区；
- 流线；
- 约束；
- 版本。

不是线段、图层和绘图命令。

## 7. 三种工作模式

三种模式不拆成三个页面，而是同一左中右结构下的三种工作状态。

### 7.1 对话推演

位置：右侧方案高参。

适合：

- 生成方案；
- 修改方案；
- 解释方案；
- 提醒风险；
- 提炼结论。

### 7.2 画布校正

位置：中央画布。

适合：

- 圈选局部优化区域；
- 标记保留区；
- 标记禁改区；
- 拖动功能泡泡；
- 锁定某个空间模块；
- 调整入口方向或动线节点。

功能泡泡只用于概念阶段，进入正式版本后必须落到 `FloorPlanIR` 的真实边界和模块。

### 7.3 对比裁决

位置：中央方案控制卡 + 右侧高参解释。

适合：

- 多方案并列比较；
- 指标差异；
- 版本 diff；
- 推荐方案；
- 冻结方案；
- 回写驾驶舱。

## 8. 跨空间类型适配

平面沙盘不是住宅工具，而是跨空间类型的空间推演模块。

首批建议覆盖：

1. 住宅；
2. 办公；
3. 餐饮；
4. 商业；
5. 展厅 / 大堂。

原因：

- 平面边界相对可控；
- 用户需求高频；
- 指标可解释；
- 容易证明平台不是单一住宅工具；
- 能承接后续企业版空间标准化需求。

第二阶段扩展：

- 酒店；
- 教育；
- 医疗诊所；
- 养老康养。

第三阶段扩展：

- 产业园区；
- 社区公共空间；
- 城市更新；
- 街区商业。

## 9. 执行路线

### Phase 1：页面结构与数据闭环

目标：跑通“驾驶舱读取 -> 平面推演 -> 方案控制卡 -> 高参解释 -> 回写驾驶舱”的基础闭环。

实现：

- 左中右页面结构；
- 中央平面沙盘画布；
- 方案控制卡；
- 右侧固定方案高参；
- 读取驾驶舱项目摘要；
- 生成 3 个方案方向；
- 指标摘要；
- 回写驾驶舱动作。

### Phase 2：FloorPlanIR 真相层

目标：让平面沙盘不只是图片操作，而是结构化空间数据。

实现：

- 空间边界；
- `zone_id/module_id`；
- 功能模块；
- 面积统计；
- 邻接关系；
- 动线网络；
- 版本记录；
- diff / rollback；
- SVG / PNG 输出。

### Phase 3：多空间类型模板

目标：证明平台是跨空间类型推演平台。

实现：

- 每类空间的专属参数；
- 每类空间的专属指标；
- 每类空间的方案策略；
- 每类空间的风险提示；
- 每类空间的回写字段。

### Phase 4：行为模拟与方案画布接口

目标：让平面沙盘成为后续视觉表达的控制骨架。

实现：

- 人流 / 客流 / 服务流模拟；
- 热力图；
- 拥堵风险；
- 可视性分析；
- 语义分区图；
- 给方案画布的 Prompt Anchor；
- 给效果图生成的控制图；
- 3D-shell 输出。

## 10. MVP 禁区

首版不要做：

- CAD 式完整绘图工具；
- 复杂图层系统；
- 精细施工图；
- 家具级自动排布；
- 实时全局仿真；
- 全空间类型一次性覆盖；
- 纯图片生图；
- 所有项目问题都塞进右侧对话。

首版必须守住：

- 驾驶舱上下文读取；
- 中央画布方案推演；
- 右侧高参解释；
- 方案控制卡集中参数和指标；
- 多方案比较；
- 决策回写驾驶舱；
- 结构化 `FloorPlanIR` 方向。

2. 更新 `frontend-nextjs/components/PlanSandboxPanel.tsx`：

   - 将参数、指标、方案卡、版本链集中到方案控制卡；
   - 保留右侧统一方案高参作为对话窗口；
   - 增加“回写项目驾驶舱”“发往方案画布”“发送给右侧高参解释”等动作；
   - 以本地版本链模拟 `FloorPlanIR` 推演和冻结状态。
3. 更新 `FloorPlanIR` 前端真实数据方式：
   - 清除旧的硬编码 `FloorPlanIRSimulation` 模拟数据；
   - 平面沙盘只读取 `ipa.space.plan-topic.v1.{sessionId}` 中当前空间的 `reconstruction.elements`；
   - 上传真实底图后，支持在大画布上框选“主平面识别区”，点击“生成 IR”时把该区域作为服务端追踪范围；
   - `/api/floor-plan/trace` 从 PDF / DXF 提取矢量墙线，并基于墙线轨道检测闭合房间单元；
   - 识别结果写回同一份 `spacePlanTopics` 数据源，与方案画布共享；
   - 画布仅渲染真实 `wall_trace / function_zone / space_boundary / door / window` 对象；
   - 没有真实重构对象时显示空状态与生成入口，不再用伪造工程图占位；
   - 右侧图纸基线卡同步显示真实闭合空间、门窗洞口、墙线对象和识别区状态。
4. 更新真实交互操作：
   - 鼠标滚轮以鼠标位置为中心缩放；
   - 按住鼠标中键拖动画布平移；
   - 缩放上限提升到 10 倍；
   - 底图可关闭，关闭后只保留 `FloorPlanIR` 工程识别层；
   - 框选识别区后，生成结果会把识别区作为 `analysis_region` 对象沉淀到 `FloorPlanIR`，便于后续回溯。

后续重点不再做假图，而是继续增强服务端识别：门窗断口、楼梯/柱/设备井、房间命名、比例尺人工校准与 `SPG zone_id/module_id` 对齐。

### 11.1 路线纠偏：从直接识别 IR 改为平面编译器

当前“点击生成 IR 后直接把墙/柱/门窗/空间对象铺到画布”的实现路线必须降级为调试候选层，不再作为正式 `FloorPlanIR` 路线。

新的执行链以 `03-底图到FloorPlanIR精准编译方案-v1.0.md` 为准：

```text
底图治理
  → 主平面区抽取
  → 去干扰分层
  → 墙图重建
  → 柱结构节点融合
  → 开口绑定
  → 空间拓扑分区
  → Contract / Geometry / System Gate
  → Reviewed FloorPlanIR
```

产品侧同步调整：

1. 未通过 Gate 的结果只显示为“编译候选”，不显示为“FloorPlanIR 已生成”；
2. 右侧面板优先显示问题桶：墙碎片、悬空墙、疑似漏柱、未绑定开口、比例尺缺失；
3. 正式 IR 层只展示 Reviewed / Gate passed 对象；
4. 近期实施优先级只做墙图与柱，不同时追求门窗和空间分区；
5. 用户交互定位为校正、复核、冻结，不发展为手工 CAD 绘图。

---

## 12. 酷家乐画布的交叉校验与转译

### 12.1 可借鉴的不是重工具，而是工程画布秩序

酷家乐画布的价值不在于工具多，而在于它把复杂空间任务压成了稳定的操作舞台：

```text
中央：工程画布
上方：全局命令
侧边：对象 / 属性 / 资源
底部：视图、楼层、缩放
```

平面沙盘应借鉴这种稳定秩序，但不能照搬其施工级工具范式。我们的目标不是“弱化版酷家乐”，而是：

```text
工程可信度接近酷家乐
操作复杂度低于酷家乐
推演与解释能力强于酷家乐
```

### 12.2 采纳项

应采纳：

- 中央大画布是主场，不能被聊天和参数面板淹没；
- 底图导入、底图显隐、透明度、比例尺校准、底图对齐是一等能力；
- 房间必须是闭合空间对象，不是色块和散线；
- 选中对象后必须进入解释模式，显示 `zone_id / module_id / area / adjacency / flow / risk`；
- 2D 为主，保留轻量 `3D-shell` 作为平面后果预览；
- 缩放层级应控制信息密度，低倍看关系，高倍看对象、尺寸、校核；
- 图纸表达必须有轴网、墙厚、门窗洞口、尺寸线、柱、楼梯、管井、图签等工程可信要素。

### 12.3 不采纳项

不应采纳：

- 大量左侧工具栏；
- 全屋硬装、厨卫定制、门窗定制、水暖电等独立深化入口；
- 家具模型库作为核心入口；
- 以拖拽、手动画墙、手动摆放为主的操作方式；
- 横向偏移、角度、材质、构件参数等密集可编辑属性面板；
- 施工图级完整深化。

这些能力会把平面沙盘带回 CAD / 家装工具路径，偏离方案高参的 AI 推演定位。

### 12.4 冲突取舍

参考意见中存在一个关键冲突：是否保留画布直接编辑。

结论是：保留“校正型交互”，不发展“手工绘图型交互”。

允许：

- 框选识别区；
- 标记禁改区；
- 标记可优化区；
- 手动闭合空间；
- 校准比例尺；
- 修正门窗识别；
- 锁定某个 zone；
- 标记“这里不要动”。

不鼓励：

- 手动画完整墙体；
- 手工排布家具；
- 手动深化施工图；
- 用属性面板精调每一个毫米级参数。

用户职责是判断、校正、冻结；AI 负责识别、推演、解释、比较和生成。

### 12.5 FloorPlanIR 的工程表达标准

当前 `FloorPlanIR` 模拟图必须从“示意关系图”升级为“工程平面 + 语义层”。

最低表达标准：

```text
1. 白色工程底纸
2. 浅灰网格
3. 图框与图签
4. 轴网与轴号
5. 外墙 / 内墙厚度
6. 墙体交接闭合
7. 门洞真实打断墙体
8. 门扇开启弧线
9. 窗洞嵌入墙体
10. 柱、楼梯、管井、湿区、设备间
11. 每个房间为闭合 polygon
12. 房间名称、面积、room_id 居中标注
13. 总尺寸与分段尺寸
14. 锁定区、可优化区、风险点
15. 客流 / 服务流轻量叠加
```

其中最重要的是第 11 条：空间必须闭合。只有闭合空间，才可以计算面积、邻接、流线、约束和版本 diff。

### 12.6 图层模型

平面沙盘应拆成可开关图层：

```text
基准底图
工程 IR
空间语义
流线模拟
风险校核
尺寸标注
```

默认策略：

```text
基准底图：开，可关闭
工程 IR：开
空间语义：轻量开
流线模拟：默认轻量
风险校核：只显示关键风险
尺寸标注：开
```

这样既保留工程可信度，又不让语义层遮挡图纸。

### 12.7 后续数据结构要求

图形不能只是 SVG 画得像工程图，底层也必须对应真实对象：

```ts
type FloorPlanIR = {
  meta: { id: string; version: string; status: 'draft' | 'validated' | 'frozen' };
  source: { type: 'pdf' | 'image' | 'dxf' | 'cad'; visible: boolean; opacity: number; scaleStatus: string };
  coordinateSystem: { unit: 'mm'; scale: number; origin: 'top_left' };
  walls: WallIR[];
  columns: ColumnIR[];
  openings: OpeningIR[];
  rooms: RoomIR[];
  stairs: StairIR[];
  lockedZones: LockedZoneIR[];
  flows: FlowIR[];
  validations: ValidationIssueIR[];
};
```

`RoomIR` 必须具备：

```ts
type RoomIR = {
  id: string;
  name: string;
  functionType: string;
  polygon: Point[];
  areaSqm: number;
  closed: boolean;
  adjacentRoomIds: string[];
  moduleId?: string;
  zoneId?: string;
  confidence: number;
};
```

### 12.8 执行结论

酷家乐给出的最低标准是“工程可信”。方案高参要在此基础上升级为“AI 决策”：

```text
酷家乐：用户画出空间
平面沙盘：AI 编译空间，用户裁决空间
```

因此当前实现优先级为：

1. 先让画布上的 `FloorPlanIR` 接近工程图；
2. 再做图层开关和底图显隐；
3. 再做选中对象后的结构化解释；
4. 最后做 AI 推演动作、版本对比和下游方案画布控制图输出。

## 13. 最终判断

平面沙盘应以既定左中右主架构为产品外壳，以 `SPG -> FloorPlanIR -> 下游投影` 为技术骨架，以功能泡泡、权重滑杆、行为模拟和 Prompt Anchor 作为局部交互增强。

它不是 CAD，也不是生图浮层。

它是项目驾驶舱和方案画布之间的几何决策层。

驾驶舱负责定义题目，平面沙盘负责把题目编译成可计算平面，方案画布负责基于平面真相继续做视觉、立面、体量和表达。
