# 2 大节点1-用户输入

> 备注（2026-03-22）：
> 本文用于展开大节点 1「用户输入」的职责、输入输出与后续可细化项。

## 节点定位

**大节点 1：用户输入**

它负责接住用户原始表达，为后续门禁与项目主链提供入口上下文。

## 核心作用

- 接收用户原始 brief
- 保留原话与原意
- 建立会话 / 项目入口
- 提取初始对象、目标、限制、场景线索
- 识别可进入后续判断的初始信号

补充口径（2026-03-26）：Node1 支持多入口接入，不默认要求“纯文本起步”。

## 输入

- 用户文本输入
- 用户附件（CAD / SU / PDF / 图片 / 草图）
- 历史对话上下文
- 已有草稿对象（如有）

### 多入口归一化（Node1 内）

Node1 对外部输入只做“接入与归一化”，不做真相判定：

1. 外部文件先进入 `ArtifactImportRequest`；
2. 生成对应 `draft` 对象（如 `FloorPlanIR draft` / `BuildingCarrierBaseline draft` / `VizObservation draft`）；
3. 记录最小元数据：`source_type`、`source_ref`、`parsed_confidence`、`missing_constraints`；
4. 归一化结果交给 Node2 做门禁与任务判型。

## 输出

- 原始 brief
- 初始结构化输入
- 入口上下文
- 可供门禁消费的基础信息
- **`geo_pin` 初始采集结果**（见下文）
- `ArtifactImportRequest` 与归一化 `draft` 对象（如适用）

## geo_pin 强制采集说明

**`geo_pin` 是 Node1 阶段唯一的强制地理字段**，须在本节点完成初始采集。

### 采集方式（满足其一即可）

| 方式 | 说明 | 优先级 |
|------|------|-------|
| 地图点选 | 用户在系统地图上直接点选项目位置 | 最高（精度最可靠） |
| 精确地址 | 精确到街道/楼盘/景区名称（系统自动地理编码） | 次选 |
| 地块/物业确认 | 上传用地红线图或输入建筑编号 | 次选 |
| 地点名称识别 | 用户说出知名地点名，系统归一后请用户确认 | 对话态临时使用 |

### 阻断规则

- **`geo_pin` 未完成且 `user_confirmed = false` → 门禁不放行，Node3 不启动**
- 用户仅提供地点名称未确认时：系统可进入对话探索状态，但生成的 `GeoCoordinateBaseline` 标记为 `provisional`，不得冻结
- 正式项目态下，`geo_pin` 的 `user_confirmed` 必须为 `true`

### geo_pin 最小字段（Node1 采集目标）

```python
class GeoPin:
    lat: float                  # 纬度 (WGS84)
    lng: float                  # 经度 (WGS84)
    address_label: str          # 用户确认的地址/地点名称
    admin_region: str           # 行政区划（省/市/区/县）
    place_name: str             # 地点标志名（楼盘/景区/片区名）
    precision_level: str        # poi / building / site / district / city
    input_method: str           # map_pin / address_text / geocoder / manual
    user_confirmed: bool        # True = 项目态；False = 对话临时态
```

> Node3.S.0 会在此基础上进一步深度编译，产出完整的 `GeoCoordinateBaseline`。
> 完整字段契约见 `4-3 世界模型/4-3-1 地理坐标/03-GeoCoordinateBaseline字段契约.md`。
