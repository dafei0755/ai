# 4 大节点3-信息对齐

> 备注（2026-03-22）：
> 本文用于展开大节点 3「信息对齐」的正式二级步骤与系统内部步骤。
>
> 说明：当前文件名仍沿用旧命名，仅作为过渡；本文现行口径以“信息对齐”为准。

## 节点定位

**大节点 3：信息对齐**

它负责把门禁放行后的原始项目输入，编译成可继续推进、可冻结、可供后续设计阶段消费的项目基线。

它不是简单的信息收集，而是一次真正的项目对齐与问题编译过程：

- 梳理显性需求
- 追问真实动机
- 明确目标与边界
- 补齐关键缺口
- 生成解题思路
- 规划工作地图
- 冻结为稳定的中间基线对象

设计行业补充口径：信息对齐不是要求“先一次定稿再设计”，而是把草图、参考图、粗模、多方案比较中形成的有效认知，编译为当前阶段可冻结的主版本。

## 核心作用

- 接住并重述原始 brief
- 明确项目目的、对象与成功标准
- 识别缺口并完成最小补齐
- 生成解题思路与工作地图
- 冻结 `AlignedBrief + SpatialProgramGraph (SPG) + WorkMap`，为大节点 4「初步设计」提供稳定基线

## 冻结治理（硬规则）

- 信息对齐完成后，必须同步冻结：`GeoCoordinateBaseline v1.0 + UseIntentBaseline v1.0 + AlignedBrief v1.0 + SPG v1.0 + WorkMap v1.0`。
- 冻结的含义是“当前阶段主版本快照”，用于协同、追溯与回退，不等于后续不得继续修改。
- **`GeoCoordinateBaseline` 与 `UseIntentBaseline` 前置冻结要求**：
  - `GeoCoordinateBaseline` 须在 `UseIntentBaseline` 之前完成冻结（`3.S.0` 步骤）
  - `UseIntentBaseline` 须在 `AlignedBrief / SPG / WorkMap` 之前完成冻结（`3.S.0.5` 步骤）
- 上游问题定义、目标边界、关键约束、成功标准、空间结构（分区/流线）与工作地图的修改或深入，只能在该成果页触发。
- 初步设计、深化设计与项目后追问阶段，不直接改写 `AlignedBrief/SPG/WorkMap`；若用户提出改题 / 重定义 / 补充核心条目，必须先回项目对齐成果页。
- 冻结触发条件：**`3.S.0` 完成** + **`3.S.0.5` 完成** + **`3.S.0.6` 完成** + **`3.S.0d` 完成** + `3.S.1` 完成 + `3.S.2` 完成 + `3.3` 用户确认。
- 若 `geo_pin` 未确认：标记 `BLOCKED（地理坐标缺失）`，不得进入 `3.S.0.5`。
- 若 `UseIntentBaseline` 中有高风险的 `unresolved_tensions` 未经用户确认：标记 `BLOCKED（用途冲突未解决）`，不得进入 `3.S.1`。
- 若存在其他阻断级 open items：标记 `BLOCKED`，不冻结，回到 `3.1/3.3` 补齐。

## 探索比选前置机制（合法阶段）

在设计行业中，草图、参考图、粗模和多方案比较是形成清晰问题定义的重要手段。为避免把“边做边想”误判为越权，Node3 明确允许以下前置活动：

- `ExplorationDraft`：单个草图/参考图/粗模形成的探索草案；
- `OptionSet`：同一问题的多个候选方向集合；
- `ComparisonBoard`：比较候选版本差异、保留理由与放弃理由的对照板。

治理要求：

1. 上述对象可作为 Node3 的合法输入信号，但不构成正式真相源；
2. 只有在 3.3 用户确认后，它们提炼出的约束、偏好与冲突才可编译进 `AlignedBrief/SPG/WorkMap`；
3. 多方案比较优先于单次仲裁，`HumanContextLayer` 应更多来自比较收敛，而不是先验独断。

## 正式二级步骤

- **3.1 信息梳理与追问**
- **3.2 动机与目的锁定**
- **3.3 补充采集与确认**
- **3.4 对齐简报审阅与冻结**

## 系统内部步骤

- **3.S.0 地理坐标编译**：`GeoCoordinateBaseline` 深度解读与冻结，是 `3.S.0.5` 的强制前置步骤
- **3.S.0.5 功能与用途编译（新增）**：基于 GeoCoordinateBaseline 约束，编译 `UseIntentBaseline` 并进行双基线交叉校验，是 `3.S.1` 的强制前置步骤
- **3.S.0.6 时间约束编译（新增）**：编译 `TemporalBaseline`，作为下游策略时段与生命周期约束输入
- **3.S.0d 人因编译与仲裁（新增）**：编译 `HumanContextLayer`（解释层/仲裁层），不作为 Node1 并列输入基线
- **3.S.1 解题思路**：位于信息对齐过程中的内部推导步骤，用于生成问题结构、求解方向与判断框架
- **3.S.2 工作地图**：承接解题思路，作为大节点 4「初步设计」中团队组建与任务安排的共同底盘，并形成 `WorkMap` 对象

补充说明：

- `3.S.0` 执行七层地理智能提取，产出 `GeoCoordinateBaseline v1.0`，同时输出四类派生产出物（场地约束卡 / 机会卡 / 用户旅程卡 / 经营影响卡）；
- **`3.S.0` 未完成冻结，`3.S.0.5` 不得启动**；
- `3.S.0.5` 执行"双基线交叉编译"：从 Node2 的功能初步表述出发，精化功能矩阵 → 施加地理约束 → 进行冲突仲裁 → 冻结 `UseIntentBaseline v1.0`，绑定到 `GeoCoordinateBaseline.v1.0`；将所有无法解决的冲突与张力显性标记到 `unresolved_tensions`；
- **`3.S.0.5` 未完成冻结，`3.S.1` 不得启动**；
- **`3.S.0.6` 与 `3.S.0d` 未完成，`3.S.1` 不得启动**；
- `3.S.1` 中必须用"一主两辅与多学科协同方法论"先识别**主线问题 / 驱动力修正轴 / 边界压缩轴**，主线问题的起点来自 `GeoCoordinateBaseline.world_model_anchor.preliminary_problem_frame` 与 `UseIntentBaseline` 的核心用途定义两个信号源；
- `3.S.2` 的 `WorkMap` 不是普通任务清单，而是把主辅关系、多学科参与位与冻结责任位一起编译进去的编排桥对象，须包含地理坐标与功能用途派生的专属专业席位与任务包。

## 输入

- 门禁结论（`accept` 或经过 `clarify` 后转入项目态）
- 已确认的项目上下文
- 原始 brief 与补充信息
- 对话态草稿（若存在）：仅作为预填信号，不作为真相源
- 片段/临时工作区转正申请（如存在）

### 片段/临时转正进入 Node3（补充规则）

当任务从片段或临时工作区升级为正式主链时，Node3 作为统一转正入口，至少校验：

1. 归一化来源是否完整（`draft_ref` / `source_ref` 可追溯）；
2. 是否显式声明 `missing_constraints` 与风险说明；
3. 是否具备最小上游约束补齐条件（至少 Geo + UseIntent）；
4. 触及结构改动时是否提交 `Impact Matrix`。

未通过上述校验时，保持在片段/临时工作区，不得进入 Node3 冻结链。

## 输出

- `ExplorationDraft / OptionSet / ComparisonBoard`（冻结前的探索与比较对象，不构成正式真相源）
- `GeoCoordinateBaseline`（地理坐标基线，世界模型第一输入，先于 AlignedBrief 冻结）
- `UseIntentBaseline`（功能用途基线，与地理基线联动冻结）
- `TemporalBaseline`（时间基线，作为横向约束输入）
- `HumanContextLayer`（人因编译层，作为仲裁与投影输入）
- `AlignedBrief`（项目对齐简报）
- `SpatialProgramGraph (SPG)`（空间结构化真相源）
- `WorkMap`（Node3→Node4 编排桥对象）
- 项目目的与目标对象
- 范围边界与约束条件
- 成功标准与核心假设
- 待验证风险
- 解题思路
- 工作地图
- 对齐成果页与冻结结果

## `AlignedBrief / SPG / WorkMap` 建议内容

建议至少包含以下字段：

`AlignedBrief`：
- 项目目的
- 目标对象
- 范围边界
- 约束条件
- 成功标准
- 核心假设
- 待验证风险
- 解题思路
- 工作地图

`SPG`：
- `space_type`
- `functional_modules`
- `zones / subzones`
- `flows / adjacency_rules`
- `strategy_scopes`
- `version / source_refs`

`WorkMap`：
- 团队组建输入面（角色能力需求）
- 任务安排输入面（任务簇、依赖、优先级）
- 与 `SPG` 的节点映射关系
- 主线问题 / 两辅修正轴
- 多学科参与位（主提 / 联提 / 审阅 / 否决 / 观察）
- 冻结前需满足的签署条件与回退触发点

## 与上下游关系

- 上游：门禁放行后的项目输入；对于目的尚不完整但具备项目意图的输入，可先经 `clarify` 做最小澄清后进入本节点
- 下游：作为独立里程碑交给大节点 4「初步设计」继续推进（消费 `AlignedBrief + SPG + WorkMap`）；若后续需要重定义或改题，则回到本节点的对齐成果页处理；片段/临时任务仅在转正后进入该下游链

## 协同组织补充规则

1. **`3.S.0`（地理坐标编译）未完成 → `3.S.0.5` 不得启动**，这是本节点的最高优先级规则。
2. **`3.S.0.5`（功能与用途编译）未完成冻结 → `3.S.1` 不得启动**，UseIntentBaseline 必须与 GeoCoordinateBaseline 同步冻结。
3. **`3.S.0.6`（时间编译）与 `3.S.0d`（人因编译）未完成 → `3.S.1` 不得启动**。
4. `3.S.1` 未明确主线问题（从 GeoCoordinateBaseline + UseIntentBaseline 双基线推导），不得进入 `3.S.2`。
5. `WorkMap` 未明确主提 / 联提 / 审阅 / 否决等责任位，不得作为 Node4 的正式输入。
6. 若主线问题与两辅修正轴发生冲突，必须在 Node3 内显性记录仲裁逻辑，不得把冲突偷偷甩给 Node4。
7. 若存在高风险 open items 但未明确谁有阻断权，则保持 `BLOCKED`，不得冻结。
8. `cultural_dna.taboo_styles`（风格禁区）一经 `3.S.0` 写入，不得在 Node3/Node4 内被任何步骤静默覆盖；如需例外须书面记录原因。
9. `UseIntentBaseline.unresolved_tensions` 中的所有张力必须显性写入 `AlignedBrief.risks`，不得隐瞒；Node4 决策必须基于完整的已知风险清单。

## 对象链（节点内视角）

```text
RawBriefPacket
	→ ExplorationDraft / OptionSet / ComparisonBoard
	→ GateDecision
	→ GeoCoordinateBaseline（3.S.0 编译，先行冻结）
	→ UseIntentBaseline（3.S.0.5 编译，与地理双基线交叉校验后冻结）
	→ AlignedBrief（消费 GeoCoordinateBaseline + UseIntentBaseline）
	→ SPG（消费 GeoCoordinateBaseline.taboo_styles + world_model_anchor + UseIntentBaseline.function_matrix）
	→ WorkMap（消费 GeoCoordinateBaseline.unique_opportunities + UseIntentBaseline.temporal_logic）
```

说明：Node3 的职责是把"地理基线 + 用途基线 + 问题定义 + 空间结构 + 编排底盘"一起冻结，避免 Node4 仅凭文本临时推理。`GeoCoordinateBaseline` 的引入使场地约束从隐性经验转为显性对象，`UseIntentBaseline` 的引入使项目用途从口头承诺转为结构化定义，所有下游消费者共享同一套地理和用途真相，不各自重新猜地点或项目意图。

> 详细字段契约与治理规则见 `4-3 世界模型/4-3-1 地理坐标/` 目录。
