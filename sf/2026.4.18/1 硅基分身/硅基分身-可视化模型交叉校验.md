## 二、8 项共识（四份均同意）

1. **不做总分面板** — 复杂的人不能压成一个分数
2. **盲区比能力更值钱** — 空白格比深色格更有产品价值
3. **必须有时间维度** — 静态档案 → 演化引擎
4. **分层展示** — 不要一屏堆砌，按认知深度递进
5. **每张图配一句诊断文字** — 不给结论的图是装饰
6. **双层对照** — 自己 vs 行业/基准，看差距而非绝对值
7. **图必须驱动行动** — 看完知道"下一步做什么"
8. **数据私有** — 评估画像不公开，仅用于自我诊断和 AI 注入

## 三、6 项分歧及裁定

### 分歧 1：维度坐标系的来源

| 方案 | 来源 |
|---|---|
| Ref1/2/4 | 各自发明新维度（8轴/6翼/8轴） |
| Ref3 | 严格复用九维本体 + 七视角 + 三维分类 |

**裁定：采纳 Ref3。**
理由：项目主链（AlignedBrief → SPG → InitialDesignPack）全部使用九维本体和七视角。可视化维度必须与主链对齐，否则诊断结果无法回流到梦幻团队补位和 Node1 上下文注入。自造维度听起来炫酷但切断了数据闭环。

### 分歧 2：雷达图的轴数和层数

| 方案 | 设计 |
|---|---|
| Ref1 | 8轴双层（原生 vs AI增强） |
| Ref3 | **九维雷达 + 七视角光谱分开做** |
| Ref4 | 8轴双层（当前 vs 头部水平） |

**裁定：采纳 Ref3 的分离方案。**
理由：九维本体描述"你做项目时关注什么"（感知频率），七视角描述"你做决策时偏重什么"（判断权重）——这是两个不同的认知层次。强行塞进一个双层雷达会混淆概念。分别做一张九边形雷达 + 一条堆叠光谱条更精确。每张图只回答一个问题。

### 分歧 3：盲区的表达形式

| 方案 | 形式 |
|---|---|
| Ref1/3 | 二维矩阵热力图（业态×地理） |
| Ref2 | 热力覆盖在行业全能地图上 |
| Ref4 | 三层六边形嵌套（知/不知/不知不知） |

**裁定：采纳 Ref3 的矩阵热力图，叠加 Ref3 的市场需求层。**
理由：
- 矩阵热力图直接对应 `DSSSpecialtyEntry` 的 `archetype × geoType` 笛卡尔积，数据已有现成字段
- Ref4 六边形概念好但数据源不清晰（"你不知道你不知道"从何计算？）
- Ref3 mockup 中的橙框标记（"市场需求高+你没覆盖"）是最能驱动行动的设计

### 分歧 4：市场定位的形式

| 方案 | 形式 |
|---|---|
| Ref1 | 四象限气泡图（复杂度×商业价值×经验浓度×AI成熟度） |
| Ref3 | 散点图/UMAP降维 |
| Ref4 | 气泡图（专项深度×定价水平） |

**裁定：Phase 1 不做市场定位图。**
理由：市场定位需要跨用户数据（"同行在哪里"），当前是单机 localStorage 模式，没有后端用户池。做出来只能是假数据占位。待平台化后再实施（Phase 3）。

### 分歧 5：时间轴的形式

| 方案 | 形式 |
|---|---|
| Ref1 | 多曲线（能力/资产/AI协同三线叠加） |
| Ref3 | 多线时间曲线（复杂度/维度数/决策回合/满意度） |
| Ref4 | 河流图（项目类型宽度表达数量） |

**裁定：Phase 1 用简化版事件时间轴，Phase 2 再做曲线。**
理由：时间轴需要历史项目数据积累。当前 DSS 刚上线，没有足够数据画曲线。先做一条标记关键事件（画像创建、知识条目增加、里程碑项目）的简单时间轴，随数据积累逐步丰富。

### 分歧 6：分身相似度/镜像图

| 方案 | 形式 |
|---|---|
| Ref1 | 左右镜像对照（6轴：表达/方法/判断/偏好/禁忌/模板） |
| Ref3 | 风格指纹波形图 |
| Ref4 | 仪表盘成熟度百分比 |

**裁定：Phase 1 做简化版成熟度指标（Ref4），不做完整镜像图。**
理由：真正的相似度计算需要 AI 回写数据与用户决策记录的比对——这是 Phase 2/3 的能力。Phase 1 先用"画像完整度"（已有字段填充率）作为成熟度代理指标。

## 四、最终确定的图表清单与分层

### L0 · 首屏卡片带（3 秒读懂）

4 个 KPI 数字卡：

| 卡片 | 数据源 | 计算方式 |
|---|---|---|
| **版图覆盖度** | `specialtyMatrix` | `confidenceLevel=done 的格子数 / 预设业态×地理总格子数` |
| **九维偏倚指数** | `perspectiveWeights`（暂用七维） | `max(weights) - min(weights)` 归一化，越高越偏 |
| **盲区机会数** | `specialtyMatrix` 空白格 | 市场需求表中有需求但用户无覆盖的格子数 |
| **生涯活跃度** | 知识条目增长率 | 近期新增条目数 vs 上期 |

### L1 · 主看板（30 秒读懂）— Phase 1 必做

| 图表 | 回答的问题 | 数据源 | 形式 |
|---|---|---|---|
| **九维敏感度雷达** | 我做项目时习惯先想什么 | `perspectiveWeights` (7→扩展到9维) | 九边形雷达 + 行业中位虚线 |
| **业态×地理版图** | 我做过什么、哪里空白 | `specialtyMatrix` | 矩阵热力图 + 橙框机会盲区 |
| **七视角决策光谱** | 我做决策的判断重心 | `perspectiveWeights` | 横向堆叠条 + 行业参考分布 |

### L2 · 深度诊断页 — Phase 2

| 图表 | 说明 |
|---|---|
| 生涯演化时间轴 | 关键事件节点 + 能力曲线 |
| AI 补足路径图 | 短板→代偿→协同→内化 |
| 分身成熟度仪表 | 画像完整度 + AI 理解准确度 |

### L3 · 证据回溯 — Phase 3

点击任何图区块 → 跳转到支撑该判断的原始知识条目/对话/决策记录

## 五、数据模型扩展

### 5.1 九维敏感度（扩展 DSSPerspectiveWeights → DSSNineDimSensitivity）

当前 `DSSPerspectiveWeights` 是 7 维，对应七视角。九维本体需要单独的数据结构：

```typescript
interface DSSNineDimSensitivity {
  people: number;     // 人
  place: number;      // 地
  space: number;      // 空间
  function: number;   // 功能
  flow: number;       // 动线
  emotion: number;    // 情绪
  culture: number;    // 文化与精神
  constraint: number; // 约束
  time: number;       // 时间
}
```

Phase 1 先用手动填写，Phase 2 从对话频率自动统计。

### 5.2 预设业态×地理枚举（用于版图覆盖度计算）

```typescript
const DSS_ARCHETYPES = ['民宿', '酒店', '办公', '商业', '展陈', '餐饮', '住宅', '文旅'] as const;
const DSS_GEO_TYPES = ['山地', '城市', '水滨', '乡村'] as const;
```

### 5.3 市场需求参考表（用于盲区标记）

硬编码一份行业基准热力表（Phase 1 静态，Phase 2 可后端动态更新）。

## 六、关键 UX 决策（采纳 Ref3 的警示）

1. **不用 0-100 分** — 雷达图显示的是"频率/权重"，不是评分。标签用"权重 7"而非"85 分"
2. **空白格 > 深色格** — 矩阵热力图中，橙色虚线框标记"市场有需求+你没覆盖"的格子
3. **每张图下一句诊断** — 系统自动生成（如："偏倚形状：创意维度饱满，约束/时间维度塌陷"）
4. **行业基准不是全局平均** — 按 `companyType` 和 `teamSize` 分组取中位
5. **一键发问出口** — 图表区块可点击发起对话（"为什么我的约束维度这么低？"）

---

## 七、视觉风格

采纳 Ref1+Ref3 共识：
- 深色底 + 低饱和高亮节点（与 mockup 一致）
- 图不密集，层级清楚
- 强调"结构感"和"诊断感"
- 每张图必须有诊断文字结论
- 少动画，多清晰

但 Phase 1 先在现有浅色系 UI 中实现（CockpitPanel 是浅色主题），深色主题留给独立画像页（Phase 2）。

## 八、Phase 1 实施计划

### 改造范围：画像弹窗 → 画像仪表盘

当前画像弹窗（max-w-4xl）升级为完整的三区布局：

```
┌──────────────────────────────────────────────────┐
│ [头部] 设计师名片 + 4个KPI卡                      │
├──────────────────────────────────────────────────┤
│ [L1 主看板]                                       │
│ ┌──────────────────┐ ┌───────────────────────┐   │
│ │ 九维敏感度雷达    │ │ 业态×地理 版图       │   │
│ │ (Chart.js Radar)  │ │ (CSS Grid 热力矩阵)  │   │
│ └──────────────────┘ └───────────────────────┘   │
│ ┌────────────────────────────────────────────┐   │
│ │ 七视角决策光谱（堆叠横条）                  │   │
│ └────────────────────────────────────────────┘   │
├──────────────────────────────────────────────────┤
│ [编辑区] 基本信息 / 权重滑块 / 业态矩阵编辑     │
└──────────────────────────────────────────────────┘
```

### 新增数据结构

- `DSSNineDimSensitivity` 接口
- `DSS_ARCHETYPES` / `DSS_GEO_TYPES` 枚举
- `DSS_MARKET_DEMAND_BASELINE` 市场需求基准表
- `DesignerProfile` 扩展 `nineDimSensitivity` 字段
