# 01 平面推演产品定义

版本：v0.1  
日期：2026-04-29

## 1. 产品定位

平面推演是项目底盘和方案画布之间的空间决策层。

它不承担完整 CAD 绘图，不承担渲染表现，也不把图纸识别本身当成终点。它负责把项目底盘、真实图纸和用户意图转化为可选择、可解释、可继续推演的空间布局版本。

更准确地说：

```text
平面推演让设计师和用户在同一张空间沙盘上，
看见一个项目可能成立的多种空间路径。
```

## 2. 用户主导性

用户不是被 AI 替代的人，而是主创和裁决者。

系统不能表现为：

```text
AI 给你一个最优平面，你照着用。
```

而应表现为：

```text
系统提出多个成立方向；
用户选择倾向；
系统继续推演；
用户锁定、否定、融合或回退；
方案持续收敛。
```

用户主导性体现在：

```text
选择一个版本
锁定某个空间
否定某个布局逻辑
要求减少改造
要求提高私密性
要求保留某版优点
要求融合 A 的公共区和 B 的私密区
随时回退到任一版本
```

## 3. 高参智能性

系统的智能性不在于替用户拍板，而在于解释每个选择背后的后果。

每个版本必须说明：

```text
为什么生成这个版本
它解决什么问题
它牺牲什么
它适合什么项目目标
它有什么施工/预算/运营风险
它和其他版本的差异在哪里
如果用户选择它，下一轮应如何推进
```

高参不是裁判，而是：

```text
选项生成者
风险提示者
取舍解释者
版本记录者
下一步建议者
```

## 4. 多版本的含义

多版本不是随机生成几张不同的图，而是生成不同策略假设。

住宅项目可以是：

```text
家庭聚合型
私密秩序型
成长弹性型
景观优先型
低改造稳妥型
```

商业项目可以是：

```text
转化效率型
品牌展示型
社交传播型
运营成本型
动线分离型
```

文旅/民宿项目可以是：

```text
到达首感型
景观记忆型
复购舒适型
内容传播型
后勤效率型
```

用户不是在“选图”，而是在选择这个项目优先成为什么。

## 5. 平面推演与相邻模块

### 项目底盘

项目底盘提供：

```text
项目类型
用户目标
预算
家庭/客群结构
空间限制
运营目标
设计动机
```

### 图纸基线

图纸基线提供：

```text
外轮廓
柱
承重或疑似不可动墙
楼梯
电梯
管井
入口
窗与采光面
比例尺
可改区域
```

### 方案画布

方案画布消费平面推演输出：

```text
语义分区图
动线关系
方案版本逻辑
空间块控制骨架
生图/文本/汇报锚点
```

### 硅基分身

硅基分身影响：

```text
默认生成哪几类版本
用户更偏好保守还是激进
用户常接受哪些取舍
用户常否定哪些风险
```

### 知识底盘

知识底盘提供：

```text
案例模式
空间策略模板
项目类型经验
常见失败教训
方法论权重
```

## 6. 最小可行产品

MVP 不追求完整自动施工图。

MVP 要做到：

```text
输入：SPG + FloorPlanFacts
输出：3 套策略不同的 LayoutVariant
展示：图纸上叠加粗空间块
解释：每套方案有策略说明、评分、风险
交互：用户可选择、冻结、回写、注入高参
沉淀：版本记录进入 LayoutVersionGraph
```

第一阶段的正确目标是：

```text
让用户看见有意义的空间选择，
而不是让机器一次画出完美平面。
```
