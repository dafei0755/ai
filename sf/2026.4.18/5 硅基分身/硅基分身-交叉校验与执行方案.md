以下校验基于：

## 二、四份参考的分歧区（逐项裁决）

### 分歧 1：是替换"知识底盘"还是拆成两个模块？

| 参考 | 立场 |
|------|------|
| 1 | 替换，仍放在知识与记忆层 |
| 2 | 升级替换 |
| 3 | **必须拆**——"我的硅基分身"(个人) + "项目知识库"(公共) |
| 4 | 升级替换 |

**裁决：采纳参考 3 的拆分思路，但不急于做两个独立导航入口。**

理由：
- 个人经验（"我做过的民宿 A"）和公共规则（"民宿通用平面模板"）确实权属不同、复用场景不同、共享策略不同
- 现有代码中 `sf_knowledge_loader.py` 加载的是公共知识（类型知识/评估矩阵/输出标准），`PersonalKnowledgeEntry` 存的是个人条目，后端已经天然分开
- 但 Phase 1 不需要在 UI 上拆成两个顶级导航，只需在数据模型中明确 `scope: 'personal' | 'project'` 标记，UI 上用两个分区即可

**执行规则**：
- `我的硅基分身`：个人画像 + 个人经验 + 个人方法论 + 个人盲区
- `项目知识库`（暂不独立入口）：团队/行业级的模板、规范、案例，保留原知识底盘的公共部分
- 每条知识条目写入时，必须标记归属（personal / project），不允许混存

---

### 分歧 2：内部模块结构——5 舱 vs 3 层 vs 4 层？

| 参考 | 结构 |
|------|------|
| 1 | 5 舱：认知画像 / 边界盲区 / AI 补足 / 经验蒸馏 / 职业档案 |
| 2 | 3 功能：Mirror / Exoskeleton / Soul Transfer |
| 3 | 3 层：L1 Mirror / L2 Diagnosis / L3 Augmentation |
| 4 | 4 层：画像层 / 评估层 / 进化层 / 分身层 |

**裁决：采纳参考 3 的 3 层模型作为架构分层，用参考 1 的 5 舱作为 UI 导航。**

**最终结构（3 层 + 渐进展开）**：

```
L1 · 镜像层（我是谁）
    ├── 设计身份画像（业态×地理×品牌定位 三维索引）
    ├── 能力结构画像（七视角倾向权重）
    ├── 经验资产库（升级现有条目，增加"禁忌/反模式"类型）
    └── 决策风格画像（从历史对话自动提取）

L2 · 诊断层（我缺什么）
    ├── 盲区图谱（对照：行业基准 / 能力全集 / 市场机会）
    ├── 边界识别（能力边界 / 项目边界 / 商业边界 / 时代边界）
    └── 三条路径建议（加深强项 / 补齐相邻弱项 / 开拓新领域）

L3 · 增强层（AI 怎么帮我）
    ├── 克隆态：AI 采用你的判断习惯和表达风格
    ├── 补足态：AI 主动引入你弱项视角
    └── 挑战态：AI 在关键节点用反向视角质疑（Phase 2+，可关闭）
```

---

### 分歧 3：是独立模块还是渗透式存在？

**裁决：两者都做——有家（管理入口）+ 有魂（运行时渗透）。**

- **静态面**（管理态）：在左侧导航保留"我的硅基分身"入口，管理画像 / 经验 / 查看诊断
- **动态面**（运行态）：通过 4 个接口注入主链
- **呈现标记**：AI 输出中，凡基于分身数据的判断，前缀标注 `[基于你的经验]` 或 `[分身提示]`

---

### 分歧 4：评分与对比机制

**裁决：采纳参考 3 的"匿名分布百分位"方案，Phase 1 不做任何评分。**

- Phase 1：不做评分、不做对比
- Phase 2：个人能力雷达图（自己看），经验浓度指标
- Phase 3：匿名百分位分布 + 互补匹配

---

### 分歧 5：参考 3 追加的"挑战态"

**裁决：有价值，放在 Phase 2，必须用户主动开启。**

---

### 分歧 6：知识发布阶梯

**裁决：参考 1 的 4 级模型正确，分两期实现。**

- Phase 1：`'草稿' | '已整理'`（现有）
- Phase 2：增加 `'团队发布'`
- Phase 3：增加 `'公开发布'`

## 三、与现有架构的接口定义

### 接口 1：分身 → Node1（意图显影前的上下文注入）

- 触发时机：用户发起新项目，Node1 开始前
- 注入内容：DesignerProfile 核心摘要
- 约束：只作为 system prompt 补充上下文

### 接口 2：分身 → Node3（信息对齐中的盲区追问）

- 触发时机：Node3 信息对齐/追问阶段
- 注入内容：BlindSpotMap 中与当前项目类型相关的盲区维度
- 约束：追问以"建议关注"形式呈现，不强制回答

### 接口 3：分身 → Node4（梦幻团队组建的能力补位）

- 触发时机：Node4 组建梦幻团队
- 注入内容：设计师能力覆盖面 vs 项目需求的差距
- 约束：不改变角色定义，只影响 AI 参与度权重

### 接口 4：项目结束 → 分身（经验回写）

- 触发时机：项目完成/设计任务书冻结后
- 约束：回写前必须用户确认；私人判断→分身，可公共化→项目知识库

## 四、伦理红线

| 红线 | 执行规则 |
|------|----------|
| 诊断不做道德判断 | "你不擅长运营视角"✅ "你是不称职的设计师"❌ |
| 评分对本人可见，不公开 | 同行只能看到用户主动选择展示的标签 |
| 数据所有权归用户 | 离开平台时可整体导出 + 彻底删除 |
| 不替用户做职业选择 | AI 只提供信息和镜像 |
| 重要提炼先确认再入库 | 自动提取的画像结论，必须经用户确认才正式生效 |
| 默认私有 | 所有数据创建时 `visibility: 'private'` |

## 六、三期执行路线

### Phase 1：镜像与沉淀（MVP）

| 任务 | 验收标准 |
|------|----------|
| 画像初始化（结构化对话引导） | 5 分钟引导后，看到 3+ 证据支撑的画像 |
| 经验资产库升级（4→6 类条目） | 现有 12 个 Demo 条目无回归 |
| 画像展示（卡片+证据链） | 点击结论可追溯到项目/对话 |
| 接口 1 预埋 | Node1 的 AI 回复体现"知道你是谁" |

**Phase 1 禁区**：不做评分、不做同行对比、不做补足建议、不做排行

### Phase 2：诊断与补足

- BlindSpotMap 生成 + 三条路径建议
- 接口 2/3 对接（Node3 盲区追问、Node4 能力补位）
- 克隆态 + 补足态 + 挑战态（可选）
- 进化日志

### Phase 3：团队与外部网络

- 4 级发布阶梯
- 匿名分布百分位
- 互补匹配
- 接口 4 完整回写
- 职业档案

## 八、与主架构的最终对齐

| 主架构原则 | 遵守方式 |
|-----------|----------|
| 设计师是驾驶员 | 分身只提供上下文和建议，不做决策 |
| 冻结对象不可被静默覆写 | 分身数据只注入 prompt，不触及冻结字段 |
| 判断深度 > 图的速度 | 盲区诊断 > 经验展示 |
| 启发式 + 选择式交互 | 画像收集用对话不用填表 |
| 六步共推框架 | 分身在 S1 注入画像、S2-S3 注入盲区追问 |
| 知识与记忆层边界 | 分身属"用户认知层"，提供供调用，不驱动节点流转 |

---

**总结**：先做"镜像"建立信任，再做"诊断"打开认知，最后做"增强"实现进化。Phase 1 的成败标准：用户第一次看到画像时是否会说——"这个 AI 真的懂我"。
