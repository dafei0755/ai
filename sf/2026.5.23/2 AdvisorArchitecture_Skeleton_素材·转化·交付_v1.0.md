## 0｜总纲

### 0.1 一句话定盘

```text
料被转化所拉动；
转化被主体所约束；
产物被编排所组织。
```

方案高参的真实骨架不是“知识库”，而是：

```text
素材层 → 转化层 → 交付层
        ↑
      主体轴贯穿
```

其中：

```text
素材层回答：有什么可用？
转化层回答：如何立意？
交付层回答：如何组织成产物？
主体轴回答：为谁、为何、谁说了算？
输出模式回答：这次应交付什么形态？
```

---

### 0.2 根本判断

方案高参的护城河不在“资料更多”，也不在“素材更全”。

```text
素材再全，都只是料；
料不会自己变成设计。
```

设计发生在“转化”这一动作中：

```text
设计 = 将源、主体、约束、手法和空间系统组织成一个可辩护的立意。
```

因此：

```text
系统主语不是素材库；
系统主语是转化引擎。
```

酷家乐有模型库，生成式工具有图像能力，传统设计公司有经验素材。它们都可能“有料”。但方案高参要建立的是：

```text
会把料转化成立意的认知操作系统。
```

---

### 0.3 当前商业纪律

本骨架不改变当前产品定盘。

第一阶段对外仍只有一个产品名：

```text
设计任务书 2.0
```

但这不代表系统能力的上限只是一份任务书。

应区分：

```text
对外产品层：
  只卖设计任务书 2.0。

系统内核层：
  必须具备多种输出模式的识别、编排和生成能力。
```

因此：

```text
对外只卖一个东西，是商业纪律；
对内能生成很多形态，是系统野心。
```

## 1｜总结构：三段一缰绳，两条回路

### 1.1 总图

```text
                    ┌────── 回路一：转化拉动采集 ──────┐
                    ↓                                  │
【素材层 · 料与边界】      【转化层 · 设计本体】      【交付层 · 组织产物】
                                                       │
被转化的源                  转译引擎四步编译           输出模式选择
转化的边界            →     解码 / 映射 / 求解 / 防滑 → 任务书 / 方法论 / 竞标 / 研究框架
转化的工具料                手法轴作为目标语言         项目图谱 / 快照 / 导出
        ↑                          ↑        ↑                │
        └── 供调用 ────────────────┘        │                │
                                             │                │
       主体轴 ── 缰绳 · 在转化两端把关 ───────┘                │
       入口：授权源 + 定终局；出口：权力裁决 + 验收             │
                    ↑                                          │
                    └────── 回路二：交付回写修正 ──────────────┘
```

### 1.2 三段定义

```text
素材层：料与边界。
转化层：设计本体。
交付层：组织产物。
```

### 1.3 一缰绳

```text
主体轴是缰绳。
```

主体轴不在转化中间，而在转化两端把关：

```text
入口：判断这个源是否适配这个主体，转译服务什么终局。
出口：判断这个产物是否回到主体终局，多方冲突时谁说了算。
```

### 1.4 两回路

```text
回路一：转化拉动采集。
回路二：交付回写修正。
```

这意味着系统不是瀑布流，不是“先采完资料，再转化，再交付”。

```text
转化一启动，就会反向暴露缺料；
交付一运行，就会反向修正转化方法。
```

## 2｜素材层：料与边界

### 2.1 定义

素材层回答：

```text
有什么可用？
```

素材层不是单一资料库。它由三类对象组成：

```text
A. 被转化的源
B. 转化的边界
C. 转化的工具料
```

这三类与转化的关系不同，不能混称为“素材”。

---

### 2.2 A｜被转化的源

被转化的源，是转译引擎要编译的对象。

包括：

```text
人格
品牌
大师方法
诗性意象
文学
音乐
自然意象
文化传统
学科理论
哲学观念
精神结构
生活方式
社会学洞察
人类学观察
```

它们回答：

```text
要把什么意义、精神、故事、人格或方法转译进空间？
```

示例：

```text
Tiffany 的“被珍视感”
Audrey Hepburn 的“克制、轻盈、自律、独立”
劳斯莱斯 Arcadia 的定制体系
“月亮落在结冰的湖面上”
苏东坡式生活美学
行为经济学中的“损失厌恶、锚定效应”
```

注意：

```text
源不是表面符号。
源必须被解码为不变结构，才能进入转化。
```

---

### 2.3 B｜转化的边界

转化的边界，不是被编译的料，而是限定编译的条件。

包括：

```text
预算
法规
消防
结构
场地
机电
给排水
物业
工期
伦理
安全
隐私
气候
技术条件
尺度范围
学科边界
交付周期
```

它们回答：

```text
这个转化必须在哪些条件内成立？
```

示例：

```text
预算 3000 元/㎡，但要保留豪宅体面感。
历史建筑不能大拆大改，但要植入现代开放派对空间。
临终病房不能像医院，但必须满足医疗护理与家属陪伴。
数据安全指挥中心必须高安全、高冗余、长期运行。
```

边界不是转化之前采完就结束的东西。

```text
边界贯穿转化全过程。
```

---

### 2.4 C｜转化的工具料

工具料是转化时可调用的空间与知识资源。

包括：

```text
业态知识
空间分类
横向系统
空间构件
建筑构件
贯穿系统
材料
灯光
机电
动线
人体工学
案例
规格卡
测绘数据
设计手法
任务书章节模板
```

它们回答：

```text
转化要调用哪些工具、系统、空间对象和知识卡？
```

示例：

```text
洗手间系统
楼梯系统
照明系统
门窗界面系统
幕墙系统
茶饮水吧台
酒店客房模块
办公会议系统
行为经济学展陈路径
```

---

### 2.5 素材层入库规则

素材层可以入库，但必须经过 System-R 契约。

入库时必须具备：

```text
grid_coordinate
production_method
source_refs
evidence_level
time_validity
transferability
output_usage
task_brief_chapter
```

素材层遵循四环节知识资产生产流程：

```text
收集 → 整理加工 → 入系统 → 使用与反馈迭代
```

其中：

```text
来源进入收集池。
卡片产生于整理加工。
正式知识进入系统仓。
价值验证发生在使用反馈。
```

## 3｜转化层：设计本体

### 3.1 定义

转化层回答：

```text
如何立意？
```

它是方案高参的核心。

素材层提供料，交付层组织产物，但真正的设计发生在转化层。

```text
设计不是知道很多东西；
设计是把这些东西转化成一个可辩护、可落地、能服务主体终局的空间立意。
```

---

### 3.2 转译引擎

转译引擎是转化层的心脏。

它负责：

```text
源 → 不变结构 → 手法 → 空间策略
```

四步编译：

```text
1. 解码
2. 映射
3. 约束求解
4. 防滑检查
```

---

### 3.3 第一步：解码

```text
源 → 不变结构
```

解码负责从源中剥离表面，提炼不变量。

错误路径：

```text
Tiffany = 蒂芙尼蓝
Audrey Hepburn = 复古小黑裙
书法 = 墙上挂字
东方茶意 = 花窗、灯笼、山水画
月亮落在冰湖 = 蓝色灯光 + 月亮装饰
```

正确路径：

```text
Tiffany = 被珍视感、仪式、精致、私密赠予关系
Hepburn = 克制、轻盈、自律、独立、优雅的距离感
书法 = 提按顿挫、计白当黑、时间性、不可逆动作
东方茶意 = 秩序、停顿、清气、留白、器物关系
月亮落在冰湖 = 冷、静、反射、孤悬、克制、低声、时间冻结感
```

解码失败，后续全部失败。

```text
解码失败 = 表面符号替代结构。
```

---

### 3.4 第二步：映射

```text
不变结构 → 设计手法
```

映射负责把源的不变量翻译为空间操作语言。

目标语言是设计语法：

```text
节奏
比例
尺度
构成
关系
层级
序列
过渡
对比
密度
边界
焦点
留白
压缩与释放
框景
借景
```

示例：

```text
“克制” → 材料数量控制、色彩收束、留白、低对比细节。
“轻盈” → 悬浮、细杆件、柔光、较低视觉重量。
“仪式” → 入口序列、视线聚焦、动作节点、光线收束。
“孤悬” → 局部焦点、周边消隐、低噪声、空间留白。
```

映射不是直接生成造型，而是给手法施加意图。

---

### 3.5 第三步：约束求解

```text
手法意图 → 在真实边界中落地
```

这一阶段把意义、手法、业态、系统、预算、法规、场地放在一起求解。

它处理：

```text
品牌 vs 预算
故事 vs 消防
体验 vs 运营
仪式感 vs 高峰效率
技术展示 vs 居住舒适
隐私 vs 展示
气质 vs 成本
意义表达 vs 施工可控
```

这一步不是简单规则表。

它属于 AdvisorAgent 的判断层。

事实层可以提供：

```text
尺寸
红线
限制
约束候选
冲突候选
风险候选
```

但最终判断必须由 AdvisorAgent 在推理纪律下完成。

---

### 3.6 第四步：防滑检查

```text
成品 → 退化检测
```

防滑检查负责判断转化是否滑向浅层表达。

常见退化：

```text
品牌转译 → 复制品牌色
文化转译 → 符号堆砌
大师方法 → 形式模仿
诗性意象 → 场景装饰
哲学概念 → 空洞文案
豪宅精神 → 材料堆钱
疗愈空间 → 米色软装模板
国风表达 → 伪中式装饰
```

防滑检查必须回答：

```text
这个转化是否仍能回到源的不变结构？
是否仍能服务主体终局？
是否只是把一个符号贴到了空间表面？
```

---

### 3.7 转化层入库规则

转化层分两半：

```text
转化方法入库。
转化产物不入库。
```

可入库：

```text
人格源转译方法
品牌源转译方法
大师方法源转译方法
诗性意象源转译方法
学科理论源转译方法
常见退化警示
正反案例
转译检查清单
```

不可入库：

```text
某个具体项目的概念主线
某个具体品牌故事
某个具体项目的体验脚本
某个竞标方案立意
某个住宅的精神叙事
```

它们属于项目产物，进入项目档案，而不是通用知识库。

## 4｜主体轴：转化的缰绳

### 4.1 定义

主体轴回答：

```text
为谁？为何？谁说了算？
```

主体轴不是 ordinary context。它是转译引擎的缰绳。

没有主体轴，转译会变成聪明联想；有主体轴，转译才可能成为立意。

---

### 4.2 主体轴两部分

```text
1. Subject Psyche｜主体精神结构
2. Stakeholder Power｜权力与决策关系
```

---

### 4.3 Subject Psyche｜主体精神结构

回答：

```text
这个空间真正服务的是怎样的人？
```

包含：

```text
生命阶段
身份结构
精神欲望
成就象征
回归需求
疗愈需求
自我认同
家庭传承
职业人格
创伤因素
焦虑结构
生活方式
```

示例：

```text
一代创业者：成就象征 + 家族传承 + 内心回归。
独立女性：优雅、自律、轻盈、边界感、自我认同。
00 后富二代：表达欲、消费符号、成熟生活方式升级。
哲学教授：与自己对话、存在感、沉思路径。
宇航员：宇宙记忆、重力适应、非地球经验。
```

---

### 4.4 Stakeholder Power｜权力与决策关系

回答：

```text
谁拥有空间主权？
```

包含：

```text
谁付钱
谁拍板
谁日常使用
谁被照顾
谁被展示
谁被隐藏
谁有否决权
谁的审美主导
谁需要妥协
谁承担运营结果
```

示例：

```text
红木父亲 vs 北欧母亲。
再婚家庭两个无血缘青春期孩子。
高管夫妇各有精神投射。
企业会所中的主客关系。
公共项目中的政府、运营方、社区居民、游客。
```

---

### 4.5 主体轴在转化两端把关

入口端：

```text
1. 授权源
   这个源是否适配这个主体？
   不适配则降级为贴标签或装饰联想。

2. 定终局
   转译要服务主体什么终局？
   是身份表达、疗愈修复、权力展示、生活升级、商业转化，还是公共价值？
```

出口端：

```text
1. 权力裁决
   多主体冲突时，谁的需求是主导，谁的需求是边界，谁的需求是补偿？

2. 验收
   产物是否能可辩护地回到主体终局？
   是否只是设计师或 AI 自己觉得有趣？
```

---

## 5｜交付层：组织产物

### 5.1 定义

交付层回答：

```text
如何组织成产物？
```

转化层产出立意，但立意不是交付物。交付层负责把立意组织成可确认、可冻结、可导出、可追踪、可复盘的成果。

---

### 5.2 输出模式选择器

内部必须存在：

```text
Output Mode Selector｜输出模式选择器
```

它判断本次任务本质上需要什么输出。

候选模式：

```text
DesignBrief｜设计任务书
ConceptFramework｜概念框架
Methodology｜方法论
CompetitionStrategy｜竞标策略
ResearchFramework｜研究框架
ConceptMatrix｜概念矩阵 / 主题矩阵
PlanningStrategy｜规划 / 建筑 / 景观策略
ProductLineStrategy｜空间产品线策略
ScenarioPrototype｜未来情景原型
UpgradeRoadmap｜能力升级路径 / 改造路径
OperationalPlaybook｜运营打法
```

---

### 5.3 对外产品容器

当前阶段对外统一容器仍是：

```text
DesignBrief_2_0｜设计任务书 2.0
```

因此内部输出模式应被包装为：

```text
方法论型设计任务书 2.0
竞标策略型设计任务书 2.0
研究框架型设计任务书 2.0
概念矩阵型设计任务书 2.0
规划策略型设计任务书 2.0
未来情景型设计任务书 2.0
```

不作为前台并列产品名。

---

### 5.4 Output Mode Selector 最小结构

```yaml
output_mode_selector:
  internal_mode: design_brief | concept_framework | methodology | competition_strategy | research_framework | concept_matrix | planning_strategy | product_line_strategy | scenario_prototype | upgrade_roadmap | operational_playbook
  secondary_modes: []
  user_visible_container: DesignBrief_2_0
  user_visible_label: ""
  output_depth: basic | standard | professional | strategic
  delivery_forms:
    - pdf_report
    - chapter_export
    - online_graph
    - presentation_pack
  reason_for_mode_selection: ""
```

示例：

```yaml
output_mode_selector:
  internal_mode: methodology
  secondary_modes:
    - concept_framework
  user_visible_container: DesignBrief_2_0
  user_visible_label: "方法论型设计任务书 2.0"
  output_depth: strategic
  reason_for_mode_selection: "用户要求将劳斯莱斯定制体系转译为住宅设计流程，目标是建立方法论而非单项目方案。"
```

---

### 5.5 交付层不入库

交付层产物是项目实例。

不入通用知识库：

```text
任务书成品
竞标策略成品
方法论交付稿
概念矩阵交付稿
规划策略成品
项目图谱快照
汇报材料
```

但它们可以进入：

```text
Project Archive｜项目档案
CaseObject｜案例对象
FeedbackEvent｜反馈事件
```

后续经整理加工，才可能提炼出可复用方法卡。

## 6｜两条反向回路

### 6.1 回路一：转化拉动采集

错误理解：

```text
先把素材全部收集完，再开始设计。
```

正确理解：

```text
转化一启动，就会暴露缺料。
```

例如：

```text
当系统尝试解码“赫本精神”时，会发现缺少独立女性空间心理素材。
当系统尝试把“月亮落在冰湖”转成光影时，会发现缺少冷光材料反射和声学资料。
当系统尝试做“AI伦理中心”时，会发现缺少后人类伦理与展陈教育逻辑。
```

于是触发：

```text
Deep Research
测绘
案例拆解
访谈
外部证据介入
透镜调用
```

---

### 6.2 回路二：交付回写修正

交付不是结束。

交付后的项目运行会产生：

```text
用户反馈
```

## 7｜入库判据

### 7.1 素材层入库

素材层是知识资产主库。

可入库：

```text
源
透镜
横向系统
业态知识
设备规格
法规约束
测绘数据
案例对象
手法方法
转译方法
```

---

### 7.2 转化层：方法入库，立意不入库

可入库：

```text
五类源转译方法卡
手法应用卡
防滑检查卡
常见误用边界
正反案例
```

不入库：

```text
某项目的概念主线
某项目的品牌叙事
某项目的体验脚本
某项目的竞标立意
```

---

### 7.3 交付层不入通用库

交付成果属于项目档案。

```text
任务书、方法论、竞标策略、研究框架、概念矩阵、规划策略，均不直接进入通用知识库。
```

但可作为案例证据，经过整理加工后提炼可复用知识。

## 9｜与已有文档的关系

### 9.1 与产品服务定义的关系

产品服务定义规定对外唯一产品名为：

```text
设计任务书 2.0
```

本骨架不推翻它。

本骨架只规定内部系统如何把不同输出模式统一组织进当前对外容器。

---

### 9.2 与 System-R 的关系

System-R 是契约层。

它规定：

```text
对象如何命名
卡片如何制式化
知识如何标注 grid_coordinate
知识如何映射任务书章节
知识如何审计、去重、升降级
```

本骨架不替代 System-R。

本骨架规定的是：

```text
System-R 管理的知识在系统总流程中的段位。
```

---

### 9.3 与 SpaceKnowledgeAsset Framework 的关系

SpaceKnowledgeAsset Framework 属于素材层的知识资产框架。

它负责：

```text
Domain Knowledge
Cross-System Knowledge
Meaning & Expression Knowledge
Design Grammar
Lens Knowledge
Case & Evidence Knowledge
```

本骨架给它一个更高位置：

```text
SpaceKnowledgeAsset Framework 是素材层与转化方法层的知识治理文件。
```

---

### 9.4 与 TeaSpace 的关系

TeaSpace 是一个 SpaceType 实例，不是总框架。

TeaSpace 负责茶饮专项知识，不负责承载全部横向系统、全部意义源、全部设计手法、全部输出模式。

---

### 9.5 与 AdvisorAgent 的关系

AdvisorAgent 是转化层与交付层的运行器。

它负责：

```text
判断头号风险
承接主体诉求
在约束内组织路径
对结论封顶
避免硬猜
避免讨好
避免怯懦
```

它不是知识库，也不是规则树。

## 10｜运行流程

### 10.1 标准流程

```text
用户输入
  ↓
空间分类与语境识别
  ↓
输出模式选择
  ↓
主体轴识别
  ↓
素材层召回
  ↓
转译引擎启动
  ↓
约束求解与防滑检查
  ↓
AdvisorAgent 组织判断
  ↓
交付层编排为设计任务书 2.0 或其内部变体
  ↓
项目图谱与版本快照
  ↓
反馈回写
```

---

### 10.2 反线性补货

```text
用户输入不足，不是直接中断。
转化中缺什么，才反向补什么。
```

例如：

```text
缺主体画像 → 追问 / 访谈 / Lens 调用
缺设备边界 → 测绘 / 规格卡
缺文化源 → Deep Research / X-Factor 来源
缺法规边界 → 外部证据介入
缺案例证据 → CaseLab 搜索
```

---

## 11｜不做的事

```text
1. 不把输出模式选择器暴露给用户。
2. 不把设计任务书 2.0 降级为众多平级产品之一。
3. 不在前台同时推出方法论、竞标策略、研究框架、概念矩阵等产品。
4. 不把转化理解为采集之后的瀑布阶段。
5. 不把约束当作被编译的源。
6. 不把项目立意直接入通用知识库。
7. 不让素材库取代转化引擎成为系统主语。
8. 不让转译自由发挥，所有转译必须被主体轴约束。
9. 不把茶饮、酒店、办公等业态继续拔高为终极中心。
10. 不用固定公式替代设计手法判断。
```

---

## 12｜最终收束

方案高参的总骨架不是：

```text
空间分类 → 知识召回 → 生成任务书
```

而是：

```text
素材被转化拉动；
转化被主体约束；
产物被编排组织。
```

更完整地说：

```text
素材层回答有什么可用；
转化层回答如何立意；
交付层回答如何组织成产物；
主体轴回答为谁、为何、谁说了算；
输出模式回答这次应交付什么形态。
```

最终一句：

```text
方案高参的护城河不是“资料更全”，而是“会把资料转化成立意”。
```

更直接一点：

```text
对外只卖一个东西，是商业纪律；
对内能生成很多形态，是系统野心。
```

## 附录 B｜三段入库判据速查

| 所在段位 | 是否入通用知识库 | 说明 |
|---|---|---|
| 素材层 | 是 | 料、边界、工具可跨项目复用 |
| 转化层方法 | 是 | 转译方法、手法方法、防滑方法可复用 |
| 转化层产物 | 否 | 具体项目立意、概念、叙事不入通用库 |
| 交付层产物 | 否 | 任务书、方法论、竞标策略等是项目档案 |
| 交付反馈 | 间接可能 | 先入 Feedback，再经整理加工后提炼 |
