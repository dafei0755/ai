## 0. 本次 v1.2 更新结论

v1.2 是对 v1.1 的结构性纠偏。v1.1 在落实“基础偏硬偏理、标准偏文”的**重心指引**时，把它误用成了**判定线**，导致一批“软但决定性”的要素（经营定位、客群角色、核心用户体验、概念与材料氛围基调）被错误下放或丢失。v1.2 修复这一根本问题，并保留 v1.1 全部正确成果。

核心裁决如下：

```text
1. 三层模块的唯一判定线是“缺角测试”：缺了它，空间设计会不会缺角。
   “偏硬偏理 / 偏文”只是各层的重心描述，不参与归属判定。
2. 基础模块补回“软但决定性”要素：经营定位、角色识别、核心用户体验、概念与材料氛围基调。
   基础模块由 8 个扩为 12 个。
3. 准入闸口、信息完整度、成熟度三者分层，不再混用。
   准入只卡“决定模块激活的核心要素”；场地详查归成熟度，不归准入。
4. 结构原型不再是硬编码门槛，而是核心要素变量组合派生出的“沟通标签 + 置信度”。
   闸口是“核心要素是否明确”，不是“是否选了某个原型”。
5. 第一轮问诊控制在 10 条以内，抓核心，不问细枝末叶；场地详查降为一个二元问题。
6. 标准模块继续承载经营效率、品牌传播、协作汇报，且其中“品牌触点、概念深化”
   是对基础层“概念与材料氛围基调”的深化，不是从零开始。
7. v1.1 的全部正确成果保留：深度研究后台分层、自定义不污染本体论、渠道解耦入图谱强依赖边、
   大词物理化但不伪精确、噪声源入基础、数字化与会员拆分、口头决策备忘录、外部数据纪律。
```

两条本可由你最终拍板、本版按你既定判定线先行落定的口径（如需可在 v1.3 推翻）：

```text
口径 A：概念锚定与材料氛围基调 → 进基础模块。
        理由：对“设计任务书”而言它是决定性的；缺了它，设计师拿到的不是设计任务书，
        而是一份可行性 + 经营 + 合规报告，无法开始设计。其深化（风格、叙事、传播）才归标准。
口径 B：基础模块扩为 12 个 → 接受。
        理由：补回的全是“缺了就缺角”的决定性要素，符合“信息完整优先、不怕多、就怕缺”。
```

一句话定盘：

```text
茶饮任务书不从“风格”开始，但必须到达“设计”。
它从经营定位、空间原型、设备接口、工艺流程、渠道冲突、报审边界开始，
经由核心用户体验与概念基调，收口于取舍账本与下一步设计任务。
```

## 1. 交叉校验与冲突排查

本章在 v1.1 已排查 1.1–1.12 的基础上，新增 v1.2 对“判定线误用”所做的系统性纠偏（1.13–1.18），并复核 v1.1 已正确解决项（1.19）。冲突项逐一列出，不跳过。

### 1.1 原型前置与对话优先是否冲突（v1.1 结论，v1.2 修订）

裁决（修订）：

```text
对话优先解决“用户如何进入”；准入闸口解决“系统何时输出正式目录”，二者不冲突。
但准入闸口不再是“原型确认”，而是“核心要素变量是否明确”（见 1.16、第 2 章）。
```

### 1.2 “基础模块偏硬偏理”与门头/品牌内容（v1.1 结论，保留并收窄）

裁决（保留）：

```text
门头/第一界面的“硬条件”（入口、招牌、视线遮挡、排队外溢、物业报审、消防、开口边界）留基础模块。
门头/第一界面的“品牌叙事”（性格、拍照、传播符号）归标准模块。
```

收窄说明（v1.2）：

```text
本条仅适用于“门头品牌叙事”。
不得据此把“经营定位”“客群”“核心用户体验”一并赶出基础模块——它们不是品牌叙事，详见 1.13。
```

### 1.3 标准模块是否承载经营效率（v1.1 结论，保留）

裁决（保留）：

```text
基础模块保留“基础人流/物流/渠道动线成立性”。
标准模块承接“高峰订单与渠道解耦”。
```

### 1.4 “三档除四项外能力一致”与“深度研究分档”（v1.1 结论，保留）

裁决（保留）：

```text
前台能力三档一致，不拆产品。
后台研究深度随模块层级变化：基础版不默认触发深度研究，标准版/专业版可在标准模块背后触发。
这不是新增第五个前台差异，而是“起点模块集不同”的后台生成强度补充。
```

### 1.5 “自定义模块查漏补缺”与“推荐池来自本体论”（v1.1 结论，保留）

裁决（保留）：

```text
推荐池生成可参考本体论、知识库；但用户添加后的自定义模块不反向改变本体论。
高频自定义只进推荐池候选，升入标准/本体论须人工评审、样本验证、版本升级，不自动进入。
```

### 1.6 “大词物理化”是否过度工程化（v1.1 结论，保留 + 补提醒）

裁决（保留）：

```text
大词必须物理化，但具体参数必须来自知识库、规范、项目验证或人工确认，AI 不得凭空写死数值。
```

v1.2 补提醒：

```text
标准模块 6.6 的大词转译表，所有指标列须标注“示例维度，非填空模板”，
防止工程实现时把示例当固定模板套用，造成伪精确。
```

### 1.7 “渠道解耦”作为章节还是图谱强依赖边（v1.1 结论，保留）

裁决（保留）：

```text
正式采纳。渠道解耦同时出现在标准模块和项目图谱。
默认强依赖/冲突边 strength 0.85–0.95，标注为“默认建议、可调”。
```

### 1.8 数字化点单与会员运营拆分（v1.1 结论，保留）

```text
数字化生产与交付 → 标准模块（偏经营效率）。
会员营销与数据运营 → 标准条件模块或自定义推荐池，不入基础。
```

### 1.9 声环境是否进入基础模块（v1.1 结论，保留）

```text
噪声源清单与影响预判 → 基础模块（噪声源是设备物理事实，属硬）。
声环境深化（吸声、隔振、声景）→ 标准模块或自定义推荐池。
```

### 1.10 决策压力测试是否增加负担（v1.1 结论，保留）

```text
采纳，但用轻量结构性问法（确定/预留/排除三选），不在首轮要求精确计算。
```

### 1.11 数据引用与年份标注（v1.1 结论，保留）

```text
采纳。所有外部市场数据须带来源、年份、适用范围、置信度、是否可直接用于决策。
```

### 1.12 专业版版本数（v1.1 结论，保留）

```text
本次不调整。专业版保持 30 个正式版本，超出走版本包或后续企业版。
```

### 1.13 【v1.2 新增 · 最严重】隐性判定线“硬=基础/文=标准”误用

冲突：

```text
产品方明确要求：基础模块需包括“必须的用户体验、经营定位”等，
“凡是离开这个要素、空间设计就缺角的，要归基础模块”，且“偏硬偏理不要绝对化”。
但 v1.1 基础模块 B1–B8 清一色硬工程/合规，没有任何经营定位、客群、用户体验模块。
```

排查：

```text
v1.1 在 1.2 节正确地把“门头品牌叙事”移出基础模块，
但顺势把“经营定位”和“核心用户体验”一并赶走，属于偷换概念：
  经营定位（客单价/客群/调性/体验目标）≠ 品牌叙事；
  核心用户体验（点单—等候—取餐—堂食停留的体验逻辑）≠ 审美表达。
前者是后续所有硬判断的“输入参数”——不知道卖给谁、什么客单，设备和面积都没有锚。
按“缺角测试”，它们缺了必然缺角，应归基础模块。
```

裁决：

```text
1. 判定线显式收敛为唯一一条“缺角测试”，删除文档中一切“硬→基础、文→标准”的暗示。
2. 基础模块补回“软但决定性”要素：经营定位、角色识别、核心用户体验、概念与材料氛围基调。
```

### 1.14 【v1.2 新增】决策方/使用方/客群既不在首轮、也不在基础模块

冲突：

```text
流程机制 v2.3 第 4.1 节 17 章中，03 章为“决策方/使用方/运营方分析”；
第 5.1 节必收 8 项中第 5 项为“主要使用者”。
v1.1 基础模块无此模块，首轮 8 项也砍掉了“使用者/客群”。
```

排查：

```text
与 1.13 同根：客群偏“文”，被判定线无意识过滤。
```

裁决：

```text
客群/角色回到基础模块（新增 B2），并回到首轮问诊（见 2.3 第 3 项）。
它是“经营定位”的前置输入。
```

### 1.15 【v1.2 新增】设计-概念层整体缺失

冲突：

```text
流程机制 17 章含 08 概念主线与空间叙事、09 文化/品牌/生活方式转译、12 材料/色彩/氛围。
v1.1 的 B + S 共 16 个模块无一对应这三章。
一份没有概念主线、没有材料氛围基调的“设计任务书”，本质不是设计任务书。
```

排查：

```text
v1.1 第 0 节“茶饮任务书不从风格开始”这一起点判断正确（先经营/原型/设备/工艺/渠道/报审）。
但“不从风格开始”≠“整本不到达概念”。任务书要让设计师能开始设计，
至少要给出概念方向与材料氛围基调，否则交付的是一堆约束、没有设计抓手。
对应核心公式：设计 + 行业 + 设计之外。
v1.1 现状是：行业重、设计之外有、设计几乎为零——公式第一项空缺。
```

裁决：

```text
新增基础模块 B10“概念锚定与材料氛围基调”（基调级，非风格深化）。
风格、叙事、传播、感官物性深化归标准模块 S4/S5。
```

### 1.16 【v1.2 新增】原型回归硬编码三类，与“变量组合”要求冲突

冲突：

```text
产品方明确：“三种结构原型的说法太局限……不要硬编码为几种，
有可能是变量组合：城市、商圈、物业、面积、租金、回收预期。”
但 v1.1 第 2.1 节摆出 A/B/C 固定原型表，第 2.2 节把“原型未确认”设为不出目录的硬闸口。
```

排查：

```text
可调和。原型可作为“核心要素变量组合聚类出的人话标签”（便于沟通、便于空间分类给置信度），
但不该是闸口。真正的闸口是“核心要素变量是否明确”。
v1.1 把因果倒置：让“选原型”成门槛，而正确的是“填变量”成门槛、原型是变量的副产物。
```

裁决：

```text
准入闸口改为“核心要素明确”（见 2.2、2.3）。
原型降级为派生标签 + 置信度，不作为强制选择项。A/B/C 表保留作沟通参考，不写成准入条件。
```

### 1.17 【v1.2 新增】三个闸口被混在一起

冲突：

```text
v1.1 第 2.2（原型未确认不出目录）、2.3（8 项必收含场地详查）、4.3（资料不足只标成熟度不删模块）
逻辑层级不同却并排，互相打架。
典型：2.3 把场地资料（平面/层高/柱网/给排水）列为首轮必收；
4.3 又说资料不足不删模块、只降成熟度。场地资料到底是出目录硬门槛，还是成熟度输入？自相矛盾。
```

排查：

```text
正确的三层应分离：
  准入闸口  —— 能不能出目录；
  信息完整度 —— 判断准不准；
  成熟度    —— 输出到哪一级。
流程机制本就分开（8 项最小包 vs 四级成熟度）。
```

裁决：

```text
目录准入只卡“决定模块激活的核心要素”；场地详查不是准入门槛，是成熟度阶梯。
核心要素明确即可在“原则级”出目录并打成熟度标签；场地资料补齐则升级到“平面前策略级”。
```

### 1.18 【v1.2 新增】首轮“8 项”是伪 8 项，违反“不问细枝末叶”

冲突：

```text
v1.1 第 2.3 第 4 项“已有场地资料”一项塞入平面/尺寸/门面宽深/层高/柱网/给排水/电力/排风/消防九子项。
表面 8 项，实际十几项，正是“首轮不该问的细枝末叶”。
```

裁决：

```text
首轮第 4 项降为一个二元问题——“是否有平面/实测图纸？（有/部分/无）”，用于定成熟度起点。
柱网、给排水点等详查移到出目录之后、随项目推进逐步拉取，不进首轮。
首轮总数控制在 10 条以内（见 2.3）。
```

### 1.19 v1.1 已正确解决、v1.2 全部保留的成果

```text
1. 深度研究后台分层（1.4）。
2. 自定义不反向污染本体论（1.5 + 第 7 章）。
```

## 2. 茶饮空间准入规则

### 2.1 原型：派生标签，不是门槛

结构原型不再作为准入门槛，而是核心要素变量组合聚类出的沟通标签，带置信度，可修正。它服务于空间分类与知识召回，不强制用户选择。

| 原型标签（派生）       | 面积参考          | 典型变量组合特征                                       | 任务书重心倾向                                   |
| ---------------------- | ----------------: | ------------------------------------------------------ | ------------------------------------------------ |
| A 小面积高频外带型     |           20–60㎡ | 外带为主、堂食弱、空间高度压缩、门头和效率极关键       | 极限效率、设备压缩、排队外溢、低预算投放         |
| B 中面积混合型         |          60–120㎡ | 到店点单、自提、外卖、有限堂食并存，前后场关系紧张     | 经营定位、设备接口、渠道解耦、堂食体验、品牌触点 |
| C 品牌表达/首店/旗舰型 | 100㎡以上或高投入 | 品牌传播、首店表达、投资汇报、连锁复制、社交权重高     | 品牌叙事、传播界面、标准店型、汇报体系           |

```text
原型由变量推导，不由用户先选。
原型只用于沟通、置信度和模块集预判，不作为出目录的硬条件。
本文默认场景：B 中面积混合型茶饮空间，60–120㎡。
```

### 2.2 准入闸口：核心要素明确

正式任务书目录的准入条件，是第一轮问诊中“决定模块激活的核心要素”已明确（见 2.3 中标记为“准入”的项），而非选定某个原型。

允许在准入前输出：

```text
项目初判
原型候选标签与置信度
关键风险提醒
第一轮轻量追问
资料缺口清单
```

准入后方可输出：

```text
正式任务书目录
基础模块完整清单
标准模块完整清单
自定义模块名额计算
正式版本号
对外汇报摘要
```

三层分离原则：

```text
准入闸口   = 决定模块激活的核心要素是否明确（2.3 准入项）。
信息完整度 = 判断准不准（影响性变量、资料缺口）。
成熟度     = 输出到哪一级（场地详查在此层，不在准入）。
核心要素明确即可在“原则级”出目录并打成熟度标签；资料补齐后升级成熟度。
```

### 2.3 第一轮轻量问诊（10 条以内）

抓核心、不问细枝末叶。其中标“准入”者决定模块激活，缺则不出正式目录；标“成熟度/精度”者缺则标假设、不阻断，但影响成熟度与判断精度。

| 编号 | 首轮核心变量                                              | 类型       | 决定什么                       |
| ---- | --------------------------------------------------------- | ---------- | ------------------------------ |
| 1    | 经营项目边界：纯自制饮品，还是叠加冷食/轻食/糕点/热食/燃气 | 准入       | 风险等级、厨房组合、报审路径   |

问诊姿态：

```text
一次只问 3–5 个，分轮推进，不做长表单。
用户已给出的信息自动填入，不重复追问。
第 7 项只问有/部分/无，不在首轮追问柱网、给排水点等细节。
缺失的准入项进入“待确认”，明确告知“补齐后才能出正式目录”，不伪装为已知事实。
信息完整优先：宁可多问一轮核心，不可为了少问而让判断失准。
```

### 3.2 三档差异的准确表述


## 4. 模块体系总规则

### 4.1 三层模块定义

| 层级 | 名称       | 定义                                                   | 是否计入本体论     | 是否默认进入任务书 | 是否可删 | 是否释放自定义名额 |
| ---- | ---------- | ------------------------------------------------------ | ------------------ | ------------------ | -------- | ------------------ |
| 1    | 基础模块   | 中面积混合型茶饮空间的最小可设计闭环                   | 是                 | 全档进入           | 不可删   | 不释放             |
| 2    | 标准模块   | 在基础成立后提升经营效率、品牌传播、协作汇报的增值结构 | 是，属于增值扩展层 | 标准版/专业版进入  | 可删     | 释放 1 个          |
| 3    | 自定义模块 | 项目特殊诉求的查漏补缺                                 | 否                 | 用户选择后进入     | 可删     | 释放 1 个          |

### 4.2 唯一判定线：缺角测试

判断一个内容属于哪一层，只问一句：

```text
缺了它，这个茶饮项目的空间设计会不会缺角？

会缺角，且无它无法稳定启动设计、报审或施工前判断  → 基础模块（必须，不可删）。
不缺角，但显著提升经营效率、传播价值或协作质量    → 标准模块（可删，释放名额）。
只服务项目特殊意图/场地/客群/运营，本体论推不出来 → 自定义模块或推荐池（不入本体论）。
```

关键纪律：

```text
“偏硬偏理 / 偏文”只是各层的重心倾向，不是判定线。
基础模块可以含偏文要素（经营定位、客群、核心用户体验、概念与材料氛围基调），只要它有决定性。
标准模块也可含偏硬要素（数字化点位、骑手交接），只要它不构成缺角。
判定线只有一条：缺了会不会缺角。
```

### 4.3 成熟度标注规则

基础模块不可因资料不足而删除，只能标注成熟度：

```text
原则级：只有项目描述与核心要素，缺少场地、设备、预算等硬资料。
条件级：有面积、地点、业态、预算、部分场地信息。
平面前策略级：有场地、面积、建筑基本条件和主要接口。
初步设计输入级：有平面、较完整需求、预算和场地条件。
```

示例：

```text
当前设备清单缺失，本模块以原则级输出。后续补充设备清单后，需复核设备负荷、后场面积和制作动线。
```

## 5. 中面积混合型茶饮空间基础模块

基础模块的判定不是“硬还是文”，而是“缺了会不会缺角”。下列 12 个模块，缺任一都会使空间设计缺角。其中 B1、B2、B8、B10 偏文，但同样具有决定性。

### 5.1 基础模块总表（12 个）

| 编号 | 基础模块                       | 重心     | 必须回答的问题                                               | 主要交付物                                       |
| ---- | ------------------------------ | -------- | ------------------------------------------------------------ | ------------------------------------------------ |
| B1   | 经营定位与门店调性锚定         | 软·决定  | 卖给谁？什么客单？什么定位与调性？体验目标是什么？           | 定位陈述、客单/客群锚、调性与体验目标基线         |
| B2   | 决策方/使用方/运营方/客群角色  | 软·决定  | 谁拍板？谁运营？谁干活？谁来买？各自诉求与冲突？             | 角色识别表、诉求/权责图、客群画像基线             |
| B3   | 经营项目与许可边界             | 硬约束   | 到底卖什么经营项目？是否触发更高风险？                       | 经营项目分类表、风险升级表、高风险项生存测试     |
| B4   | 场地、物业与市政接口核验       | 硬约束   | 场地是否具备做茶饮的基础条件？                               | 场地接口清单、物业条件表、待确认问题表           |

| B8   | 核心用户体验逻辑               | 软·决定  | 点单—等候—取餐—堂食停留的体验是否成立、是否有断点？         | 体验路径骨架、关键体验触点表、断点风险清单       |
| B9   | 安全卫生与专项系统基线         | 硬约束   | 洗消、照明、通风、防水、隔油、垃圾、虫害、卫生间关系是否成立？ | 食安设施矩阵、专项系统基线表                     |

排序逻辑：

```text
B1 定位、B2 角色先行——它们是后续一切判断的输入参数。
B3–B7、B9 是硬工程/合规链。
B8 用户体验紧随动线（体验在很大程度上就是动线的人本表达）。
B10 概念与材料基调在硬条件成立后收束，给设计师设计抓手。
B11 报审、B12 取舍账本收口。
```

### 5.2 B1 经营定位与门店调性锚定（v1.2 新增 · 软但决定）

```text
明确目标客群（年龄/职业/消费力/到店动机）。
明确客单价区间与价格带定位。
明确门店调性与体验目标（高效便捷型 / 社交停留型 / 品质信任型 / 形象表达型）。
明确这是“经营项目”的定位锚，而非品牌叙事——叙事归标准模块 S4。
```

执行原则：

```text
定位是设备、面积、体验、概念的输入参数。定位未明确，后续硬判断都缺锚。
定位变化（如客单价上移、客群切换）必须触发任务书复核与图谱节点状态更新。
```

### 5.3 B2 决策方/使用方/运营方/客群角色识别（v1.2 新增 · 软但决定）

```text
决策方：谁拍板（业主/品牌方/投资人/加盟商）。
运营方：谁负责日常经营（自营/加盟/托管）。
使用方：员工（岗位与班次）与顾客（客群画像基线）。
外部角色：骑手、物业、供应商。
识别各角色的核心诉求与潜在冲突（如投资回报 vs 体验投入）。
```

### 5.4 B3 经营项目与许可边界

内容要求：

```text
明确是否只做自制饮品。
明确是否涉及冷食、冷加工糕点、轻食、热食、半成品、预包装销售。
明确是否使用燃气、明火、大量蒸汽或油烟设备。
明确当前是“确定经营项目”“未来可能增加项目”还是“明确排除项目”。
```

高风险项生存测试（轻量问法）：

```text
如果未来增加冷食、冷加工糕点、轻食或燃气热食，系统将触发更高风险模块，
并可能影响后场面积、设备、工期、报审和动线。你希望它属于：
A 当前确定经营项目  B 未来预留项目  C 明确排除项目
```

执行原则：

```text
未确认经营项目边界，不进入正式任务书目录。
经营项目变化，必须触发任务书复核和图谱节点状态更新。
```

### 5.5 B4 场地、物业与市政接口核验

```text
商场铺、街铺、社区底商、办公配套、学校/景区等场地类型。
原始平面、门面宽深、层高、柱网、入口方向、招牌界面。
给水、排水、排污、隔油、排风、补风、空调、电力、消防、燃气条件。
卸货、垃圾、骑手停留、排队外溢、物业报审、门前三包或商场公共通道关系。
```

裁决：

```text
入口与第一界面在基础模块中只处理硬边界，不处理品牌表达。
品牌气质、打卡界面、传播口径移入标准模块 S4。
```

### 5.6 B5 食品处理分区与工艺流程

把“吧台”从模糊视觉对象拆成工艺对象。

```text
原料进入 / 储存 / 备料 / 制作 / 出杯 / 取餐 / 洗消 / 暂存 / 垃圾回收 / 员工进入 / 骑手交接
```

必须输出：

```text
清洁操作区、准清洁操作区、一般操作区之间的关系。
自制饮品区与其他食品处理功能区的关系。
堂食、外带、自提、外卖四种渠道的基础路径。
```

执行原则：

```text
不能先画漂亮吧台再倒塞设备。必须先有工艺流程，再进入空间组织。
```

### 5.7 B6 设备清单与机电接口

中面积混合型最易返工的模块。

```text
设备名称 / 数量 / 尺寸 / 功率 / 给水点 / 排水点 / 排气散热 / 冷链容量 / 检修面 / 噪声源类型 / 备用或扩展设备
```

噪声源清单与影响预判（基础版只要求识别）：

```text
持续噪声源：制冰机、冷柜、空调、排风、净水设备。
间歇噪声源：封杯机、破壁机、咖啡机、叫号提示、人声高峰。
受影响区域：点单区、等候区、堂食区、员工制作区。
声环境深化不进入基础模块，可进入标准模块或自定义推荐池。
```

### 5.8 B7 基础人流、物流与渠道动线

基础模块不做高峰运营推演，但必须判断基本动线是否成立。

必须覆盖：

```text
顾客点单 / 等候 / 取餐 / 堂食入座路径
员工制作 / 原料补货 / 垃圾转运路径
骑手到达与交接路径
```

基础判断：

```text
是否存在必然逆行？是否堵住入口？是否占用商场公共通道？
骑手是否进入顾客等待区？垃圾/原料是否穿越主要顾客路径？
```

### 5.9 B8 核心用户体验逻辑（v1.2 新增 · 软但决定）

该模块是用户体验骨架，不是审美表达；缺了它，空间在体验上缺角。

```text
点单体验：排队感受、点单效率、信息获取。
等候体验：等候区位置、等候时长感知、是否有焦虑外溢。
取餐体验：取餐识别、动线清晰、与堂食/外卖是否冲突。
堂食停留体验：座位舒适度、停留时长目标、是否鼓励翻台或鼓励停留。
体验断点识别：哪一环最容易让顾客困惑、烦躁或流失。
```

执行原则：

```text
本模块只建立体验逻辑骨架与断点判断。
氛围、拍照、社交符号等体验“表达层”归标准模块 S4。
```

### 5.10 B9 安全卫生与专项系统基线

```text
洗手设施 / 清洗消毒 / 保洁设施 / 食品处理区照明 / 通风排烟 / 防水 / 隔油 / 垃圾暂存 / 虫害防治 / 卫生间关系 / 更衣或员工后勤
```

原则：

```text
只建立基线，不替代专业深化。
涉及地方要求、物业要求和主管部门要求时，必须进入待验证项。
```

### 5.11 B10 概念锚定与材料氛围基调（v1.2 新增 · 软但决定）

修复设计-概念层缺失。本模块只到“基调级”，不做风格深化。

```text
概念主线：用一句话陈述本项目的空间概念方向（与 B1 定位一致）。
材料氛围基调：主材方向、色彩基调、光环境基调、整体氛围倾向。
一致性核验：概念/材料基调是否与经营定位、客单价、客群、预算自洽。
```

执行原则：

```text
本模块给设计师“设计抓手”，不替代设计师的审美创作。
风格深化、文化转译、感官物性指标（照度/反射率等）归标准模块 S4/S5。
基调与定位冲突时（如低客单却要高造价材料），进入 B12 取舍账本。
```

### 5.12 B11 报审出图与竣工验收路径

```text
物业报审需要什么。
食品经营许可或备案需要什么。
消防、机电、排水、招牌、燃气等变更由谁确认。
施工图阶段必须补哪些资料。
试营业前必须联调什么。竣工移交时必须形成哪些台账。
```

### 5.13 B12 设计取舍账本与一票否决项

不是软性建议总结，而是项目控制文件。

必须区分：

```text
事实 / 判断 / 建议 / 选择 / 风险 / 待验证项
```

一票否决项示例：

```text
经营定位或客群未明确，不生成正式目录。
经营项目边界未确认，不生成正式目录。
场地不具备基础给排水或排风条件，不能假设可做完整茶饮后场。
设备清单缺失，不输出确定吧台布局。
高风险食品制售未确认，不输出简化厨房逻辑。
物业/消防关键接口未确认，不输出施工前确认版。
```

标准模块在基础成立后，把经营效率、品牌传播、协作汇报转成可执行内容。其中 S4/S5 是对基础模块 B10 概念基调的深化，不是从零开始。

### 6.2 S1 高峰订单与渠道解耦

必须拆分：

```text
到店点单 / 小程序自提 / 第三方外卖 / 堂食入座 / 骑手取货 / 高峰临时排队
```

项目图谱映射：

```text
问题节点：高峰订单叠加 / 外卖骑手交接路径 / 顾客点单取餐路径
决策节点：是否设置独立骑手交接点
风险节点：渠道合一导致拥堵
强依赖边：骑手交接路径 → 高峰订单叠加
冲突边：外卖取餐口与堂食取餐口合一 → 顾客体验/出杯效率风险
```

### 6.3 S2 数字化生产与交付

处理直接影响空间和设备点位的数字化内容：

```text
线上菜单同步 / 订单打印 / 标签打印 / 叫号屏 / 出杯屏 / 取餐通知 /
缺货停售状态 / 外卖平台接单 / 网络与弱电点位 / 屏幕和打印设备位置
```

```text
会员营销、私域积分、CRM、复购机制不在本模块硬性处理，可进入 S8 或自定义推荐池。
```

### 6.4 S3 岗位协同与出杯效率

```text
点单 / 备料 / 制茶 / 封杯 / 打包 / 出餐 / 外卖交接岗位 / 高峰补位机制
```

输出重点：

```text
峰值瓶颈在哪里？哪个岗位最易与顾客路径冲突？
哪个设备最易成为排队源头？是否需要高峰临时取餐台或骑手专用台？
```

### 6.5 S4 品牌触点、空间叙事与菜单宣称

本模块是对基础模块 B10 概念基调的传播层深化（对应 17 章 08/09 深化）。

触点包括：

```text
门头 / 橱窗 / 点单台 / 菜单板 / 价签 / 取餐背景 / 包装 / 电子屏 / 外卖出餐区 / 员工服装或口播
```

执行原则：

```text
空间叙事与品牌表达必须与 B1 定位、B10 概念基调一致，不另起炉灶。
所有对外宣称（鲜奶、无糖、低脂、现切、手作、天然）必须进入宣称审核表，与实际产品/原料/工艺/供应链一致。
```

### 6.6 S5 大词遮蔽拦截与物理化转译

适用：用户或甲方提出“高级感、松弛感、年轻化、东方、疗愈、自然、精致、社交感、未来感”等抽象表达。

系统不得直接顺从大词，而要强制转译。下表为**示例维度，非填空模板**：

| 大词   | 物理转译维度（示例）                   | 可验证指标（示例）                   | 代价（示例）               | 待确认项               |
| ------ | -------------------------------------- | ------------------------------------ | -------------------------- | ---------------------- |
| 高级感 | 接缝、反射、灯光、材料耐久、界面留白   | 照度、反射率、材料维护等级、收边工艺 | 成本上升、施工精度要求提高 | 是否接受成本与工期增加 |
| 松弛感 | 座距、声环境、等待姿态、光色、动线压力 | 座位密度、背景噪声、等待区尺度       | 坪效下降、后场可能被压缩   | 是否牺牲部分座位效率   |
| 年轻化 | 拍照界面、社交内容、产品展示、可变装置 | 镜头点位、内容更新频率、视觉识别     | 维护成本、审美衰减快       | 是否建立内容运营机制   |

规则：

```text
AI 可提出指标维度，但不得凭空写死具体数值。
具体数值必须来自项目条件、知识库、规范、品牌标准或人工确认。
```

### 6.7 S6 食品安全叙事触点与可视化信任

```text
可视化制作区 / 透明清洁展示 / 原料可视化 / 清洁计划展示 / 明厨亮灶或视频厨房 / 镜头点位 / 食安承诺的物理位置
```

```text
可视化不是把所有后场暴露出来。

```


专业版增强：

### 6.9 S8 标准店型、连锁复制与投资汇报

## 7. 自定义模块规则

### 7.1 定义

```text
自定义模块是项目级查漏补缺，不是茶饮空间本体论的一部分。
它可以很重要，但其重要性来自单个项目，不来自中面积混合型茶饮空间的普遍必要结构。
```

### 7.2 名额

| 版本   | 起始自定义模块位 |
| ------ | ---------------: |
| 基础版 |             4 个 |
| 标准版 |             6 个 |
| 专业版 |            10 个 |

释放规则：

```text
删除 1 个标准模块 → 释放 1 个名额。
删除 1 个自定义模块 → 释放 1 个名额。
基础模块不可删除，不释放名额。
```

### 7.3 分类只是管理标签

| 管理类别 | 示例                                           |
| -------- | ---------------------------------------------- |
| 经营类   | 夜间营业专项、外卖爆单专项、回本测算专项       |
| 客群类   | 学生客群、亲子客群、白领午后消费、宠物友好     |
| 品牌类   | 小红书内容专项、直播拍摄位、联名快闪、周边陈列 |
| 空间类   | 外摆专项、转角铺双界面、堂食声环境深化         |
| 工程类   | 燃气专项、强排专项、特殊排水、设备扩容预留     |
| 汇报类   | 投资人专项说明、物业专项沟通包、施工前交底包   |

```text
分类只用于管理，不等于进入本体论。
```

### 7.4 推荐池与知识缺口回写

触发条件：

```text
用户新增系统未覆盖的自定义模块 / 多个同类项目反复出现同类需求 / 知识库支撑不足。
```

系统动作：

```text
生成知识缺口工单，打上项目/空间/需求/触发语句/模块名标签，进入后台推荐池候选。
```

禁止动作：

```text
不得自动升入基础模块。不得自动升入标准模块。不得自动写入茶饮空间本体论。
```

升级条件：

```text
高频出现 + 足够案例支撑 + 明确适用条件 + 人工评审 + 新版本正式发布。
```

### 7.5 重复识别规则

```text
与基础模块重复 → 提示已包含，不占名额。
与标准模块重复 → 提示已包含，可选择升级为独立专项，占 1 个名额。
自定义之间高度重复 → 建议合并，合并后占 1 个名额。
```

基础版特例（v1.2 明确）：

```text
基础版起点不含标准模块。基础版用户若需要某个标准模块能力（如出杯效率），
可作为自定义模块加入，占 1 个名额；也可升档获得完整标准模块集。
不强制升档，保护独立单店店主的轻量使用。
```

## 10. 三档销售口径

### 10.1 基础版

适合项目启动阶段相对明确、只需建立基础设计闭环的茶饮项目（尤其独立单店）。

基础版包含中面积混合型茶饮空间的 12 个基础模块，重点解决：

```text
经营定位与客群是否清晰
经营项目是否成立、场地接口是否具备
设备机电是否有基础逻辑、工艺流程与食品处理分区是否成立
基础人流物流是否冲突、核心用户体验是否成立
设计概念与材料氛围基调是否有抓手
报审与验收是否有路径
```

支持 4 个自定义模块，最多保存 10 个正式版本，包含项目图谱和全部输出形态。基础版不默认触发深度研究，只支持必要的单点事实补缺。

### 10.2 标准版

适合大多数正式茶饮空间项目。

标准版在 12 个基础模块之上，增加经营效率、品牌传播、协作汇报三类标准模块，重点解决：

```text
高峰订单与渠道解耦、数字化生产与交付、出杯效率与岗位协同
品牌触点与空间叙事、大词物理化转译、食品安全叙事触点
协作汇报与决策看板、标准店型与复制边界
```

支持 6 个自定义模块，最多保存 20 个正式版本，包含项目图谱和全部输出形态。标准模块背后可触发深度研究。

### 10.3 专业版

适合品牌首店、旗舰店、连锁复制、投资较大或多人参与的茶饮项目。

专业版包含标准版全部内容，并强化：

```text
多人协作权限分级、图谱变更审批、版本冻结与回退、汇报版输出、节点责任人机制、专家/人工复核接口
```

支持 10 个自定义模块，最多保存 30 个正式版本，包含项目图谱、全部输出形态，并支持多人协作。

## 11. 法规、行业数据与外部检索纪律

### 11.1 事实来源分级

```text
硬法规与标准：必须标注来源、版本、适用地区、是否需人工复核。
行业报告与市场数据：必须标注年份、样本范围、置信度，不得绝对化。
品牌/商圈/竞品/价格/趋势：必须通过外部检索或项目资料更新，不得使用陈旧常识。
```

### 11.2 不得把外部检索当作已验证事实

```text
外部检索可告知某类趋势、某品牌店型、某商圈竞品；
但不能替代项目的给排水点、层高、柱网、物业条件、设备清单。
```

### 11.3 数据进入任务书的格式

```text
信息内容：
来源：
年份：
适用范围：
置信度：高 / 中 / 低
是否作为硬决策依据：是 / 否 / 待人工确认
```

## 12. 执行落地思路

### 12.1 MVP 阶段

```text
1. 手工维护“中面积混合型茶饮空间”的 12 基础模块 + 8 标准模块清单。
2. 每个模块标注 necessity_level：essential / recommended / optional。
3. 建立准入闸口：核心要素（2.3 准入项）未明确，不出正式目录；场地详查归成熟度。
4. 建立 10 条以内首轮问诊，场地详查降为一个二元题。
5. 建立基础图谱节点和强依赖边模板。
6. 建立自定义模块去重与知识缺口工单。
7. 建立大词遮蔽词典和转译表模板（标注示例维度非模板）。
8. 用 4.4 映射核对表做交付前体检，确保 17 章无遗漏、无空挂模块。
```

### 12.2 V2 阶段

```text
1. 本体论动态激活基础模块和标准模块（含 B1/B2/B8/B10 软性决定要素）。
2. 推荐池由知识库失败案例反向驱动。
3. 外部检索结果进入模块内容生成。
4. 任务书与项目图谱 source_refs 建立稳定引用关系。
5. 外部 CAD/平面导入后，对照强依赖边进行冲突识别。
```

### 12.3 V3 阶段

```text
1. 基于历史项目数据优化模块推荐排序。
2. 基于用户删除/保留行为优化推荐池。
3. 高频知识缺口进入人工评审流程。
4. 形成茶饮空间子类型下的多套模块激活策略（按变量组合）。
5. 与硅基分身打通，形成设计师个人茶饮项目经验画像。
```

## 13. 定盘句

```text
茶饮空间先明核心要素，再出目录；原型是派生标签，不是门槛。
```

```text
三层归属只有一条判定线：缺了会不会缺角。
偏硬偏理、偏文，只是重心，不是判定。
```

```text
基础模块不是“硬工程清单”，而是“项目成立 + 设计可启动”的最小闭环。
它既含设备、工艺、动线、报审，也含经营定位、客群、核心体验、概念与材料基调。
标准模块是效率、传播、协作的增值层。
自定义模块是项目特殊需求的查漏补缺，不入本体论。
```

```text
基础版解决“能不能稳妥开始设计”。
标准版解决“能不能更有效、更会表达、更好协作”。
专业版解决“多人、首店、连锁、投资汇报如何可控推进”。
```

```text
大词必须物理化，但参数不得伪精确。
渠道必须解耦，并进入项目图谱强依赖边。
知识缺口可回写推荐池，但不能自动污染本体论。
设计任务书不从风格开始，但必须到达设计。
```
