# B2 — 目标冲突诊断器

> **组别**：B 组（框架选型必说）| **阶段**：S2 | **类型**：互动·必说
> **原始编号**：L3 核心张力识别 | **发声顺序**：B 组第 2 件

---

## 一分钟定义

定位项目目标中**不可回避的互斥对**，强迫用户在 S4 张力冻结之前有意识地面对取舍——而不是在设计执行阶段被动发现「鱼和熊掌不可兼得」。

---

## 功能详述

B2 处理的不是「用户没说清楚的信息缺口」，而是「用户以为可以全部实现、但逻辑上不可兼得的目标冲突」。

**典型冲突类型**：

| 冲突类型 | 举例 |
|---------|------|
| 成本 vs 品质 | 「60 万预算」vs「高端材料全屋定制」 |
| 开放 vs 私密 | 「喜欢大通透空间」vs「需要安静独立工作区」 |
| 风格 vs 功能 | 「极简主义」vs「大量储物需求」 |
| 短期 vs 长期 | 「快速入住」vs「未来可改造扩展」 |
| 个人 vs 群体 | 「业主个人艺术表达」vs「家庭成员舒适使用」 |

**B2 不做的事**：不帮用户做选择，只让用户「清醒地知道选哪个」，真正的选择在 S4 完成。

---

## 输入

```
jtbd_statement         # B1 输出的任务定义
structured_requirements  # A1 全部信号包
```

---

## 输出

```python
conflict_pairs: [
    {
        "goal_a":    "开放公共空间",
        "goal_b":    "安静私密工作区",
        "conflict":  "空间有限，两种需求争夺同一区域",
        "if_both":   "若同时保留，最可能损失的是工作区的隔音性",
        "type":      "开放 vs 私密"
    },
    ...
]
# 写入 state.conflict_pairs，S4 张力冻结时消费
```

---

## 激活条件

- B1 responded（用户确认任务定义后）
- S2 强制执行，不可跳过

---

## 执行方式

- **执行器**：LLM 调用
- **对抗视角**：内部用「最大化目标 A 的视角」vs「最大化目标 B 的视角」对抗，找到真实冲突点
- **数量控制**：输出 1~3 个冲突对（超过 3 个则按优先影响程度筛选）
- **G1 检查**：冲突描述必须具体，不接受「目标 A 和目标 B 存在一定张力」等模糊表达

---

## 用户交互

**有**。展示格式：

```
在你的目标中发现了一个根本矛盾：

「[目标 A]」vs「[目标 B]」

[冲突性质说明]

如果两者都不让步，最可能牺牲的是 [X]。

目前不需要你做选择，只需要确认：这个矛盾理解对了吗？
```

**用户响应类型及处理**：

| 响应类型 | 处理方式 |
|---------|---------|
| 确认（冲突存在） | 槽位 responded，conflict_pairs 存入，进入 B3 |
| 否定（这不是冲突） | 触发 reframe，B2 重置，重新分析 |
| 提出第三条路 | 记录用户建议，标注为待 S3 挑战 |
| 提前给出选择 | 接受并记录，在 S4 时引用（但 S4 仍需正式确认） |

---

## 协作关系

```
上游（依赖）：
  ← B1 任务目标提炼器（任务定义是找冲突的前提）

下游（供给）：
  → B3 全局影响扫描器（冲突对影响系统性影响分析的重点方向）
  → S4 张力冻结（conflict_pairs 是决策矩阵的行）
  → D1 设计前提校验器（S3 会专门挑战 B2 给出的冲突诊断是否正确）
```

---

## Reframe 依赖关系

B2 被否定（reframe）时，以下槽位重置为 `invalidated`：
- B3（依赖 B2 冲突对调整影响扫描重点）
- D1（S3 的挑战基于 B2 的假设）
- C1/C2/C3（可能依赖 B2 结论）

---

## 常见误用

1. **把「偏好差异」当作「目标冲突」**
   纠偏：「想要北欧风格」vs「想要储物丰富」是偏好兼容的，不是真正互斥的冲突；真正的冲突是「极简美学要求的严格留白」vs「储物需求导致的大量柜体」

2. **列出 5 个以上冲突对淹没用户**
   纠偏：最多 3 个，按「影响最终方向」的权重筛选，剩余冲突在 S4 决策矩阵时再展开

3. **在 B2 就追问用户「选哪个」**
   纠偏：B2 只确认「冲突存在」，不做选择——选择的权利在 S4，不要提前索要

---

## 扩展优化方向

- **冲突库积累**：按项目类型积累常见冲突模式，B2 可以先查库再判断，提升诊断速度和质量
- **冲突强度评分**：给每个冲突对打「不兼容程度」分数，帮助用户判断哪个冲突更需要优先决策
- **冲突可视化**：在前端展示「目标张力图」，用可视化帮助用户理解冲突关系
