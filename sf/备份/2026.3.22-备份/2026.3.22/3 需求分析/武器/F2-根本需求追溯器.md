# F2 — 根本需求追溯器

> **组别**：F 组（后台引擎）| **阶段**：S1 | **类型**：后台·F1 之后
> **原始编号**：L1.5 第一性原理

---

## 一分钟定义

用第一性原理把表层需求**剥离到最小可还原的「裸需求」**，防止分析阶段响应的是「装修愿望清单」而不是「真正需要被满足的需求」。

---

## 功能详述

追溯路径示例：

```
「我想要一个开放式厨房」
    ↓ 剥离：为什么想要开放式？
「我想在做饭时能看到孩子在客厅玩耍」
    ↓ 剥离：这背后的裸需求是？
「需要在照料孩子的同时完成家务」← 裸需求
```

F2 不是追到最哲学化的层面（「我想要幸福」），而是追到「可以用设计动作响应的最基础层面」。

---

## 输入

```
fact_inference_map   # F1 输出（只处理 [FACT] 和 [PREFERENCE]）
```

---

## 输出

```python
bare_requirements: [
    {
        "surface":  "开放式厨房",
        "root":     "照料孩子同时完成家务",
        "design_response": "视线连通客厅的烹饪区，而非必须开放式"
    },
    ...
]
```

---

## 激活条件

F1 完成后立即触发，S1 强制执行。

---

## 用户交互

**无**。结果供 B1、F3 使用。

---

## 协作关系

```
上游（依赖）：← F1 事实推断分离器
下游（供给）：
  → F3 关键洞见提炼器（裸需求是 F3 提炼洞见的核心素材）
  → B1 任务目标提炼器（裸需求是 JTBD 的基础输入）
```

---

## 常见误用

追到太抽象的层面（「裸需求：家庭幸福感」→ 对 B1 没有参考价值）。裸需求必须是「设计动作可响应的」。

---

## 扩展优化方向

- **追溯深度控制**：根据输入复杂度自动判断需要追溯几层（简单住宅 1~2 层，复杂商业 3~4 层）
