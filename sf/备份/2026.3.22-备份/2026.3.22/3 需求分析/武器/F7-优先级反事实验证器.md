# F7 — 优先级反事实验证器

> **组别**：F 组（后台引擎）| **阶段**：S2 | **类型**：后台·B1+B2 响应后异步
> **原始编号**：L4.6 思想实验

---

## 一分钟定义

通过「如果 X 不存在」的反事实假设，**验证 B1/B2 给出的优先级排序是否内在一致**，防止用户表达的优先级排序和真实行为优先级不一致。

---

## 功能详述

反事实测试模板：

```
假设：「[最高优先级目标]」完全无法实现，你会怎么做？

• 放弃整个项目 → 说明这个目标是真正的核心
• 降低标准继续做 → 说明「想要」但不是「必须」
• 转向备选方案 → 说明真实优先级可能是「备选方案中的某个目标」
```

F7 的验证**不直接告知用户**，只是把验证结果作为 B1/B2 优先级排序的「稳健性评分」，high/medium/low。

---

## 输入

```
jtbd_statement   # B1 任务定义（含优先级）
conflict_pairs   # B2 冲突对（含用户初步倾向）
```

---

## 输出

```python
priority_stability: {
    "jtbd_priority_stable": True,             # B1 优先级没有内在矛盾
    "conflict_resolution_stable": False,      # B2 用户选择在反事实下会动摇
    "note": "用户表示「首要保证开放感」，但
             若开放牺牲了独立工作区，
             用户大概率无法接受——实际上工作区优先"
}
```

---

## 激活条件

B1 + B2 都 responded 后，在后台异步运行（不阻塞 S2 进程）。

结果在 S4 张力冻结时注入决策矩阵，作为「稳健性验证」一列。

---

## 用户交互

**无**。后台静默，结果在 S4 时隐性体现（影响哪些决策被标注为「需要进一步确认」）。

---

## 协作关系

```
上游（依赖）：← B1 任务目标提炼器 + B2 目标冲突诊断器
下游（供给）：→ S4 张力冻结（stability 注入决策矩阵的「稳健性」维度）
```

---

## 扩展优化方向

- **低稳健性时触发追问**：若 `priority_stability` 为 low，S4 中标注该决策点「建议用户再确认一次」
