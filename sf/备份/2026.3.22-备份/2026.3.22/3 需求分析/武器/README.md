## 设计原则

- **单一职责**：每个文件只描述一件武器，不做跨武器比较
- **自包含**：看这一个文件就能完整理解该武器的功能、用法、协作关系
- **可追溯**：每件武器标注原始编号，与旧版文档可对照
- **可扩展**：「扩展优化方向」一节供专题迭代时填写

## 方法论与武器协作关系（统一口径）

一句话：**方法论负责“为什么与是否通过”，武器负责“如何执行与产出什么”。**

### 四层关系

1. **方法论层（S-1）**：定义目标、边界、冻结门禁与验收（如 BQ、HEVA、冻结节点）。
2. **方法/策略层**：把方法论拆成可执行策略（主线推进、驱动力修正、边界压缩、横切校验、编译交接）。
3. **武器层（本目录）**：按触发条件执行具体分析动作（A1/B1/F6/Y3…），产出结构化中间结果。
4. **产物层**：沉淀为冻结对象（`AlignedBrief` / `InitialDesignPack`）供上下游交接。

### 在 Node1~Node4 中的协作分工

- **Node1（用户输入）/ Node2（门禁）**：以流程治理为主，武器通常不作为主执行层。
- **Node3（信息对齐）**：武器主工作区，负责问题定义与结构化证据构建。
- **Node4（初步设计）**：武器承担编译、门控与交接支持，服务冻结决策。

执行原则：武器不得绕过方法论门禁；任一高风险结论必须回到方法论验收口径（HEVA-A / 冻结节点）。
