# Y3 — 假设证据优先引擎

> **组别**：Y 组（战略升级·新增）| **阶段**：S3/S4 | **类型**：后台·问题求解核心引擎
> **优先级**：P0 | **触发条件**：复杂项目/高不确定性项目默认激活 | **消费方**：D1、S4、Y4

---

## 一分钟定义

把当前项目的关键判断，整理成**假设树 + 证据缺口 + 验证优先级**，让系统不仅能“看懂问题”，还能知道**先验证什么，错了哪一条会整盘重来**。

---

## 功能详述

当前武器库已经很擅长洞察，但顶级问题求解系统还需要另一种能力：

> 把复杂问题拆成若干关键假设，并判断哪一个最值得优先验证。

### 三层结构

| 层级 | 问题 | 输出 |
|-----|-----|------|
| **核心假设** | 我们当前方案成立，最依赖哪几个判断？ | `critical_hypotheses` |
| **证据状态** | 这些判断是已知事实、弱推断、还是无证据？ | `evidence_strength` |
| **验证优先级** | 哪条假设如果错了，伤害最大、应最先验证？ | `validation_priority` |

### 典型输出

```python
hypothesis_tree: {
    "critical_hypotheses": [
        {
            "hypothesis": "目标客群会把‘非传统五星’视为优势而非廉价感",
            "evidence_strength": "weak_inference",
            "if_wrong": "品牌定位整体失效",
            "priority": 1
        },
        {
            "hypothesis": "老居民愿意接受部分底商非标品牌替换",
            "evidence_strength": "unknown",
            "if_wrong": "社区阻力高，推进节奏必须放缓",
            "priority": 1
        },
        {
            "hypothesis": "双模切换空间可由非专业人员在30分钟内完成",
            "evidence_strength": "low_confidence",
            "if_wrong": "运营端无法执行，设计逻辑失效",
            "priority": 2
        }
    ],
    "no_regret_moves": [
        "先锁定不可逆结构界面",
        "将高成本投入延后到关键假设验证后"
    ]
}
```

### 价值

Y3 的价值在于，它让系统不再只是输出“有洞见的话”，而是开始输出：
- 最危险的假设是什么
- 最先该补哪类信息
- 哪些动作即使假设错了也不会后悔

这就是从洞察系统，迈向问题求解系统的关键一步。

---

## 输入

```
all_upstream_outputs     # B/C/D/X 组关键输出
project_type             # X1 类型判断
uncertainty_signals      # 来自题目中的不确定性线索
```

---

## 激活条件

以下任一满足即激活：
- 项目存在强竞争判断
- 项目存在治理/公众接受度风险
- 项目存在技术可执行性不确定
- 项目处于概念前期、没有足够已知事实

---

## 用户交互

**无（默认）**。  
如最高优先级假设完全无证据，可触发 1 个高杠杆问题：

> 「如果只能确认一件事来决定项目方向，您最希望先验证哪一件？」

---

## 协作关系

```
上游（依赖）：← D1/X7/X8/Y2 等全部关键判断
下游（供给）：→ S4（优先冻结高风险假设相关张力）
             → Y4（把 validation_priority 转成推进顺序）
             → F8（交给下游专家先验证 priority=1 的假设）
```

---

## 常见误用

1. 把所有不确定点都列成假设（Y3 只关心“错了会重伤全局”的关键假设）
2. 把“需要更多灵感”当作假设不足（Y3 解决的是决策风险，不是创意匮乏）

---

## 扩展优化方向

- 建立标准化 `if_wrong` 影响等级模型，把验证优先级从定性升级为半定量
