# Z1 — 政策目标树生成器

> **导航提示：** 若你在看城市、政府、区域治理类项目，建议先读 [README](README.md) 与 [05-城市与区域复杂场景武器](05-城市与区域复杂场景武器-2026-03-11.md)；本文是城市级复杂目标拆解的前置底盘件。

> **组别**：Z 组（城市底盘·新增）| **阶段**：S1/S2 | **类型**：后台·城市/政府项目前置框架器
> **优先级**：P0 | **触发条件**：X1/Y2 判断为城市/区域型、政府主导型项目 | **消费方**：Y2、Y3、S4

---

## 一分钟定义

把政府、平台公司、示范区、公共项目中的宏大口号，拆成**可执行、可验证、可排序的政策目标树**，防止系统把“提升城市能级”“促进乡村振兴”之类大词直接当需求本身。

---

## 功能详述

城市/治理项目里，最大的风险之一不是信息不足，而是**目标太大、太抽象、太正确**。如果不把政策话术拆成目标树，需求分析就会落入空泛正确。

Z1 的任务是把政策目标拆成三层：

| 层级 | 问题 | 输出 |
|-----|-----|------|
| **一级目标** | 项目名义上的最高目标是什么？ | `top_policy_goal` |
| **二级操作目标** | 这个目标要通过哪几类机制实现？ | `operational_goals` |
| **三级可验证目标** | 哪些结果在 1-3 年内可被观察、衡量、复盘？ | `observable_outcomes` |

### 典型示例

```python
policy_goal_tree: {
    "top_policy_goal": "激活老城区活力，同时保留原有生活肌理",
    "operational_goals": [
        "提高街道一层界面有效使用率",
        "引入年轻消费场景但不挤出原居民高频服务",
        "提升夜间可达性与安全感"
    ],
    "observable_outcomes": [
        "原居民日常使用频次不下降",
        "底商空置率下降",
        "夜间人流提升但居民投诉不过线"
    ],
    "goal_conflicts": [
        "商业活化 vs 生活肌理保留",
        "游客吸引力 vs 居民容忍度"
    ]
}
```

### 为什么重要

因为没有目标树，后续武器会陷入两个问题：
1. 只会重复政策口号
2. 无法判断什么才算“项目成功”

Z1 的意义，就是把“政治正确”变成“可操作正确”。

## 输入

```
raw_input_text          # 原始项目描述
project_brief           # 简报中的政策/示范/振兴/更新类表述
```

---

## 激活条件

检测到以下语义时优先激活：
- 示范区 / 振兴 / 激活 / 城市能级 / 公共服务 / 更新 / 样板 / 高质量发展
- 政府 / 国企平台 / 街道 / 开发区 / 社区主导

---

## 用户交互

**有（最多 2 个问题）**。目标是逼出“真正考核口径”：

> 「如果两年后要复盘这个项目，领导最关心的是人流、招商、口碑，还是治理稳定？」

---

## 协作关系

```
上游（依赖）：← X1/Y2 的城市项目识别
下游（供给）：→ Y2（治理网络要围绕目标树分析）
             → Y3（关键假设围绕 observable_outcomes 生成）
             → S4（冻结的是目标排序，不只是空间取舍）
```

---

## 常见误用

1. 把口号直接当一级目标，不继续拆解
2. 把设计指标（如立面更新）误写成政策目标（它只是手段，不是目标）
