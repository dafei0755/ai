# Z3 — 区域场景产品线规划器

> **组别**：Z 组（城市底盘·新增）| **阶段**：S2/S4 | **类型**：互动·区域级产品结构器
> **优先级**：P1 | **触发条件**：新区、示范社区、复合开发、文旅聚落等多产品场景 | **消费方**：Y1、S4、Y4

---

## 一分钟定义

把区域/复合项目从“一个大概念”拆成**一组相互支撑的场景产品线**，明确不同客群、不同空间单元、不同收益/公共使命之间的结构关系。

---

## 功能详述

很多新区、文旅、复合开发类项目的问题，不是概念不够大，而是**只有总概念，没有产品结构**。结果就是：
- 什么都想做
- 每一块都差不多
- 没有主次
- 没有相互支撑

Z3 的任务是从区域角度做“产品线拆分”。

### 拆分维度

| 维度 | 核心问题 | 输出 |
|-----|---------|------|
| **客群分层** | 不同人群为什么来、停多久、付多少钱？ | `segment_profiles` |
| **场景产品** | 每类客群对应什么空间产品？ | `product_lines` |
| **主次关系** | 哪个是引流产品，哪个是盈利产品，哪个是形象产品？ | `portfolio_roles` |
| **协同关系** | 产品之间如何彼此带动？ | `cross_support_logic` |

### 典型输出

```python
regional_product_portfolio: {
    "segment_profiles": ["本地居民", "周末游客", "青年主理人", "机构考察客"],
    "product_lines": [
        "高频社区服务界面",
        "目的地型公共空间",
        "轻运营文旅住宿单元",
        "展示型品牌会客空间"
    ],
    "portfolio_roles": {
        "引流产品": "目的地型公共空间",
        "盈利产品": "住宿与餐饮复合单元",
        "形象产品": "品牌会客与展示空间"
    },
    "cross_support_logic": "公共空间聚人→餐饮留人→住宿延长停留→展示空间强化区域品牌"
}
```

---

## 输入

```
project_brief                # 区域/复合项目描述
client_type_profile          # X1 输出
Z2_development_value_model   # 如已存在时序模型，优先吸收
```

---

## 激活条件

- 项目出现：聚落 / 复合体 / 社区 / 小镇 / 文旅 / 示范区 / 会所群 / 多业态
- 或需求中明确要求“产品线分级”“客群结构”“可复制模型”

---

## 用户交互

**有（最多 2 个问题）**。核心是逼出主次：

> 「如果项目只能先打造一个最有代表性的场景，它应该优先承担引流、盈利，还是形象展示？」

---

## 协作关系

```
上游（依赖）：← Z1 政策目标树 ← Z2 开发时序价值链
下游（供给）：→ S4（冻结产品组合主次）
             → Y4（推进顺序围绕主产品线展开）
             → X7（不同产品线的商业性分别校验）
```

---

## 常见误用

1. 把所有场景都设计成“主角”
2. 用一个空间总概念覆盖所有客群，不做分层
