## 项目思维总则（第一性原理反推）

这条主链不是“设计师怎么做设计”的流程，而是“项目如何达成终局目标”的决策流程。

### 1）先问终局，不先问风格

- 先定义项目最终要解决什么（业务目标 / 使用目标 / 风险目标）。
- 再反推当前阶段最该做的最小关键动作。
- 任何节点都不能脱离“终局目标”自我循环。

### 2）以第一性原理拆题

每一轮都先回答三个问题：

- **项目真正要什么**：最终价值与不可替代目标是什么？
- **项目取决于什么**：关键变量、关键约束、关键风险是什么？
- **现在先做什么**：在当前信息条件下，最小但有效的推进动作是什么？

一句话：**先还原本质，再组织动作。**

### 3）全维度参与，而非单专业裁决

- 不是只看空间审美，而是同时看：用户、业主、运营、实施、供应链、成本、风险、文化等立场。
- 不是只看建筑/景观/室内，而是与项目相关的泛学科共同参与判断。
- 不是只看“现在能不能过”，还看“交付后能不能长期成立”。

### 4）按“项目成功条件”组织流程

- Node3 的使命是把问题定义清楚（定义成功条件、约束条件、验证条件）。
- Node4 的使命是把首轮方案做成“可执行的项目决策包”，而非仅输出概念描述。
- 深化分支的使命是持续消解关键风险与关键不确定性。

### 5）反推法工作句式（统一口径）

在每个节点统一使用以下句式：

- **为了达成 X（终局目标）**，
- **本阶段必须先锁定 Y（关键变量/关键约束）**，
- **否则会导致 Z（关键风险/失败后果）**。

该句式用于信息对齐、任务安排、成果审阅与深化分支，确保全链路都在“项目思维”而非“局部偏好”下运行。

## 两大功能与四大节点（总览）

### Node 命名来源与严格定义（2026-03-22）

为避免“Node3 / Node4”被不同文档语境混用，统一口径如下：

1. **命名来源**
	- `Node1~Node4` 来自本文件定义的“项目态主链四大节点编号”，不是临时别名。
	- 编号与下列文件一一对应：
	  - `2 大节点1-用户输入.md` → Node1
	  - `3 大节点2-门禁.md` → Node2
	  - `4 大节点3-信息对齐.md` → Node3
	  - `5 大节点4-初步设计.md` → Node4

2. **Node3 是什么（严格定义）**
	- Node3 = **信息对齐节点（项目定义层）**。
	- 职责：把原始输入编译为可执行问题定义，并形成冻结基线 `AlignedBrief`。
	- 边界：Node3 负责“定义清楚问题”，不负责输出最终实施成果包。

3. **Node4 是什么（严格定义）**
	- Node4 = **初步设计节点（项目决策层）**。
	- 职责：基于 Node3 冻结基线，形成可推进、可校验、可回溯的 `InitialDesignPack`。
	- 边界：Node4 负责“做成首轮决策包”，不回写改题；改题应回到 Node3 对齐链。

4. **与历史标签的关系（防混淆）**
	- 历史资料中的 `S1/S2/S3/S4`（常见于武器文档）是**武器运行阶段标签**。
	- 现行主链以 `Node1~Node4` 为准；`S*` 仅作执行层历史标签，不替代 Node 定义。

5. **判定规则（执行时）**
	- 若讨论“问题定义、约束显性化、对齐冻结” → 归 Node3。
	- 若讨论“团队组建、任务编排、实施与成果冻结” → 归 Node4。
	- 若出现“在 Node4 直接改题” → 视为越界，回退 Node3。

### 功能层（对业务价值）

**功能 A：信息对齐（项目定义层）**

- 目标：把原始输入反推为“可执行的项目定义”（目标 / 约束 / 风险 / 验证）
- 产物：`AlignedBrief`（项目对齐简报）
- 关键步骤：终局目标澄清、关键变量识别、约束显性化、缺口补齐
- 内部承接：3.S.1 解题思路、3.S.2 工作地图
- 冻结治理：Node3 完成后冻结 `AlignedBrief`，作为后续初步设计的稳定基线

**功能 B：初步设计（项目决策层）**

- 目标：把已对齐的问题转成首轮“可执行决策包”（可推进、可校验、可回溯）
- 产物：`InitialDesignPack`（阶段性成果包 / 初步设计包）
- 关键步骤：跨专业协作编组、任务反推编排、执行与校验、成果审阅与冻结
- 分流治理：轻量级项目可在 Node4 结束；复杂项目以该成果包为基线进入“深化设计”后续分支

一句话：**信息对齐负责“把项目问题定义清楚”，初步设计负责“把首轮项目决策做成立”。**

### 流程层（对系统编排）

**大节点 1**：用户输入（输入接入）

→ **大节点 2**：门禁（前置治理与路由）

		→ **门禁结果**：`accept`（进入项目态主链） / `clarify`（先做最小澄清再判定） / `reject`（结束或拒绝）

		→ **前置条件**：仅对“空间设计相关且在方案高参范围内”的请求启动双态分流；不相关输入门禁外拦截（out-of-scope），不进入双态判断

→ **大节点 3**：信息对齐（承载功能 A）

	　→ **二级步骤 3.1**：信息梳理与追问

	　→ **二级步骤 3.2**：动机与目的锁定

	　→ **二级步骤 3.3**：补充采集与确认

	　　　　→ **系统内部步骤 3.S.1**：解题思路（对齐过程中的内部推导）

	　　　　　　→ **调用模块**：终极追问引擎 + 用户需求层级框架（形成“追问结论卡 + 层级覆盖结论”）

	　　　　→ **系统内部步骤 3.S.2**：工作地图（初步设计的底盘）

	　　　　　　→ **调用模块**：HEVA（建立关键假设池与验证计划）

→ **大节点 4**：初步设计（承载功能 B）

	　→ **二级步骤 4.1**：梦幻团队组建（基于工作地图 → 团队清单）

	　→ **二级步骤 4.2**：任务安排（基于工作地图 + 团队清单 → 执行蓝图）

	　→ **二级步骤 4.3**：任务实施（方向锁定 / 专题推进）

	　→ **二级步骤 4.4**：成果审阅与冻结（阶段性成果包）

	　　　　　　→ **调用模块**：HEVA-A（PASS / PASS-WARN / FAIL），作为冻结前门禁

→ **后续分支**：深化设计（按需触发，不强制）

	　→ **回合步骤 R0**：触发判定

	　→ **回合步骤 R1**：意图归类

	　→ **回合步骤 R2**：上下文装载

	　→ **回合步骤 R3**：动作编排

	　→ **回合步骤 R4**：执行协同与审阅

## 如何区分：大节点、二级步骤、系统内部步骤、后续分支

### 大节点

大节点是项目主链上的**骨架层**，回答的是：

- 现在流程走到哪一段；
- 这一段承担什么职责；
- 要向下一个环节交接什么。

在当前口径里，大节点是：

- 大节点 1：用户输入
- 大节点 2：门禁
- 大节点 3：信息对齐
- 大节点 4：初步设计

一句话：**大节点是整条主链的分段。**

### 二级步骤

二级步骤是挂在某个大节点下面的**内部推进步骤**，回答的是：

- 这个大节点内部具体怎么完成；
- 先做什么，后做什么；
- 哪些步骤构成冻结链或回合链。

在当前口径里：

- 大节点 3（信息对齐）下的二级步骤是 `3.1 → 3.3`，即信息梳理与追问、动机与目的锁定、补充采集与确认
- 大节点 4（初步设计）下的二级步骤是 `4.1 → 4.4`，即梦幻团队组建、任务安排、任务实施、成果审阅与冻结

一句话：**二级步骤不是新的大节点，而是某个大节点内部的走法。**

### 面向系统的内部步骤

系统内部步骤指的是：**存在于系统编排与认知组织层，但不单独升格为大节点的内部推导/内部对象/内部底盘。**

在这条链里，典型代表是：

- 系统内部步骤 3.S.1：解题思路
- 系统内部步骤 3.S.2：工作地图

它们的作用分别是：

- **解题思路**：位于信息对齐过程中，是大节点 3 内部的系统承接步骤，用于生成后续工作结构；
- **工作地图**：承接解题思路，作为初步设计中团队组建与任务安排的共同底盘。

在新的口径里，它们更准确地承担：

- **解题思路**：位于信息对齐过程中，是大节点 3 内部的系统承接步骤，用于生成问题结构与求解方向；
- **工作地图**：承接解题思路，作为大节点 4 中梦幻团队组建与任务安排的共同底盘。

因此它们更适合被理解为：

- 不是大节点；
- 也不是对外独立主链步骤；
- 而是服务于大节点 3 内部、并向大节点 4 提供底盘支撑的**系统内部步骤/内部对象**。

一句话：**系统内部步骤负责支撑步骤，不单独成为主链节点。**

### 后续分支

后续分支指的是：**主链完成后，只有在用户明确要求继续、当前成果不足以落地、复杂度超出轻量阈值，或关键风险尚未消解时，才按需触发的后继工作域。**

在当前口径里，典型代表是：

- 深化设计（`R0 → R5` 回合制）

它回答的是：

- 当前阶段性成果之后是否还需要继续；
- 如果继续，本轮想深化、修订、派生什么；
- 如何在不改写上游冻结对象的前提下完成下一轮推进。

一句话：**后续分支不是主链必经段，而是主链之后的按需延展。**

## 最简单判断法

- 如果它在项目主链上承担一整段职责，就是**大节点**。
- 如果它是某个大节点内部的正式推进序列，就是**二级步骤**。
- 如果它主要服务于系统内部推导、编排、承接与组织，但不单独对外成段展示，就是**系统内部步骤**。
- 如果它只在主链完成后按条件触发、并以回合方式持续推进，就是**后续分支**。
