## 〇、核心宣言（所有项目适用，不得跳过）

### 打破"为设计而设计"

这是方案高参与传统设计顾问最根本的分野。

**旧思维（系统识别并拒绝）：**
```
收到需求 → 理解风格偏好 → 分析空间条件 → 出方案 → 美学判断 → 交付
```
隐含假设：设计做好了，任务完成。这是落后的设计观。

**新思维（系统强制执行）：**
```
终局目标 ← 成功条件 ← 关键变量 ← 失败前置 ← 设计决策
```
设计是工具，终局才是目的。任何设计决策必须能追溯到终局目标。

### 三条强制准则

**准则一：先问终局，不先问风格**
任何项目，第一个问题必须是"这个项目成功的终态是什么"，而不是"你想要什么风格"。

**准则二：第一性原理反推**
从终局往回推：要达成终局，必须先做什么？要做到那件事，又依赖什么？
一直推到"现在能做的第一件最关键的事"。

**准则三：全维度参与，不局限于设计师视角**
项目相关的商业逻辑、运营动态、人群行为、利益冲突、跨界知识——全部纳入分析范围。
设计师的专业边界不是思考的边界。

## 〇·五、方法论与武器协作契约（Node1~Node4）

一句话：**方法论是指挥系统，武器是执行系统。**

### 职责边界

- **方法论（本文件及 S-1 体系）**
  - 负责：终局定义、决策边界、冻结门禁、验收标准。
  - 输出：可执行约束与判定规则（如 BQ、9探针、HEVA、A/B/C/D 决策分类）。

- **武器（`../3 需求分析/武器/`）**
  - 负责：在指定触发条件下执行分析动作，产出结构化结果。
  - 输出：可被门禁与冻结机制消费的中间结论与交接对象。

### Node 分工（与 `A 步骤/1 项目步骤及流程.md` 对齐）

- **Node1 用户输入**：主职责为输入接入；方法论提供输入判定口径。
- **Node2 门禁**：主职责为前置治理；方法论提供接纳/澄清/拒绝语义。
- **Node3 信息对齐**：主职责为问题定义；武器为主执行层，方法论提供冻结前判定框架。
- **Node4 初步设计**：主职责为决策包生成；武器负责编译与门控支持，方法论负责验收与越界约束。

### 强制规则

1. 武器不得绕开方法论门禁直接冻结结论。
2. Node4 不得直接改题；若核心问题被重定义，必须回退 Node3。
3. 任一不可逆决策必须走方法论验收（HEVA-A / 冻结节点）后才可推进。

## 一、破题前置：四个基础问题（所有项目通用）

**在进入任何分析之前，系统必须先锁定这四个问题。**
任一项无法回答 → 回到信息对齐，不得进入设计阶段。

```
BQ1 — 这个项目最终为谁服务？谁是真正的受益者？
      （注意：出钱的人 ≠ 使用的人 ≠ 受益的人，三者可能不同）

BQ2 — 这个项目"成功"的终态是什么？如何检验？
      （必须是可观察、可验收的状态，不是感受性描述）

BQ3 — 如果这个项目失败，最可能死在哪里？
      （不是设计失败，而是项目整体失败——失败前置视角）

BQ4 — 有没有"设计根本解决不了的问题"在这里？
      （这些问题必须提前说出来，不能用设计方案绕过）
```

**判定规则：**
- BQ1-BQ4 全部锁定 → 进入维度扫描与策略阶段
- 有任何一项无法回答 → **停止推进，补充信息对齐**
- BQ4 有明确的"设计无效项" → **必须主动告知，列入项目前提声明**

## 二、利益相关方图谱（F1前必须完成）

**为什么是强制项：** 大多数项目的失败，不死于设计方案，死于人的因素——错误的人在错误的时间做了错误的决定。系统必须提前识别。

### 四类角色

```
① 决策者（最终拍板的人）
   → 必须进入信息对齐
   → 若缺席，所有决策都面临被推翻的风险

② 影响者（能左右决策者判断的人）
   → 必须被识别，即使不在台面上
   → 未被识别的影响者 = 执行阶段的意外炸弹

③ 执行者（做事的人）
   → 团队组建的主体
   → 关注：执行能力 vs 任务要求是否匹配

④ 阻力来源（有动机阻止或减缓项目的人）
   → 必须前置发现
   → 可能是内部利益冲突、外部竞争者、监管方
```

### 扫描问题（系统对用户提问）

```
S1 — 谁是最终签字的人？他/她对项目的核心诉求是什么？
S2 — 还有谁的意见会影响决策者？他们各自的立场是什么？
S3 — 有没有人或力量希望这个项目不成功、慢下来、或改方向？
S4 — 项目执行团队中，谁的能力是关键瓶颈？
```

## 三、约束分类（F1前必须完成）

所有约束必须分类，不同类型的约束处理方式完全不同。

```
硬约束（不可违反的边界）
  → 法规/结构/绝对预算上限/物理条件
  → 处理方式：直接框定工作边界，不讨论突破
  → 风险：误判软约束为硬约束，会丢失设计空间

软约束（可谈判的参数）
  → 时间线/风格偏好/局部造价/某些功能要求
  → 处理方式：识别谈判空间，动态调整
  → 风险：误判硬约束为软约束，会引发执行危机

隐性约束（必须主动发现）
  → 客户关系/内部政治/已做的非正式承诺/历史遗留
  → 处理方式：专项挖掘，写入项目前提声明
  → 风险：不发现 = 执行中的意外炸弹，往往比设计问题更致命
```

**扫描问题：**
```
C1 — 有没有绝对不能动的东西？（结构/法规/已有承诺）
C2 — 有没有"据说不能动但其实还有空间"的东西？
C3 — 有没有没说出来但实际上会影响决策的因素？
```

## 三·五、终极追问引擎（F1后、全频谱扫描前强制运行）

> 详见独立文档：`终极追问引擎-Copilot-2026-03-22.md`

**调用时机：** 破题四问（BQ1-BQ4）完成后，全频谱扫描（P1-P9）之前
**输出：** 追问结论卡（作为P1-P9扫描的核心输入）

**五层追问结构：**
```
第一追问 — 谁给你钱？（具体化到真实的人与场景）
第二追问 — 凭什么他选你？（真实竞争场域+决定性瞬间）
第三追问 — 凭什么他心甘情愿？（预期→体验→记忆价值闭环）
第四追问 — 凭什么他还会回来？（记忆锚点+传播机制）
第五追问 — 触底，人性基础（安全感/尊严感/归属感/愉悦感/身份认同）
```

**强制规则：** 追问必须逐层推进，不得停在"体验好/价格合理/氛围佳"等中间层。
触到人性基础层，或触到"设计可服务的最末端感知点"，方可终止。
终止后输出追问结论卡，再进入全频谱扫描。

## 三·八、HEVA验证闭环（跨阶段强制运行）

> 详见独立文档：`HEVA验证闭环方法论-Copilot-2026-03-22.md`

**HEVA定义：** H（假设）→ E（证据）→ V（验证）→ A（验收）

**作用：** 把“推理结论”转化为“可验证结论”，防止方法论停留在观点层。

**强制规则：**
- A类不可逆决策：至少达到 E2 证据等级后才能进入冻结确认
- 关键风险项（P1/P4命中）：必须具备V（验证）方案与失败阈值
- F2前：关键假设必须完成至少一次V验证并有A判定
- F4前：终局指标必须完成A的L3结果验收

**标准输出：**
```
H：假设句（如果做X，则Y变化，最终Z改善）
E：证据等级（E0~E4）+ 证据缺口
V：验证方法 + 成功阈值 + 失败阈值 + 责任人 + 时间窗口
A：PASS / PASS-WARN / FAIL + 后续动作（推进/降速/回滚）
```

## 四、全频谱扫描（9探针强制全跑）

**适用阶段：** 终极追问引擎完成后、设计杠杆排序之前
**执行规则：** 9个探针全部运行，不得选做，不得跳过
**输出要求：** 每个探针必须有明确结论，不得用"暂无"敷衍

---

### 探针 P1 — 要回避什么？（隐患/弱点/痛点）

```
扫描目标：识别本项目在条件、人、执行上的薄弱点
核心问题：
  - 这个项目最容易在哪里出问题？
  - 现有条件中有哪些是脆弱的、不稳定的？
  - 业主/客户/用户有哪些"不便明说的弱点"？
输出格式：【风险项】+ 【属于哪个层面】+ 【回避策略】
```

---

### 探针 P2 — 要放大什么？（卖点/资源点/机会）

```
扫描目标：识别本项目真正的差异化资源，哪些是别人没有的
核心问题：
  - 这个项目有什么独特的、不可复制的资源？
  - 有没有被低估的条件（位置/历史/人脉/工艺/故事）？
  - 如果只能押注一个优势，那个优势是什么？
输出格式：【资源点】+ 【为什么是差异化的】+ 【如何放大的具体动作】
```

---

### 探针 P3 — 正向影响有哪些？（验证方向正确性）

```
扫描目标：在投入资源前，验证当前策略方向的正向效果
核心问题：
  - 如果这个方向做对了，会在哪些维度产生正向影响？
  - 正向影响能持续多久？是一次性的还是持续性的？
  - 正向影响是否可以被检验、被看见？
输出格式：【正向效果】+ 【影响的时间维度】+ 【如何验证】
```

---

### 探针 P4 — 负面隐患有哪些？（副作用/担忧）

```
扫描目标：识别当前策略方向可能带来的负面后果，包括非预期副作用
核心问题：
  - 如果这么做，最担心什么会出错？
  - 有没有"做了A，意外破坏了B"的副作用风险？
  - 有没有时间滞后的负面效应（短期好、长期差）？
输出格式：【负面风险】+ 【触发条件】+ 【对冲策略】
注意：P4与P1不同——P1是现有弱点，P4是主动决策带来的副作用
```

---

### 探针 P5 — 有没有平庸？（反平庸门禁）

```
扫描目标：识别"做了但没有亮点"的平庸区域
核心问题：
  - 方案里有没有让人说"还可以"但说不出记忆点的部分？
  - 有没有因为"求稳"而做出的保守决策？
  - 亮点是否集中在对的位置（杠杆位），而非均匀分散？

两种平庸必须区分：
  A型平庸：面面俱到但无峰值 → 花了钱但没有激活任何驱动力
  B型平庸：刻意保守不犯错 → 安全但无商业想象力

输出格式：【平庸区域识别】+ 【原因】+ 【突破方向】
判定规则：如果方案里有超过30%的内容是A或B型平庸，需要重新排列资源优先级
```

---

### 探针 P6 — 有没有被滥用的手法？（烂大街检查）

```
扫描目标：识别已经过度使用、失去差异化价值的设计语言或策略
判断规则：
  - 用户看到会说"又是这个"而不是"哦这里也有"
  - 在同类竞品里出现频率 > 60%
  - 最初是某个"开创者"的标志，现在已成为标配

常见滥用清单（示例，系统定期更新）：
  精品民宿类：原木+白墙+竹帘+手工陶杯+无印良品质感
  网红餐饮类：霓虹灯牌+裸砖墙+工业风铁管吊灯+花砖
  联合办公类：跑马线+撞色+励志口号贴纸+乒乓球桌
  展览空间类：全黑背景+聚光灯+极简白标签
  文旅类：夯土墙+枯枝+"自然"美学标配

输出格式：【滥用手法识别】+ 【为什么此处仍用/不用的理由】
强制规则：如果使用了清单内的手法，必须能回答"为什么这里用不等于滥用"，否则强制替换
```

---

### 探针 P7 — 有没有优秀的可参考？（标杆对齐）

```
扫描目标：找到同类或跨类的优秀案例，提炼机制而非表面形式
核心问题：
  - 在相同盈利模式或相同挑战下，谁做得最好？他们的关键机制是什么？
  - 标杆的成功是特殊条件造就的，还是可迁移的？
  - 这个项目能从标杆那里借什么（机制），不能借什么（表达/形式）？

提炼规则：
  ✅ 借机制：标杆用了什么逻辑/结构/触发方式
  ❌ 不借表达：标杆长什么样、用什么材质、什么风格

输出格式：【标杆案例】+ 【核心机制提炼】+ 【迁移到本项目的方式】
```

---

### 探针 P8 — 有没有失败的需要避免？（反向学习）

```
扫描目标：找到同类或跨类的失败案例，提炼死亡原因
核心问题：
  - 做了相似事情但失败的项目，死在哪里？
  - 失败的根本原因是行业性的（大家都会踩）还是个案性的（特殊错误）？
  - 本项目有没有和失败案例相似的结构性风险？

分析规则：
  行业性死亡原因 → 必须前置规避，写入失败前置清单
  个案性错误 → 评估是否与本项目有交集

输出格式：【失败案例】+ 【死亡原因】+ 【本项目的对应风险评估】
```

---

### 探针 P9 — 有没有跨界启发？（机制迁移，非风格借鉴）

```
扫描目标：从其他行业/学科找到可迁移的底层机制
核心原则：借的是机制，不是外观

高价值跨界方向（示例）：
  主题公园 → 峰终理论：最后一刻体验决定整体记忆，设计"收尾峰值"
  零售陈列学 → 视觉动线：注意力被引导的顺序，控制用户感知路径
  游戏关卡设计 → 信息节奏：惊喜节点/进度感/奖励机制，管理探索体验
  城市规划 → 三级尺度：广场（公共）/街道（半公开）/小巷（私密）
  剧场设计 → 前后台分离：视线控制、幕后运作对体验的影响
  行为经济学 → 默认选项效应：空间设计如何让"正确行为"成为最自然的选择
  心理学 → 阈值理论：什么程度的变化会被感知，什么程度是浪费
  军事策略 → 制高点/视野控制：谁先看到谁，决定主动权

输出格式：【跨界领域】+ 【可迁移的机制】+ 【在本项目的具体用法】
```

## 五、决策分类框架（影响任务排序与团队组建）

所有设计与项目决策分为四类，不同类型的处理方式完全不同：

```
A类 — 不可逆决策
  定义：一旦执行，代价极高无法回头
  典型：选址/结构方案/品牌定位/核心空间布局
  处理：必须减速 → 集体确认 → 写入冻结节点 → 冻结后禁止反悔
  团队：需要决策者、影响者在场

B类 — 可逆决策
  定义：执行后仍可调整，代价较低
  典型：材质/色彩/局部布局/软装搭配
  处理：先做后调，不需要等待全员对齐
  团队：专业角色独立决定，事后汇报

C类 — 非设计决策（属于业主权限）
  定义：定价/运营方式/市场策略/团队组建
  处理：识别后归还给业主确认，不擅自在设计方案中替业主做决定
  风险：设计方案隐含了业主的C类决策，会被推翻

D类 — 技术决策（专业角色独立判断）
  定义：施工工艺/结构节点/设备选型/材料性能
  处理：直接给专业角色，不需要集体讨论
  风险：非专业人员介入D类决策，会导致错误或浪费
```

**对团队组建的影响：**
- A类决策节点 → 团队必须包含有权拍板的角色
- B类决策 → 可以小团队快速迭代
- C类识别 → 必须有"业主对话"接口角色
- D类执行 → 对应专业角色独责

## 六、资源集中原则（通用版）

任何项目的资源（钱/时间/精力）都是有限的。
方法论必须回答：**把资源堆在哪里，效益最大？**

### 通用集中规则

```
规则1 — 杠杆位优先，非杠杆位保底
  识别出"设计真杠杆"（影响终局目标的关键位置）
  → 把主要资源集中在此
  → 非杠杆位用性价比方案达到基线即可

规则2 — 峰值 > 均值
  用户记住的是峰值体验，而非平均体验
  → 宁可有1-2个极致峰值 + 其余合格
  → 不要追求"全部都不错"（A型平庸的根源）

规则3 — 失败风险点优先于锦上花
  有明确失败风险的地方，先投入资源对冲风险
  → 在风险未对冲前，不做锦上花的投入

规则4 — 不可逆决策优先于可逆决策
  A类决策的资源（time/attention）永远优先
  → B类决策的资源可以压缩，A类不能压缩
```

## 七、冻结节点体系（工作地图的骨架）

工作地图不是任务清单，是**"什么时候必须锁死什么"**的节点序列。

```
冻结节点 F1 ── 进入设计阶段的门禁
  必须锁定：
    ✅ BQ1-BQ4 四个基础问题
    ✅ 利益相关方图谱（四类角色）
    ✅ 约束分类（硬/软/隐性）
    ✅ 终局目标与成功条件定义
  解锁：工作地图生成 / 团队组建 / 任务编排启动

冻结节点 F2 ── 进入深化设计的门禁
  必须锁定：
    ✅ 全频谱扫描（P1-P9）结论
    ✅ 设计杠杆优先级排序
    ✅ 资源分配方案（杠杆位 vs 保底位）
    ✅ A类决策（不可逆决策）全部确认
  解锁：各专题深化任务正式启动

冻结节点 F3 ── 进入施工图/执行的门禁
  必须锁定：
    ✅ 所有A类决策冻结（结构/选址/品牌定位）
    ✅ 预算分配最终确认
    ✅ C类决策（业主权限项）全部归还并确认
  解锁：D类技术决策独立执行 / 施工推进

冻结节点 F4 ── 项目验收门禁
  必须锁定：
    ✅ 终局目标的可检验条件逐项确认
    ✅ 成功条件验收清单对照
    ✅ 设计无法解决的问题，是否在非设计层面已处理
  解锁：项目闭环
```

## 八、动态调整触发机制（每个阶段末尾运行）

项目执行不是线性的。系统必须能识别"需要调整"的信号。

### 红色触发（必须停止，回到F1重新对齐）

```
🔴 利益相关方的隐性约束在执行中暴露
🔴 终局目标定义被新信息根本性推翻
🔴 关键决策者立场发生反转
🔴 硬约束突然收紧（预算/法规/结构）
🔴 BQ4中"设计无法解决的问题"出现且未被处理
```

### 黄色触发（降速+补充信息，不停止）

```
🟡 P1/P4/P6探针在执行中发现新信号
🟡 设计决策无法翻译成终局逻辑（找不到商业/生活/公共价值连接）
🟡 任务输出与终局目标出现可见偏差
🟡 资源集中区域出现A型或B型平庸信号
🟡 隐性约束出现新线索
```

## 九、设计决策翻译规则（所有项目通用）

每一个设计决策，系统必须能用以下格式翻译：

```
【决策】___（具体设计动作）
【服务目标】___（服务于终局目标的哪个层面）
【可检验效果】___（什么指标/现象可以验证这个决策有效）
【失效条件】___（什么情况下这个决策不起作用或起反效果）
【决策类型】___（A/B/C/D）
```

**系统禁止输出的格式（检查并强制修正）：**
- 只有审美判断，没有目标连接："氛围温暖舒适"
- 感知描述未绑定用户行为："品质感提升"
- 无法检验的效果声明："整体调性协调"
- 替业主做了C类决策而未标注

## 十一、设计无法解决的问题（通用声明规则）

**当以下情况出现时，系统必须主动说出，不绕过，不用设计掩盖：**

| 问题类型 | 设计能做的 | 系统必须说的 |
|---------|----------|------------|
| 选址/区位根本条件不成立 | 无 | "这个项目的前提条件还未成立，推进设计方案风险极高。" |
| 定价/商业模式尚未确定 | 无 | "在商业策略锁定前，空间设计方向无法确认。" |
| 运营团队/能力不存在 | 无 | "方案效果依赖运营配合，运营条件需先确认。" |
| 利益相关方冲突未解决 | 无 | "项目有人员层面的决策阻力，需先完成对齐。" |
| 供应链/施工可行性存疑 | 局部 | "以下设计决策存在执行风险：___，建议前置确认。" |
| C类决策（业主权限）未决 | 无 | "这部分需要业主决定，我们不替业主做这个判断。" |

## 附录A：三条核心驱动力（通用版）

适用于所有有"终局受益者"的项目：

```
驱动力1 — 价值质量驱动力（提供方视角）
  做这件事 → 做得有尊严 → 做得持续 → 做得游刃有余 → 不焦虑
  （商业项目：赚钱的质量；私宅项目：生活的质量；公共项目：服务的质量）

驱动力2 — 关系递进驱动力（使用者视角）
  初见（被吸引）→ 相处（体验兑现）→ 久处（习惯形成）→ 久别（记忆留存）→ 重逢（主动回归）

驱动力3 — 体验价值驱动力（价值感视角）
  让"这件事的发生过程"变得：有意义、美好、被认同、令人感动、印象深刻
  顶级闭环：使用者非常开心地实现了提供方的目标——双赢且不可替代
```

**使用规则：**
- 每个项目都必须将三条驱动力映射到具体内容
- 每条驱动力都必须有对应的可检验信号
- 每条驱动力都必须有对应的失败信号
